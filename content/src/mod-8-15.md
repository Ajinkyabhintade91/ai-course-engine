# Agent Project 1: AI Research Agent

This is the first of five project modules that bring Unit 8 together. Each builds one realistic agent, reusing the patterns of the earlier modules, and each lab implements the parts of that agent that decide whether it can be trusted. The first project is a **research agent**: given a question, it plans searches, reads sources, and writes a report with citations. Research agents are a natural first project because their value is obvious, their failure modes are well understood, and their outputs can be checked.

The difficult part is not making a model write a report. Any model will write a fluent report. The difficult part is making the report **true, sourced, and honest about uncertainty**: every claim traceable to a source, duplicates recognised, outdated sources set aside, disagreements reported rather than smoothed over, and quality measured rather than assumed.

## 1. First-Principles Mental Model & Intuition

### A good research assistant

Ask a good junior analyst to compare two products, and they work in a recognisable way. They **plan**: which questions matter, runtime, weight, warranty, price. They **search** and keep a **source list**, noticing when two links are the same article. They **read** and note each fact with where it came from. They **cross-check**: when the manufacturer says 50 minutes and an independent tester measured 38, they report both. They ignore a 2021 blog post about a warranty that has since changed. And they **write** a report where every sentence can be traced, with uncertainty stated plainly.

A weak analyst skips the source list, copies the first number found, and writes "the ZipCut runs 50 minutes" with total confidence. The research agent's job is to behave like the good analyst, and the system around it should check that it did.

```text
   question
      |
   [plan]  aspects: runtime, weight, warranty, price -> search queries
      |
   [search loop]  budget: max searches, max sources; stop when searches add nothing new
      |     \--> [source registry]  S1, S2, S3: normalised URL, title, year, domain (duplicates merged)
      v
   [read + extract claims]  (topic, value, source id)
      |
   [corroborate]  per topic: confirmed (2+ domains agree) | single source | conflict | no current source
      |
   [write report]  every sentence cites [S#]; conflicts stated; stale sources excluded
      |
   [check + score]  citations valid and current; aspects covered; conflicts acknowledged -> score
```

### Why structure beats a single prompt

Modern models with search tools can run this whole loop themselves, and products that do so are useful. But building your own gives you three things a single prompt does not: **control** over sources, budgets, and stopping; **records** of every source and claim for checking; and **measurement**, so a change to the prompt or model can be evaluated, Module 8.12. The lab implements the deterministic parts; the model's parts, deciding queries, extracting claims, and drafting sentences, are represented by fixed inputs so that the checks can be tested exactly.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Planning: aspects and queries

A research question is decomposed into **aspects**, the dimensions a good answer must cover, and each aspect into search queries. Stanford's STORM system, by Shao and colleagues, generates long, Wikipedia-style articles by first researching the topic from several **perspectives**, simulating conversations in which writers with different viewpoints ask questions answered from retrieved sources, and building an outline before any writing. The lesson for a research agent is that question generation deserves its own step: the queries a model asks determine the sources it finds, and a plan that lists aspects in advance makes coverage measurable later.

### The search loop and its budget

Each search returns results; each result is either a new source or one already seen. The loop needs two limits and one stopping signal:

| Control | Purpose |
|---|---|
| Maximum searches | Bounds cost and time |
| Maximum sources | Bounds the reading the model must do and the context it fills |
| Saturation | When a search adds no new sources, further searches on the plan are likely wasted |

Anthropic's description of its research system includes explicit effort guidance: simple fact-finding with a few tool calls, comparisons with more, complex research with many subagents. A single-agent research loop applies the same idea through its budget. Logging each query with the number of new sources it added makes saturation visible: a sequence of 2, 2, 0, 1 shows the third query was redundant.

### Source tracking

Sources need stable identifiers, S1, S2, and so on, so that claims and sentences can refer to them. The same article often appears under several URLs: with and without `www`, with tracking parameters such as `utm_source`, with or without a trailing slash, over HTTP or HTTPS. A **normalised key**, lower-case host without `www`, path without trailing slash, query without tracking parameters, sorted, merges these, so one article is counted once. Each source also records its **domain**, needed to tell independent confirmation from one site saying the same thing twice, and its **year**, needed to set aside outdated information.

### Claims and corroboration

The agent extracts **claims** from sources as structured records: a topic, a value, and the source identifier, such as ("ZipCut runtime in minutes", "50", "S1"). Structuring claims makes them checkable. For each topic, considering only sources newer than a maximum age:

| Status | Condition | How the report should state it |
|---|---|---|
| Confirmed | One value, supported by two or more distinct domains | Plainly, with citations |
| Single source | One value from one domain | With attribution: "according to the manufacturer" |
| Conflict | Two or more different values | Report each with its source: "sources disagree" |
| No current source | Only outdated sources | Say the information could not be confirmed |

Counting **domains**, not pages, matters: a review site's two pages agreeing is one voice. A manufacturer's specification and an independent review agreeing on a weight is real corroboration. A manufacturer's runtime of 50 minutes and a forum tester's 38 is a conflict, and often the most useful finding in the report: rated figures and real-world measurements differ.

### Citation discipline

Every factual sentence in the report should carry citation markers pointing to registered sources. Checks:

1. **Uncited sentences**: a factual sentence with no marker. Recommendations and transitions may be exempt by policy, but must be identified.
2. **Unknown identifiers**: a marker such as [S9] for a source that was never registered, a common hallucination.
3. **Stale sources**: a citation to a source older than the maximum age, such as a 2021 blog post cited for a warranty term.

Module 7.18 checked that cited passages were actually retrieved and that numbers appeared in them; the same support check applies here. Model providers increasingly offer citation features natively: the Claude API's citations feature returns references to the specific passages of supplied documents that support each part of a response, which makes the support check easier and more precise.

### Evaluating report quality

A report can be scored against a rubric. A simple, transparent version combines three measures:

$$\text{score} = w_1 \cdot \text{coverage} + w_2 \cdot \text{cited share} + w_3 \cdot \text{conflicts acknowledged}$$

where coverage is the share of planned aspects the report addresses, the cited share is the fraction of sentences with citations, and the conflict term is 1 if every conflict found was acknowledged, or if there were none. With weights 0.4, 0.4, and 0.2, a report covering half the aspects, citing four of five sentences, and acknowledging its conflict scores $0.4 \times 0.5 + 0.4 \times 0.8 + 0.2 \times 1 = 0.72$. Keyword-based coverage is crude, it misses an aspect discussed in other words, so in practice a model grader checks coverage against the rubric, calibrated as in Module 8.12, while the citation checks stay in code.

### Complexity

URL normalisation is linear in the URL. Registration checks existing sources, linear in the registry, or constant with a dictionary keyed by the normalised URL. The research loop costs at most the search budget in tool calls. Corroboration is linear in claims. Citation checks are linear in sentences. Scoring is linear in the report and aspects.

## 3. Production-Grade Implementation & Annotated Walkthrough

The lab's offline corpus stands in for the web: six pages, two of which are the same review under different URLs.

```python
import re
from urllib.parse import parse_qsl, urlencode, urlsplit

CORPUS = {
    "https://www.toolreview.example/saws/zipcut?utm_source=news": ("ZipCut review", 2026, "ZipCut runs 50 minutes per charge and weighs 2.8 kg."),
    "http://toolreview.example/saws/zipcut/": ("ZipCut review", 2026, "ZipCut runs 50 minutes per charge and weighs 2.8 kg."),
    "https://makerforum.example/t/123": ("ZipCut battery test", 2025, "In my tests the ZipCut ran 38 minutes per charge."),
    "https://zipcut.example/specs": ("ZipCut specifications", 2026, "ZipCut runtime is 50 minutes; weight 2.8 kg; warranty 3 years."),
    "https://oldblog.example/2021/saws": ("Saw roundup 2021", 2021, "The ZipCut warranty is 1 year."),
    "https://toolreview.example/saws/saw-3": ("SAW-3 review", 2026, "SAW-3 runs 45 minutes per charge and weighs 3.1 kg."),
}

def normalise_url(url):
    parts = urlsplit(url)
    host = (parts.hostname or "").lower()
    if host.startswith("www."):
        host = host[4:]
    path = parts.path.rstrip("/") or "/"
    query = urlencode(sorted((k, v) for k, v in parse_qsl(parts.query) if not k.startswith("utm_")))
    return f"{host}{path}" + (f"?{query}" if query else "")

def register(registry, url, title, year):
    key = normalise_url(url)
    for sid, source in registry.items():
        if source["key"] == key:
            return sid, False
    sid = f"S{len(registry) + 1}"
    registry[sid] = {"key": key, "url": url, "title": title, "year": year, "domain": key.split("/")[0]}
    return sid, True

registry = {}
for url, (title, year, _) in CORPUS.items():
    print(register(registry, url, title, year))
```

- **Normalisation drops the scheme, `www`, trailing slashes, and tracking parameters.** Real query parameters are kept, sorted.
- **The two ZipCut review URLs share the key `toolreview.example/saws/zipcut`.** The second registration returns S1 and False: one source, not two.
- **Identifiers are assigned in order of first registration.** They are stable for the life of the report.
- **Each source records its domain and year.** Corroboration needs both.

Next, a budgeted research loop.

```python
WORD = re.compile(r"[a-z0-9]+")

def search(query, corpus, k=3):
    q = set(WORD.findall(query.lower()))
    scored = sorted(((len(q & set(WORD.findall((title + " " + body).lower()))), url)
                     for url, (title, year, body) in corpus.items()), key=lambda pair: (-pair[0], pair[1]))
    return [url for score, url in scored if score > 0][:k]

def research(queries, corpus, max_searches=3, max_sources=4):
    registry, log = {}, []
    for query in queries[:max_searches]:
        new = 0
        for url in search(query, corpus):
            if len(registry) >= max_sources:
                break
            title, year, _ = corpus[url]
            sid, added = register(registry, url, title, year)
            new += added
        log.append((query, new))
        if len(registry) >= max_sources:
            break
    return registry, log

QUERIES = ["zipcut runtime minutes per charge", "zipcut warranty", "zipcut weight kg", "saw-3 runtime"]
print(research(QUERIES, CORPUS)[1])
print(research(QUERIES, CORPUS, max_searches=4, max_sources=10)[1])
```

- **The search is a keyword stand-in for a web search tool.** It returns up to three URLs, best first.
- **With a budget of four sources, the loop stops after two searches.** Each added two sources.
- **With a larger budget, the log reads 2, 2, 0, 1.** The weight query found nothing new: both pages mentioning weight were already registered, a saturation signal.
- **The log is the evidence for tuning the plan.** Queries that add nothing can be dropped or rewritten.

Then, corroboration across domains and dates.

```python
CLAIMS = [("zipcut_runtime_min", "50", "S1"), ("zipcut_runtime_min", "38", "S2"), ("zipcut_runtime_min", "50", "S4"),
          ("zipcut_warranty_years", "1", "S3"), ("zipcut_warranty_years", "3", "S4"),
          ("zipcut_weight_kg", "2.8", "S1"), ("zipcut_weight_kg", "2.8", "S4"), ("saw3_runtime_min", "45", "S5")]

def corroborate(claims, registry, now_year=2026, max_age=2):
    result = {}
    for topic in dict.fromkeys(t for t, _, _ in claims):
        values = {}
        for t, value, sid in claims:
            if t == topic and now_year - registry[sid]["year"] <= max_age:
                values.setdefault(value, set()).add(registry[sid]["domain"])
        if not values:
            status = "no current source"
        elif len(values) > 1:
            status = "conflict"
        elif len(next(iter(values.values()))) >= 2:
            status = "confirmed"
        else:
            status = "single source"
        result[topic] = (status, {value: sorted(domains) for value, domains in values.items()})
    return result

full_registry = research(QUERIES, CORPUS, max_searches=4, max_sources=10)[0]
for topic, verdict in corroborate(CLAIMS, full_registry).items():
    print(topic, verdict)
```

- **Topics keep their first-seen order; values map to the set of supporting domains.**
- **Runtime is a conflict: 50 from the review site and the manufacturer, 38 from the forum test.** The report must say so.
- **The warranty's 1-year claim comes from the 2021 blog, five years old, and is set aside.** Only the manufacturer's 3 years remains: a single source.
- **Weight is confirmed by two independent domains.**
- **SAW-3's runtime has one source.** Attribute it.

Then, citation checks.

```python
CITE = re.compile(r"\[(S\d+)\]")

def check_citations(sentences, registry, now_year=2026, max_age=2):
    problems = []
    for index, sentence in enumerate(sentences):
        ids = CITE.findall(sentence)
        if not ids:
            problems.append((index, "uncited"))
            continue
        for sid in ids:
            if sid not in registry:
                problems.append((index, f"unknown {sid}"))
            elif now_year - registry[sid]["year"] > max_age:
                problems.append((index, f"stale {sid}"))
    return problems

REPORT = ["ZipCut is rated at 50 minutes per charge [S1][S4].",
          "A forum tester measured 38 minutes [S2], so sources disagree on real-world runtime.",
          "ZipCut has a 1 year warranty [S3].",
          "SAW-3 runs 45 minutes per charge [S5].",
          "We recommend stocking both."]
print(check_citations(REPORT, full_registry))
```

- **Each sentence's markers are extracted and checked against the registry.**
- **Index 2, the third sentence, cites S3, the 2021 blog: stale.** The draft repeated the outdated warranty that corroboration had already set aside.
- **Index 4, the fifth sentence and the recommendation, has no citation.** Policy decides whether recommendations need one; the check makes the decision visible.
- **An invented [S9] would be reported as unknown.**

Finally, scoring the report.

```python
def score_report(sentences, aspects, conflicts, weights=(0.4, 0.4, 0.2)):
    text = " ".join(sentences).lower()
    covered = [a for a in aspects if a in text]
    coverage = len(covered) / len(aspects) if aspects else 1.0
    cited = sum(1 for s in sentences if CITE.search(s)) / len(sentences) if sentences else 0.0
    acknowledged = 1.0 if not conflicts or "disagree" in text else 0.0
    score = round(weights[0] * coverage + weights[1] * cited + weights[2] * acknowledged, 3)
    return score, {"coverage": round(coverage, 3), "cited": round(cited, 3),
                   "conflicts_acknowledged": acknowledged, "missing": [a for a in aspects if a not in covered]}

print(score_report(REPORT, ["runtime", "warranty", "weight", "price"], ["zipcut_runtime_min"]))
```

- **Coverage is 2 of 4: runtime and warranty are mentioned, weight and price are not.** The missing list tells the agent what to add.
- **Four of five sentences are cited, 0.8.**
- **The runtime conflict is acknowledged with "disagree".**
- **The score is 0.72.** A gate might require 0.8 and send the report back with the missing aspects.

**Complexity.** `normalise_url` is linear in the URL. `register` scans the registry. `research` is bounded by the search budget. `corroborate` is linear in claims per topic. `check_citations` is linear in sentences. `score_report` is linear in text and aspects.

### A research agent specification

```text
INPUT        question + aspects (runtime, weight, warranty, price) + max age 2 years
PLAN         2 queries per aspect, model-generated, reviewed for coverage
BUDGET       max 12 searches, max 15 sources; stop an aspect after a search adds 0 new sources
SOURCES      registry with normalised URL, domain, year; manufacturer pages tagged as primary
CLAIMS       extracted as (topic, value, source); corroborated by distinct current domains
REPORT       every factual sentence cited; conflicts stated as "sources disagree"; single-source facts attributed
CHECKS       uncited, unknown, stale citations block the report; numbers must appear in the cited source
SCORE        rubric >= 0.8 to deliver; else one revision round with the missing aspects (Module 8.10)
```

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Counting the same article twice.** Tracking parameters and `www` variants inflate the source count. Normalise URLs.

**Pages are not independent sources.** Two pages from one site are one voice. Corroborate by domain.

**Old pages win searches.** Search ranking does not care about age. Record years and exclude stale sources.

**Smoothing over conflicts.** Averaging 50 and 38 minutes, or picking one, hides the most useful finding. Report both.

**Manufacturer figures as facts.** Rated runtime is a claim by an interested party. Label it as rated.

**Citations to sources never read.** Models invent identifiers. Check every marker against the registry.

**Citations that do not support the sentence.** A real source cited for a number it does not contain is still wrong. Check support.

**No budget.** Research agents happily search for an hour. Cap searches and sources, and watch saturation.

**Reading too much.** Fifty full pages fill the context and bury the facts. Extract claims per source, then synthesise.

**Untrusted pages.** Every web page is untrusted input. Apply Module 8.14: no sensitive tools in the research session.

**Unmeasured quality.** "The reports look good" is not an evaluation. Score coverage, citations, and conflicts.

**One giant prompt.** Plan, search, extract, and write in separate steps, so each can be checked.

## 5. Active Recall Check & Synthesis Summary

**Summary.** A research agent plans aspects and queries, searches within a budget of searches and sources while watching for saturation, registers sources under normalised URLs with stable identifiers, domains, and years, extracts claims as topic, value, and source, and corroborates each topic across distinct, current domains as confirmed, single source, conflict, or no current source. Its report cites every factual sentence, states conflicts, attributes single-source facts, and avoids stale sources, and checks catch uncited sentences, unknown identifiers, and outdated citations. Quality is scored with a rubric combining aspect coverage, citation share, and acknowledged conflicts, with model graders for nuanced coverage calibrated against people. STORM's perspective-guided questioning, Anthropic's effort scaling, and native citation features all support the same discipline: the report must be traceable, current, and honest about disagreement.

# ---------------------------------------------------------------- Step 1
def normalise_url(url):
    """One article, one key, however it was linked."""
    parts = urlsplit(url)
    host = (parts.hostname or "").lower()
    if host.startswith("www."):
        host = host[4:]
    path = parts.path.rstrip("/") or "/"
    query = urlencode(sorted((k, v) for k, v in parse_qsl(parts.query) if not k.startswith("utm_")))
    return f"{host}{path}" + (f"?{query}" if query else "")


def register(registry, url, title, year):
    """Stable identifiers for citation; duplicates merged."""
    key = normalise_url(url)
    for sid, source in registry.items():
        if source["key"] == key:
            return sid, False
    sid = f"S{len(registry) + 1}"
    registry[sid] = {"key": key, "url": url, "title": title, "year": year, "domain": key.split("/")[0]}
    return sid, True


# ---------------------------------------------------------------- Step 2
def research(queries, corpus, max_searches=3, max_sources=4):
    """A budgeted loop whose log shows saturation."""
    registry, log = {}, []
    for query in queries[:max_searches]:
        new = 0
        for url in search(query, corpus):
            if len(registry) >= max_sources:
                break
            title, year, _ = corpus[url]
            sid, added = register(registry, url, title, year)
            new += added
        log.append((query, new))
        if len(registry) >= max_sources:
            break
    return registry, log


# ---------------------------------------------------------------- Step 3
def corroborate(claims, registry, now_year=2026, max_age=2):
    """Count independent, current voices per value; surface conflicts."""
    result = {}
    for topic in dict.fromkeys(t for t, _, _ in claims):
        values = {}
        for t, value, sid in claims:
            if t == topic and now_year - registry[sid]["year"] <= max_age:
                values.setdefault(value, set()).add(registry[sid]["domain"])
        if not values:
            status = "no current source"
        elif len(values) > 1:
            status = "conflict"
        elif len(next(iter(values.values()))) >= 2:
            status = "confirmed"
        else:
            status = "single source"
        result[topic] = (status, {value: sorted(domains) for value, domains in values.items()})
    return result


# ---------------------------------------------------------------- Step 4
def check_citations(sentences, registry, now_year=2026, max_age=2):
    """Every factual sentence cited, every citation real and current."""
    problems = []
    for index, sentence in enumerate(sentences):
        ids = CITE.findall(sentence)
        if not ids:
            problems.append((index, "uncited"))
            continue
        for sid in ids:
            if sid not in registry:
                problems.append((index, f"unknown {sid}"))
            elif now_year - registry[sid]["year"] > max_age:
                problems.append((index, f"stale {sid}"))
    return problems


# ---------------------------------------------------------------- Step 5
def score_report(sentences, aspects, conflicts, weights=(0.4, 0.4, 0.2)):
    """A transparent rubric: coverage, citations, honesty about conflicts."""
    text = " ".join(sentences).lower()
    covered = [a for a in aspects if a in text]
    coverage = len(covered) / len(aspects) if aspects else 1.0
    cited = sum(1 for s in sentences if CITE.search(s)) / len(sentences) if sentences else 0.0
    acknowledged = 1.0 if not conflicts or "disagree" in text else 0.0
    score = round(weights[0] * coverage + weights[1] * cited + weights[2] * acknowledged, 3)
    return score, {"coverage": round(coverage, 3), "cited": round(cited, 3),
                   "conflicts_acknowledged": acknowledged, "missing": [a for a in aspects if a not in covered]}
