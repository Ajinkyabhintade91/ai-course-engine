# Qwen

**Qwen** is the family of models from Alibaba's Qwen team, and for local use it has become one of the most popular choices: a wide range of sizes from under one billion to hundreds of billions of parameters, strong coding and tool use, broad language coverage, and, for its open-weight releases, the permissive Apache 2.0 licence. This module surveys the family as it stands, explains how to choose among its general, coder, and vision models, how its thinking modes work and how to control them, and which sampling settings its makers recommend.

The family moves quickly: several generations were released in 2026 alone. Facts here are from Qwen's repository and model cards and from Ollama's library at the time of writing (November 2026), and benchmark claims are the vendor's own. Check the model card of the exact version you use.

## 1. First-Principles Mental Model & Intuition

### A well-stocked tool catalogue

Think of the Qwen family as a manufacturer's catalogue of power tools. The same company makes a **general-purpose drill** in many sizes, from a light cordless one to a heavy industrial one: the general models. It makes **specialist tools**: a router for fine joinery, the coder models, and a laser measure that reads what it sees, the vision models. Each product line has **generations**, and newer generations often make the specialist features standard: today's general drill may include the laser guide. Each tool has a **mode switch**, fast or careful: thinking off or on. And the **manual** recommends settings, speed and pressure, for each mode, and ignoring them is the commonest reason a good tool performs badly: sampling parameters.

```text
                          QWEN FAMILY (open-weight releases; Apache 2.0 per Qwen)
  Qwen3 (2025)        dense 0.6B to 32B, MoE 30B-A3B and 235B-A22B; hybrid thinking; 2507 refresh
    |-- Qwen3-Coder   30B-A3B, 480B-A35B (agentic coding, tools)
    |-- Qwen3-VL      2B to 235B (vision-language)
  Qwen3.5 (Feb-Mar 2026)  0.8B to 397B-A17B; natively multimodal; 201 languages and dialects (per Qwen)
  Qwen3.6 (Apr 2026)      27B dense, 35B-A3B MoE; "-coding" tags on Ollama
  Qwen3.8 (Aug 2026)      27B dense; 2.4T-A95B MoE (not a local model)

  choose:  capability needed (tools, vision, thinking) -> context needed -> fits memory -> speed -> newest
```

### The point of the family view

Picking "Qwen" is not a decision; picking `qwen3.5:9b` for a 16 GB GPU, or `qwen3.6:35b-a3b` for a large-memory Mac, is. The decision follows the arithmetic of Module 10.10 and the capabilities each model actually has.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Generations

**Qwen3**, released in 2025, offered dense models from 0.6B to 32B parameters and two mixture-of-experts models, 30B-A3B and 235B-A22B, all **hybrid**: one model could think step by step or answer directly. Its model card describes support for over 100 languages and dialects and a native context of 32,768 tokens, extendable with YaRN. A **2507** refresh split the line into separate Instruct and Thinking checkpoints with longer native context.

**Qwen3.5**, released from February 2026, spans 0.8B to a 397B-A17B mixture of experts and is natively multimodal: the same weights accept images. Qwen's repository describes it as expanding language support to 201 languages and dialects. **Qwen3.6**, from April 2026, has a 27B dense model and a 35B-A3B mixture of experts. **Qwen3.8**, from August 2026, has a 27B dense model, whose card describes a hybrid architecture mixing linear-attention and standard attention layers with multi-token prediction, and a very large 2.4-trillion-parameter mixture of experts that is not practical to run locally. Ollama's tags for the newest models include `mtp` variants that use multi-token prediction to speed up generation.

### Specialist lines

**Qwen3-Coder** targets agentic coding: Ollama lists 30B-A3B and 480B-A35B versions with 256K context and tool support. **Qwen3-VL** adds vision to Qwen3 in sizes from 2B to 235B. In the newest generations the distinction blurs: Qwen3.5, 3.6, and 3.8 accept images natively, and Ollama offers `-coding` tags for Qwen3.6.

### What Ollama offers

At the time of writing, Ollama's library lists, among others:

### Thinking modes and how to control them

A thinking model writes a reasoning trace before its answer. It helps on maths, planning, and tricky code, and costs time and tokens. Control has changed between generations:

- **Qwen3** supported soft switches, `/think` and `/no_think` in a message, when thinking was enabled.
- **Qwen3-2507** used separate Instruct and Thinking checkpoints.
- **Qwen3.6's** card says the soft switches are not officially supported; thinking is controlled through the chat template's settings, and newer cards describe further options such as reasoning effort.

Through Ollama, the portable way is the API's `think` field: `true` asks for thinking output, `false` asks for none, and leaving it unset uses the model default. Ollama's documentation adds that `/api/show` reports which thinking values a model supports. The trace arrives in a separate `thinking` field, so applications can hide it.

### Sampling: follow the card

Qwen's cards recommend sampling settings per mode. For Qwen3: thinking, temperature 0.6, top-p 0.95, top-k 20, min-p 0; non-thinking, temperature 0.7, top-p 0.8, top-k 20. The Qwen3 card warns specifically against **greedy decoding**, temperature 0, in thinking mode, because it can cause endless repetition, and notes that a high presence penalty can cause occasional language mixing. Qwen3.6's card recommends temperature 1.0 with a presence penalty of 1.5 for general thinking, temperature 0.6 and no presence penalty for precise coding, and temperature 0.7, top-p 0.8, presence penalty 1.5 for non-thinking use. These differ from Ollama's generic defaults, Module 10.2, so set them in a Modelfile or per request.

### Choosing a model

Combining the capability filter with Module 10.10's arithmetic, a model is a candidate if it has every needed capability, its context is long enough, and it fits:

$$\text{fits} \iff \text{size} \times 1.2 \le \text{GPU memory}, \qquad \text{tokens/s} \approx 0.6 \times \frac{\text{bandwidth}}{\text{size} \times a / t}$$

with $a$ active and $t$ total parameters, so mixture-of-experts models read only a fraction of their size per token. Among candidates, a simple policy prefers the **newest generation**, then the **largest**, then the **smallest file**. A real choice then tests the top two on your own tasks, Module 10.15.

### Licence

Qwen's repository states that its open-weight models are released under **Apache 2.0**, and the model cards checked for this module say so. Apache 2.0 permits commercial use, modification, and redistribution, with conditions: include the licence, keep notices, and mark changes; it also contains a patent licence that terminates for anyone who sues over patents in the work. Check the card of each model you ship: at the time of writing, the largest Qwen3.8 model's card lists a different licence identifier.

### Complexity

Filtering a catalogue of $n$ models is $O(n)$; checking sampling settings is linear in the parameters; recommending is $O(n)$.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, the catalogue and a capability filter.

```python
CATALOGUE = [
    {"name": "qwen3:8b", "gen": 3.0, "total_b": 8.2, "active_b": 8.2, "gb": 5.2, "ctx_k": 40, "caps": {"tools", "thinking"}},
    {"name": "qwen3:30b", "gen": 3.0, "total_b": 30.5, "active_b": 3.3, "gb": 19.0, "ctx_k": 256, "caps": {"tools", "thinking"}},
    {"name": "qwen3-coder:30b", "gen": 3.0, "total_b": 30.5, "active_b": 3.3, "gb": 19.0, "ctx_k": 256, "caps": {"tools"}},
    {"name": "qwen3-vl:8b", "gen": 3.0, "total_b": 8.0, "active_b": 8.0, "gb": 6.2, "ctx_k": 256, "caps": {"vision", "tools", "thinking"}},
    {"name": "qwen3.5:4b", "gen": 3.5, "total_b": 4.0, "active_b": 4.0, "gb": 3.3, "ctx_k": 256, "caps": {"vision", "tools", "thinking"}},
    {"name": "qwen3.5:9b", "gen": 3.5, "total_b": 9.0, "active_b": 9.0, "gb": 6.6, "ctx_k": 256, "caps": {"vision", "tools", "thinking"}},
    {"name": "qwen3.6:27b", "gen": 3.6, "total_b": 27.0, "active_b": 27.0, "gb": 18.0, "ctx_k": 256, "caps": {"vision", "tools", "thinking"}},
    {"name": "qwen3.6:35b-a3b", "gen": 3.6, "total_b": 35.0, "active_b": 3.0, "gb": 23.0, "ctx_k": 256, "caps": {"vision", "tools", "thinking"}},
    {"name": "qwen3.8:27b", "gen": 3.8, "total_b": 27.0, "active_b": 27.0, "gb": 18.0, "ctx_k": 256, "caps": {"vision", "tools", "thinking"}},
]

def matches(catalogue, needs, min_ctx_k=0):
    return [m["name"] for m in catalogue if set(needs) <= m["caps"] and m["ctx_k"] >= min_ctx_k]

print(matches(CATALOGUE, {"vision"}))
print(matches(CATALOGUE, {"tools", "thinking"}, 32))
```

- **Sizes, contexts, and capabilities are from Ollama's pages at the time of writing.** Parameter counts for the newest models are rounded from their names.
- **Six models accept images.** The vision line plus every model from Qwen3.5 on.
- **`qwen3-coder` lists tools but not thinking,** so it drops out when thinking is required.

Next, fit and speed.

```python
def run_profile(model, gpu_gb, bw, headroom=1.2, efficiency=0.6):
    fits = model["gb"] * headroom <= gpu_gb
    read = model["gb"] * model["active_b"] / model["total_b"]
    return fits, round(efficiency * bw / read, 1)

BY_NAME = {m["name"]: m for m in CATALOGUE}
print(run_profile(BY_NAME["qwen3.5:9b"], 16, 288))
print(run_profile(BY_NAME["qwen3.6:35b-a3b"], 48, 546), run_profile(BY_NAME["qwen3.8:27b"], 48, 546))
```

- **`qwen3.5:9b` fits a 16 GB card at about 26 tokens per second.**
- **On a 64 GB Mac with about 48 GB for the GPU, the 35B-A3B mixture of experts runs at about 166 tokens per second; the dense 27B at about 18.** The estimate for mixture-of-experts models is optimistic, since attention and shared layers add reads, but the gap is real.

Then, checking sampling settings against the card.

```python
RECOMMENDED = {
    ("qwen3", "thinking"): {"temperature": 0.6, "top_p": 0.95, "top_k": 20, "min_p": 0.0},
    ("qwen3", "non-thinking"): {"temperature": 0.7, "top_p": 0.8, "top_k": 20, "min_p": 0.0},
    ("qwen3.6", "thinking"): {"temperature": 1.0, "top_p": 0.95, "top_k": 20, "presence_penalty": 1.5},
    ("qwen3.6", "coding"): {"temperature": 0.6, "top_p": 0.95, "top_k": 20, "presence_penalty": 0.0},
    ("qwen3.6", "non-thinking"): {"temperature": 0.7, "top_p": 0.8, "top_k": 20, "presence_penalty": 1.5},
}

def check_sampling(family, mode, options):
    rec = RECOMMENDED[(family, mode)]
    issues = []
    if options.get("temperature", 0.8) == 0:
        issues.append("greedy decoding (temperature 0) can cause endless repetition")
    for k in sorted(rec):
        if k in options and options[k] != rec[k]:
            issues.append(f"{k} {options[k]} differs from recommended {rec[k]}")
    if options.get("presence_penalty", 0) > 1.5:
        issues.append("presence_penalty above 1.5 can cause language mixing")
    return issues

print(check_sampling("qwen3", "thinking", {"temperature": 0}))
print(check_sampling("qwen3.6", "coding", {"temperature": 0.6, "presence_penalty": 1.5}))
```

- **Temperature 0 raises two issues:** the repetition warning and the mismatch with 0.6.
- **Copying general settings into coding mode is caught.** Qwen3.6 recommends no presence penalty for precise coding.
- **Only settings that are present are compared.** Omitted ones fall back to Ollama's defaults, which a Modelfile can override.

Then, building a request that controls thinking.

```python
def build_request(model, prompt, think):
    family = model.split(":")[0]
    warnings = []
    if family == "qwen3.6" and ("/think" in prompt or "/no_think" in prompt or "/nothink" in prompt):
        warnings.append("soft switches are not officially supported: use the think field")
    return {"model": model, "messages": [{"role": "user", "content": prompt}], "think": think, "stream": False}, warnings

print(build_request("qwen3.6:27b", "Summarise this /no_think", False))
```

- **`think` is the portable control.** It works the same across thinking models in Ollama.
- **Soft switches left over from Qwen3 prompts are flagged for Qwen3.6.** They may be ignored or treated as text.
- **`stream` is off** so the whole answer, and its separate `thinking` field, arrive together, Module 10.11.

Finally, a recommendation per machine.

```python
def recommend(catalogue, needs, min_ctx_k, gpu_gb, bw):
    best = None
    for m in catalogue:
        if m["name"] not in matches(catalogue, needs, min_ctx_k):
            continue
        fits, tps = run_profile(m, gpu_gb, bw)
        if not fits:
            continue
        key = (m["gen"], m["total_b"], -m["gb"])
        if best is None or key > best[0]:
            best = (key, m["name"], tps)
    return (best[1], best[2]) if best else None

for gpu, bw in [(16, 288), (24, 1008), (48, 546), (4, 100)]:
    print(gpu, recommend(CATALOGUE, {"tools"}, 32, gpu, bw))
```

- **16 GB: `qwen3.5:9b`. 24 GB and 48 GB: `qwen3.8:27b`. 4 GB: `qwen3.5:4b`.**
- **The policy prefers newer and larger,** which on the 48 GB Mac picks a dense model at about 18 tokens per second over a mixture of experts that would be much faster. That is a judgement to test, not accept.

**Complexity.** Linear in the catalogue for every function.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Endless thinking loops.** Usually wrong sampling, a broken chat template, or a poor fine-tune. Use the card's settings and official tags.

**Greedy decoding with thinking on.** The card warns of repetition. Use the recommended temperature.

**Thinking when you do not need it.** Slower and longer. Turn it off with `think: false` for simple tasks.

**Old soft switches in new models.** `/no_think` in prompts may be ignored. Use the `think` field.

**Showing the trace to customers.** It can be long and odd. Hide the `thinking` field in the interface.

**Assuming the maximum context is used.** 256K is the ceiling, not the setting. Set `num_ctx`.

**Presence penalty too high.** Can cause language mixing. Stay at or below the card's value.

**Comparing benchmark tables.** Vendor numbers use vendor harnesses. Test on your own tasks.

**Choosing dense when MoE would do.** On bandwidth-limited machines, MoE models are much faster. Try both.

**Newer is not always better for you.** Some users report the newest models thinking longer. Measure time to answer.

**Licence per card.** Most are Apache 2.0, but check the specific model you ship.

**Long-context extension.** Static YaRN scaling can hurt short prompts, the cards note. Enable it only when needed.

# ---------------------------------------------------------------- Step 1
def matches(catalogue, needs, min_ctx_k=0):
    """Models with every needed capability and enough context."""
    return [m["name"] for m in catalogue if set(needs) <= m["caps"] and m["ctx_k"] >= min_ctx_k]


# ---------------------------------------------------------------- Step 2
def run_profile(model, gpu_gb, bw, headroom=1.2, efficiency=0.6):
    """Fit with headroom; speed from bytes read per token (active share for MoE)."""
    fits = model["gb"] * headroom <= gpu_gb
    read = model["gb"] * model["active_b"] / model["total_b"]
    return fits, round(efficiency * bw / read, 1)


# ---------------------------------------------------------------- Step 3
def check_sampling(family, mode, options):
    """Differences from the model card's recommended sampling, plus known hazards."""
    rec = RECOMMENDED[(family, mode)]
    issues = []
    if options.get("temperature", 0.8) == 0:
        issues.append("greedy decoding (temperature 0) can cause endless repetition")
    for k in sorted(rec):
        if k in options and options[k] != rec[k]:
            issues.append(f"{k} {options[k]} differs from recommended {rec[k]}")
    if options.get("presence_penalty", 0) > 1.5:
        issues.append("presence_penalty above 1.5 can cause language mixing")
    return issues


# ---------------------------------------------------------------- Step 4
def build_request(model, prompt, think):
    """An Ollama chat request with explicit thinking control."""
    family = model.split(":")[0]
    warnings = []
    if family == "qwen3.6" and ("/think" in prompt or "/no_think" in prompt or "/nothink" in prompt):
        warnings.append("soft switches are not officially supported: use the think field")
    return {"model": model, "messages": [{"role": "user", "content": prompt}], "think": think, "stream": False}, warnings


# ---------------------------------------------------------------- Step 5
def recommend(catalogue, needs, min_ctx_k, gpu_gb, bw):
    """Newest, then largest, then smallest file among capable models that fit."""
    best = None
    for m in catalogue:
        if m["name"] not in matches(catalogue, needs, min_ctx_k):
            continue
        fits, tps = run_profile(m, gpu_gb, bw)
        if not fits:
            continue
        key = (m["gen"], m["total_b"], -m["gb"])
        if best is None or key > best[0]:
            best = (key, m["name"], tps)
    return (best[1], best[2]) if best else None
