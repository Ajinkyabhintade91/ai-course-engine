# Project 6: Social Media Content Automation

Posting regularly on several social platforms is relentless work: ideas, drafts, adapting each draft to each platform, scheduling, answering, and checking what worked. It is also work that automation handles unusually well, as long as two things stay under human control: what goes out in the brand's name, and the judgement about what is worth saying.

This project builds the pipeline from an idea backlog to published posts and back again: AI drafts from ideas, platform-specific formatting and limits, an approval step with brand-safety and disclosure checks, scheduling within each platform's publishing limits, publishing through the platforms' APIs, and analytics that feed the next round of ideas. Unit 6 covered creating content for each format; Module 7.20 produced the raw material from long-form content. This module automates its distribution.

## 1. First-Principles Mental Model & Intuition

### A newsroom's social desk

Picture a newspaper's social media desk. An ideas board holds story angles. A writer drafts posts for each platform, short and punchy for one, longer for another. An editor checks every post before it goes out: facts, tone, legal issues, and whether any sponsored content is clearly labelled. A scheduler places the approved posts through the day, never two on the same platform too close together. And every Monday, the desk looks at which posts people engaged with, and adjusts the ideas board.

```text
   IDEA BACKLOG          ideas tagged by pillar (how-to, product, behind-the-scenes), with sources
        |
        v
   DRAFT                 AI writes one variant per platform, from the idea and its source only
        |
        v
   FORMAT AND LINT       platform length rules, hashtags, links, disclosure for sponsored posts
        |
        v
   APPROVAL              a person approves, edits, or rejects (brand safety, facts, tone)
        |
        v
   SCHEDULE              slots per platform, caps per rolling 24 hours, minimum spacing
        |
        v
   PUBLISH               platform APIs (LinkedIn Posts, Instagram and Threads publishing, X)
        |
        v
   MEASURE               engagement per post -> per pillar -> back to the backlog
```

### The four platforms in this project

| Platform | Typical length rule | Publishing route |
|---|---|---|
| X | Up to 280 weighted characters; links count as 23 | X API |
| Threads | 500 characters; emoji count as their UTF-8 byte length | Threads API |
| Instagram | Caption length limit; links in captions are not clickable | Instagram content publishing API |
| LinkedIn | Long posts allowed; a length error is returned if exceeded | LinkedIn Posts API |

Platform rules change, so treat limits as configuration checked against each platform's current documentation, not constants buried in code.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### The idea backlog and content pillars

A **content pillar** is a recurring theme, such as how-to guides, product news, or behind the scenes. Tagging every idea with a pillar makes balance and measurement possible: a schedule can mix pillars, and analytics can compare them. Each idea also records its source, a blog post, a transcript segment from Module 7.20, a product page, because AI drafts must be grounded in a source, as in Modules 7.18 and 7.20, not in the model's imagination.

### Drafting per platform

The drafting prompt takes the idea, its source, the platform, and the brand voice from the system prompt of Module 5.7, and returns one variant per platform. The variants should differ in more than length: a LinkedIn post can explain, an X post must make one point, an Instagram caption supports an image. Generating each platform's version separately, with its rules in the prompt, works better than shortening one master text.

### Counting length the way each platform does

Length limits are where naive automation fails most visibly. Counting `len(text)` is wrong on at least two platforms:

**X.** The developer documentation explains that posts can contain up to 280 characters, but not all characters count equally. Every URL is wrapped by the t.co link shortener and counts as **23 characters**, whatever its real length. Emoji count as 2. Characters from some scripts, such as Chinese, Japanese, and Korean, are also weighted 2. A 130-character post whose URL is 73 characters long counts as only 80 on X.

**Threads.** Meta's Threads documentation gives a 500-character limit and states that **emoji count as their UTF-8 byte length**, so a typical emoji, four bytes in UTF-8, uses four of the 500.

The lab implements simplified versions of both rules: URLs as 23 and characters outside Unicode's Basic Multilingual Plane, where most emoji live, as 2 on X and as their UTF-8 bytes on Threads. A production system should use each platform's official counting library or documented algorithm.

### Brand safety and disclosure

An approval step catches what automation cannot judge: tone, accuracy, sensitivity to current events, and claims that need evidence. Some checks can be automated in front of the person, flagging rather than deciding:

| Check | Why |
|---|---|
| Length within the platform limit | Rejected or truncated posts |
| Words from a blocked list | Competitor names, sensitive terms, legal claims |
| Links that work and point to the right domain | Broken or wrong links in a scheduled post |
| Disclosure on sponsored or affiliated posts | Consumer protection law |

The last deserves detail. The US Federal Trade Commission's "Disclosures 101 for Social Media Influencers" says to disclose any financial, employment, personal, or family relationship with a brand; to put the disclosure **with the endorsement itself, where it is hard to miss**; to use plain words such as "ad" or "sponsored"; and not to bury it among hashtags or behind a "more" link. A brand that pays for or gifts products to creators, or posts about partners, needs the same discipline. An automated check can confirm that a disclosure word appears, and that it appears early, in the part of the post visible before any truncation; the lab treats the first 125 characters as that visible preview, a parameter to set per platform.

### Publishing limits and scheduling

Platforms limit how many posts an account can publish through their APIs. At the time of writing (November 2026), Meta's Threads documentation allows 250 API-published posts per profile in a rolling 24-hour period, with a carousel counting as one. Meta's Instagram content publishing documentation gives a limit of 100 API-published posts in a rolling 24-hour period in one place and 50 in another, which is itself a lesson: limits change and documentation lags, so call the API's own `content_publishing_limit` endpoint to check current usage before publishing a batch.

Most brands post far below these caps, and their own rules are stricter: no more than two Instagram posts a day, at least three hours apart. A scheduler therefore enforces two constraints per platform:

$$\text{count of posts in the last 24 hours} < \text{cap} \qquad \text{and} \qquad t - t_{\text{last}} \ge \text{minimum gap}$$

The lab's scheduler walks through time slots and places the first queued post whose platform satisfies both, so a backlog spreads out naturally across days.

### Publishing APIs

Each platform has its own publishing API and authentication, via OAuth as Module 7.15 described.

| Platform | Publishing call | Notes |
|---|---|---|
| LinkedIn | `POST https://api.linkedin.com/rest/posts` | Headers `Linkedin-Version` (YYYYMM) and `X-Restli-Protocol-Version: 2.0.0`; success is 201 with the post ID in the `x-restli-id` header; member posts need the `w_member_social` permission, organisation posts `w_organization_social` |
| Instagram | Create a media container, then publish it | Two steps; check the publishing limit first |
| Threads | Create a container, then publish it | The same two-step pattern |
| X | Create a post through the X API | Access and pricing depend on the API plan |

LinkedIn's version header deserves a note: versions are dated by month, and each is supported for a limited time before it is retired, so the version is configuration to review regularly, like the model names in Module 7.10. The Posts API documentation also notes that for article posts LinkedIn does not fetch the link's preview for you: the title, description, and thumbnail must be supplied.

### Measuring and feeding back

Platforms report impressions and interactions per post. A simple, comparable measure is the **engagement rate**:

$$\text{engagement rate} = \frac{\text{likes} + \text{comments} + \text{shares} + \text{saves}}{\text{impressions}}$$

Averaged per pillar, it shows which themes resonate. Feeding it back means weighting the backlog: more ideas from strong pillars, fewer from weak ones, while keeping some variety so the account does not collapse into one theme. Two cautions apply: small samples mislead, a pillar with one viral post is not a trend; and engagement is not the goal, sales, sign-ups, or enquiries are, so track clicks and conversions too where possible.

### Complexity

Length counting is linear in the post's length. Disclosure checks are linear in the text. Scheduling walks time slots and the queue, roughly the number of slots times the queue length in this simple form. Building a request is constant. Pillar analytics is linear in the posts.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, counting length per platform.

```python
import re

URL = re.compile(r"https?://\S+")
LIMITS = {"x": 280, "threads": 500, "linkedin": 3000, "instagram": 2200}

def post_length(text, platform):
    if platform == "x":
        text = URL.sub("x" * 23, text)
        return sum(2 if ord(character) > 0xFFFF else 1 for character in text)
    if platform == "threads":
        return sum(len(character.encode("utf-8")) if ord(character) > 0xFFFF else 1 for character in text)
    return len(text)

POST = "New chisel guide: how to get a mirror edge in 10 minutes https://tidytools.example/blog/chisel-sharpening-guide-for-beginners-2026"
print(len(POST), post_length(POST, "x"), post_length(POST, "linkedin"))
EMOJI = "Sharp! \U0001FA9A\U0001FA9A"
print(len(EMOJI), post_length(EMOJI, "x"), post_length(EMOJI, "threads"), post_length("café", "threads"))
```

- **On X, every URL counts as 23 characters.** The 130-character post with a long link counts as 80, leaving plenty of room.
- **On LinkedIn the plain length is used.** The same post is 130 characters.
- **Emoji outside the Basic Multilingual Plane count as 2 on X and as 4 bytes on Threads.** "Sharp! " plus two saw emoji is 9 characters to Python, 11 on X, and 15 on Threads.
- **Accented letters count as one on Threads here.** "café" is 4. Only emoji are measured in bytes, following the documented rule.
- **The limits table is configuration.** The values for LinkedIn and Instagram are commonly published figures; check each platform's documentation before relying on them.

Next, checking disclosures.

```python
DISCLOSURE = re.compile(r"(#ad\b|\bad\b|\bsponsored\b|\bpaid partnership\b)", re.IGNORECASE)

def disclosure_issues(text, sponsored, visible=125):
    if not sponsored:
        return []
    found = DISCLOSURE.search(text)
    if not found:
        return ["missing_disclosure"]
    return ["disclosure_not_visible"] if found.start() >= visible else []

LONG = ("We tested Narex's new chisels for a month and here is what we found about the steel, the handles "
        "and the edge retention in real use. #woodworking #chisels #tools #ad")
print(disclosure_issues("Ad: we teamed up with Narex to test their new chisels.", True))
print(disclosure_issues(LONG, True))
print(disclosure_issues("Our favourite chisels.", True), disclosure_issues("Our favourite chisels.", False))
print(disclosure_issues("Download our free guide today", True))
```

- **Only sponsored posts are checked.** Whether a post is sponsored is recorded on the idea, not guessed from the text.
- **"Ad:" at the start passes.** Clear, plain, and visible.
- **"#ad" at the end of a long post fails.** It appears at position 162, after the visible preview and among a block of hashtags, exactly what the FTC guidance warns against.
- **A sponsored post with no disclosure word fails.** The same text unsponsored passes.
- **Word boundaries prevent false matches.** "Download" contains the letters "ad" but is not a disclosure.

Then, scheduling within caps and spacing.

```python
from datetime import datetime, timedelta

def schedule(posts, start, slot_minutes, caps, min_gap, max_slots=1000):
    placed, history, queue, moment = [], {}, list(posts), start
    for _ in range(max_slots):
        if not queue:
            break
        for post in queue:
            times = history.setdefault(post["platform"], [])
            recent = [t for t in times if moment - t < timedelta(hours=24)]
            if len(recent) < caps[post["platform"]] and (not times or moment - times[-1] >= min_gap[post["platform"]]):
                times.append(moment)
                placed.append((post["id"], post["platform"], moment))
                queue.remove(post)
                break
        moment += timedelta(minutes=slot_minutes)
    return placed

QUEUE = [{"id": f"p{i}", "platform": platform} for i, platform in enumerate(["instagram", "instagram", "x", "instagram", "x", "threads"])]
CAPS = {"instagram": 2, "x": 5, "threads": 250}
GAPS = {"instagram": timedelta(hours=3), "x": timedelta(hours=1), "threads": timedelta(hours=1)}
for post_id, platform, when in schedule(QUEUE, datetime(2026, 11, 16, 9, 0), 60, CAPS, GAPS):
    print(post_id, platform, when.strftime("%a %H:%M"))
```

- **Each hourly slot takes the first queued post whose platform allows it.** One post per slot keeps the account's output steady.
- **Instagram's own rules here are two posts a day, three hours apart.** The brand's caps, far below the platform's.
- **p0 goes at 09:00 Monday.** p1, the next Instagram post, must wait three hours, so X's p2 and p4 take the 10:00 and 11:00 slots.
- **p1 goes at 12:00, the second Instagram post of the rolling day.**
- **p3, the third Instagram post, waits until 09:00 Tuesday.** That is the first moment when fewer than two Instagram posts fall within the previous 24 hours.
- **The loop has a limit on slots.** A queue that can never be placed, for example a platform with a cap of zero, cannot loop forever.

Finally, a LinkedIn request and pillar analytics.

```python
def linkedin_request(author, text, version="202611"):
    body = {"author": author, "commentary": text, "visibility": "PUBLIC",
            "distribution": {"feedDistribution": "MAIN_FEED", "targetEntities": [], "thirdPartyDistributionChannels": []},
            "lifecycleState": "PUBLISHED", "isReshareDisabledByAuthor": False}
    headers = {"Content-Type": "application/json", "Linkedin-Version": version, "X-Restli-Protocol-Version": "2.0.0"}
    return "https://api.linkedin.com/rest/posts", headers, body

url, headers, body = linkedin_request("urn:li:organization:5515715", "Three mistakes that ruin a chisel edge, and how to avoid them.")
print(url, headers["Linkedin-Version"], body["author"], body["lifecycleState"])

def pillar_report(posts):
    rates = {}
    for post in posts:
        interactions = post["likes"] + post["comments"] + post["shares"] + post["saves"]
        rates.setdefault(post["pillar"], []).append(interactions / post["impressions"] if post["impressions"] else 0.0)
    return sorted(((pillar, round(100 * sum(values) / len(values), 2), len(values)) for pillar, values in rates.items()),
                  key=lambda row: -row[1])

POSTS = [{"pillar": "how-to", "impressions": 4000, "likes": 180, "comments": 22, "shares": 30, "saves": 95},
         {"pillar": "how-to", "impressions": 2500, "likes": 90, "comments": 10, "shares": 12, "saves": 60},
         {"pillar": "product", "impressions": 6000, "likes": 120, "comments": 8, "shares": 5, "saves": 15},
         {"pillar": "behind-the-scenes", "impressions": 1800, "likes": 95, "comments": 30, "shares": 4, "saves": 3},
         {"pillar": "product", "impressions": 3000, "likes": 40, "comments": 2, "shares": 1, "saves": 4}]
print(pillar_report(POSTS))
```

- **The request follows the Posts API's documented shape.** The author is a person or organisation URN; the text goes in `commentary`; the post is public, in the main feed, and published rather than a draft.
- **The version header is configuration.** It names the monthly API version and must be updated before that version is retired.
- **The token goes in an Authorization header added by the HTTP step from the credential store,** never in this function, as Module 7.15 described.
- **Engagement rate is interactions over impressions, averaged per pillar.** How-to posts average 7.53 percent, behind-the-scenes 7.33 percent, and product posts 2.02 percent.
- **The count per pillar is reported with the rate.** Behind-the-scenes rests on a single post, too few to conclude much; how-to has two strong results.
- **The feedback is a weighting, not a rule.** More how-to ideas next month, a few more behind-the-scenes posts to test the signal, and product posts reworked rather than dropped, since they may drive sales that engagement does not show.

**Complexity.** `post_length` and `disclosure_issues` are linear in the text. `schedule` is bounded by the slots times the queue. `linkedin_request` is constant. `pillar_report` is linear in the posts plus sorting the pillars.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Counting characters with `len`.** X weights URLs and emoji; Threads counts emoji in bytes. Use each platform's rules.

**One text for every platform.** A LinkedIn essay cut to 280 characters reads badly. Draft per platform.

**Auto-publishing without approval.** One badly timed or inaccurate post can undo months of work. Keep a person in the loop.

**Posting during a crisis.** Scheduled cheerful posts during bad news look careless. Have a one-click pause for the whole schedule.

**Hidden disclosures.** "#ad" at the end of a hashtag block is what regulators warn against. Put it first.

**Hard-coded limits.** Platform limits and documentation change. Keep limits in configuration and check publishing quotas through the API.

**Expired tokens on a Friday night.** Scheduled posts fail silently over the weekend. Refresh early and alert on failures, as Modules 7.14 and 7.15 described.

**Retired API versions.** A LinkedIn version that has been retired starts returning errors. Track version dates.

**Link previews missing.** LinkedIn article posts need their title, description, and thumbnail supplied. Fetch them from the page and include them.

**Engagement chasing.** Optimising only for likes produces content that is liked and not bought from. Track clicks and conversions too.

**Small-sample conclusions.** One viral post is not a pillar's performance. Wait for enough posts before reweighting heavily.

**Ignoring replies.** Publishing is half of social media. Route comments and messages to a person.

"""
Lab solution: Platform Lengths, Disclosures, Scheduling Caps, LinkedIn Requests, and Pillar Analytics
Standard library only. No network calls.

import re
from datetime import datetime, timedelta

URL = re.compile(r"https?://\S+")
LIMITS = {"x": 280, "threads": 500, "linkedin": 3000, "instagram": 2200}
DISCLOSURE = re.compile(r"(#ad\b|\bad\b|\bsponsored\b|\bpaid partnership\b)", re.IGNORECASE)


# ---------------------------------------------------------------- Step 1
def post_length(text, platform):
    """Each platform counts its own way: X weights URLs and emoji; Threads counts emoji in bytes."""
    if platform == "x":
        text = URL.sub("x" * 23, text)
        return sum(2 if ord(character) > 0xFFFF else 1 for character in text)
    if platform == "threads":
        return sum(len(character.encode("utf-8")) if ord(character) > 0xFFFF else 1 for character in text)
    return len(text)


# ---------------------------------------------------------------- Step 2
def disclosure_issues(text, sponsored, visible=125):
    """Plain words, early, with the endorsement: hard to miss, never buried."""
    if not sponsored:
        return []
    found = DISCLOSURE.search(text)
    if not found:
        return ["missing_disclosure"]
    return ["disclosure_not_visible"] if found.start() >= visible else []


# ---------------------------------------------------------------- Step 3
def schedule(posts, start, slot_minutes, caps, min_gap, max_slots=1000):
    """Rolling 24-hour caps and minimum gaps per platform; one post per slot; bounded so it cannot loop forever."""
    placed, history, queue, moment = [], {}, list(posts), start
    for _ in range(max_slots):
        if not queue:
            break
        for post in queue:
            times = history.setdefault(post["platform"], [])
            recent = [t for t in times if moment - t < timedelta(hours=24)]
            if len(recent) < caps[post["platform"]] and (not times or moment - times[-1] >= min_gap[post["platform"]]):
                times.append(moment)
                placed.append((post["id"], post["platform"], moment))
                queue.remove(post)
                break
        moment += timedelta(minutes=slot_minutes)
    return placed


# ---------------------------------------------------------------- Step 4
def linkedin_request(author, text, version="202611"):
    """The Posts API shape; the token is added by the HTTP step from the credential store."""
    body = {"author": author, "commentary": text, "visibility": "PUBLIC",
            "distribution": {"feedDistribution": "MAIN_FEED", "targetEntities": [], "thirdPartyDistributionChannels": []},
            "lifecycleState": "PUBLISHED", "isReshareDisabledByAuthor": False}
    headers = {"Content-Type": "application/json", "Linkedin-Version": version, "X-Restli-Protocol-Version": "2.0.0"}
    return "https://api.linkedin.com/rest/posts", headers, body


# ---------------------------------------------------------------- Step 5
def pillar_report(posts):
    """Mean engagement rate per pillar, with the sample size alongside."""
    rates = {}
    for post in posts:
        interactions = post["likes"] + post["comments"] + post["shares"] + post["saves"]
        rates.setdefault(post["pillar"], []).append(interactions / post["impressions"] if post["impressions"] else 0.0)
    return sorted(((pillar, round(100 * sum(values) / len(values), 2), len(values)) for pillar, values in rates.items()),
                  key=lambda row: -row[1])
