# Downloading Models

With Ollama installed, Module 10.3, the next step is getting models. One command downloads a model, but the name you type decides a lot: the model's size, its quantization, and therefore how good it is, how much disk it uses, and whether it fits in your GPU memory. This module covers pulling, listing, inspecting, copying, and removing models; reading tags; and budgeting disk and memory so that downloads do not surprise you.

Sizes and tags quoted here are from the Ollama library at the time of writing (November 2026). They change as models are updated, so check the tags page of each model before relying on a number.

## 1. First-Principles Mental Model & Intuition

### Buying timber

Choosing a model download is like buying timber for a project. The **species** is the model family, such as Qwen3 or Llama. The **dimensions** are the parameter count, 4B, 8B, or 14B: bigger pieces do more but are heavier to carry and need more space. The **grade** is the quantization: a premium grade, FP16, is precise and heavy; a standard grade, Q4_K_M, is lighter and good enough for most jobs; a low grade, Q2_K, is light but full of knots. The **label** on the timber, the tag, tells you all of this if you know how to read it. And the **store room** is your disk: if you keep buying without clearing out offcuts, it fills up.

```text
 ollama pull qwen3:8b-q4_K_M
             |     |  |
             |     |  +-- quantization (grade): q4_K_M, q8_0, fp16
             |     +----- size (dimensions): 0.6b, 4b, 8b, 14b, 30b-a3b
             +----------- model family (species)

 ollama.com registry --pull--> manifest (list of layers) + blobs (weights, template, params, licence)
                                stored in OLLAMA_MODELS:  manifests/   blobs/sha256-<digest>
 ollama ls   -> what is installed        ollama show -> details of one model
 ollama cp   -> new name, same blobs     ollama rm   -> remove a name (unused blobs freed)
```

### Why this matters

A wrong guess costs real time and space: an FP16 70B model is well over a hundred gigabytes, takes hours to download on a home connection, and will not run on a consumer GPU. A few seconds reading the tags page first avoids that.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### The commands

| Command | What it does |
|---|---|
| `ollama pull qwen3:8b` | Download a model, or update it: only changed layers are fetched |
| `ollama run qwen3:8b` | Pull if missing, then run |
| `ollama ls` | List installed models: NAME, ID, SIZE, MODIFIED |
| `ollama show qwen3:8b` | Architecture, parameter count, context length, quantization, licence |
| `ollama cp qwen3:8b shop-base` | A new name pointing at the same data |
| `ollama rm qwen3:14b` | Remove a model name |

The same operations are available over the API, for example a `POST /api/pull` that streams download progress. Pulls of models from Hugging Face use `hf.co/{user}/{repository}:{quantization}`, Module 10.2; Ollama's import documentation also covers bringing in a local GGUF file or Safetensors weights with a Modelfile.

### Reading a tag

Library tags follow a pattern, though not every model uses every part:

| Part | Examples | Meaning |
|---|---|---|
| Size | `0.6b`, `8b`, `14b`, `235b` | Total parameters, in billions |
| Active parameters | `a3b`, `a22b` | Mixture-of-experts models: parameters used per token, Module 10.10 |
| Variant | `instruct`, `thinking`, `instruct-2507` | Tuning style or release |
| Quantization | `q4_K_M`, `q8_0`, `fp16` | Precision of the stored weights |

A tag without a quantization is an alias, usually for the default 4-bit quantization. On the Qwen3 tags page at the time of writing, `qwen3:8b`, `qwen3:latest`, and `qwen3:8b-q4_K_M` share one ID and size, 5.2 GB; `qwen3:8b-q8_0` is 8.9 GB; `qwen3:8b-fp16` is 16 GB. A tag without a size, `llama3.2`, means `latest`, whichever size the publisher chose as default.

### Quantization names

Quantization stores each weight in fewer bits, Module 10.1. In llama.cpp's names, the number is the nominal bits per weight; `_0` and `_1` are simple older schemes; `K` marks the "k-quant" schemes, which quantize blocks with per-block scales; and `S`, `M`, `L` are small, medium, and large mixes, keeping some sensitive tensors at higher precision. `q4_K_M` is the usual default because it keeps quality close to 8-bit on most tasks at roughly half the size. Lower than 4 bits, quality drops faster; `q8_0` is nearly indistinguishable from FP16 for most uses.

### Estimating size

File size is roughly parameters times bits per weight:

$$\text{size (GB)} \approx \frac{P_{\text{billion}} \times b_{\text{effective}}}{8}$$

The effective bits are a little above the nominal number, because of block scales and the tensors kept at higher precision. Qwen3 8B has about 8.2 billion parameters, so at 5.2 GB the `q4_K_M` file works out to about $5.2 \times 8 / 8.2 \approx 5.1$ bits per weight, and `q8_0` at 8.9 GB to about 8.7.

### Disk: shared layers

A model is stored as a **manifest**, a list of layers, plus **blobs**, one file per layer named by the SHA-256 digest of its content. Layers are the weights, the prompt template, the parameters, the system prompt, and the licence. Because blobs are identified by content, two models that share weights store them once. A custom model built with a Modelfile `FROM qwen3:8b`, Module 10.2, adds only a tiny layer for its system prompt and parameters. `ollama cp` creates a new manifest pointing at the same blobs. But `ollama ls` shows each name with its full size, so adding up its SIZE column overstates real disk usage:

$$\text{actual} = \sum_{d \,\in\, \text{unique digests}} \text{size}(d) \;\le\; \text{naive} = \sum_{\text{models}} \sum_{\text{layers}} \text{size}$$

Different quantizations of the same model, `q4_K_M` and `q8_0`, have different weights and share nothing large.

Removing a model removes its name; blobs are freed only when no remaining manifest refers to them. Removing a custom model built on `qwen3:8b` frees almost nothing while `qwen3:8b` remains.

### Memory: does it fit?

To run fully on the GPU, the model's weights, plus the **KV cache** for the context, plus runtime overhead, must fit in GPU memory, Module 10.10. A rough rule of thumb before downloading: allow about 20 per cent above the file size for a modest context.

$$\text{fits} \iff \text{size} \times 1.2 \le \text{memory}$$

With a choice of quantizations ordered from best quality to smallest, pick the first that fits. On a 12 GB GPU, `qwen3:8b-q8_0` at $8.9 \times 1.2 = 10.68$ GB fits, while `fp16` at $19.2$ GB does not. Long contexts need much more memory, so this rule is a first filter, not a guarantee; `ollama ps` after loading is the check, Module 10.2.

### Complexity

Parsing tags and listings is linear in their size. Computing disk usage is linear in the total number of layers, using a dictionary of digests. Choosing a quantization is linear in candidates. The cleanup plan sorts models, $O(n \log n)$.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, reading tags.

```python
import re

def parse_tag(ref):
    model, _, tag = ref.partition(":")
    tag = tag or "latest"
    out = {"model": model, "tag": tag, "size": None, "active": None, "variant": None, "quant": None}
    rest = []
    for part in tag.split("-"):
        if out["size"] is None and re.fullmatch(r"\d+(\.\d+)?[bm]", part):
            out["size"] = part
        elif re.fullmatch(r"a\d+(\.\d+)?b", part):
            out["active"] = part
        elif re.fullmatch(r"q\d\w*|fp16|bf16", part):
            out["quant"] = part
        elif part != "latest":
            rest.append(part)
    out["variant"] = "-".join(rest) or None
    return out

for ref in ["qwen3:8b", "qwen3:8b-q4_K_M", "qwen3:30b-a3b-instruct-2507-q8_0", "llama3.2", "llama3.1:8b-instruct-q4_K_M"]:
    print(ref, parse_tag(ref))
```

- **Split on hyphens and classify each part.** The first number-plus-`b` is the size; `a3b` is active parameters; `q`-something or `fp16` is the quantization; the rest is the variant.
- **`qwen3:8b` has no quantization in its name.** It is an alias for the default, which the tags page shows as `q4_K_M`.
- **`instruct-2507` is a release variant.** Different releases of the same size can behave differently.

Next, parsing `ollama ls`.

```python
LS = """NAME                       ID              SIZE      MODIFIED
qwen3:8b                   500a1f067a9f    5.2 GB    2 days ago
shop-assistant:latest      7c1e2d9b4f30    5.2 GB    2 days ago
qwen3:8b-q8_0              3f9a8d21c6e4    8.9 GB    3 weeks ago
qwen3:14b                  bdbd181c33f2    9.3 GB    2 months ago
llama3.2:latest            a80c4f17acd5    2.0 GB    5 months ago
nomic-embed-text:latest    0a109f422b47    274 MB    6 weeks ago"""
UNIT_DAYS = {"hour": 0, "day": 1, "week": 7, "month": 30, "year": 365}

def parse_ls(text):
    rows = []
    for line in text.strip().splitlines()[1:]:
        cols = re.split(r"\s{2,}", line.strip())
        num, unit = cols[2].split()
        gb = float(num) / 1000 if unit == "MB" else float(num)
        m = re.match(r"(\d+|an?) (\w+?)s? ago", cols[3])
        n = int(m.group(1)) if m.group(1).isdigit() else 1
        rows.append({"name": cols[0], "id": cols[1], "gb": round(gb, 3), "age_days": n * UNIT_DAYS[m.group(2)]})
    return rows

rows = parse_ls(LS)
print(rows[0], round(sum(r["gb"] for r in rows), 3))
```

- **Sizes come in GB and MB.** The embedding model is 274 MB, 0.274 GB.
- **Ages are relative.** Converting to days, with a month as 30, is enough to sort by staleness.
- **The naive total is 30.874 GB.** It is not the real disk usage, as the next function shows.

Then, real disk usage from manifests.

```python
MANIFESTS = {
    "qwen3:8b": [("sha256:a3de", 5.2), ("sha256:tmpl", 0.001), ("sha256:prm1", 0.001)],
    "shop-assistant:latest": [("sha256:a3de", 5.2), ("sha256:tmpl", 0.001), ("sha256:sys9", 0.001), ("sha256:prm2", 0.001)],
    "qwen3:8b-q8_0": [("sha256:b81f", 8.9), ("sha256:tmpl", 0.001), ("sha256:prm1", 0.001)],
}

def disk_usage(manifests):
    naive = sum(size for layers in manifests.values() for _, size in layers)
    unique = {}
    for layers in manifests.values():
        for digest, size in layers:
            unique[digest] = size
    actual = sum(unique.values())
    return round(naive, 3), round(actual, 3), round(naive - actual, 3)

print(disk_usage(MANIFESTS))
```

- **Shortened digests stand in for real SHA-256 values.** The logic is the same.
- **The shop's custom model shares the 5.2 GB weights blob with `qwen3:8b`.** Naive 19.307 GB, actual 14.104 GB, shared 5.203 GB.
- **The `q8_0` weights are a different blob.** Only the tiny template and parameter layers are shared with the base.

Then, choosing a quantization for the memory available.

```python
QWEN3_8B = [("qwen3:8b-fp16", 16.0), ("qwen3:8b-q8_0", 8.9), ("qwen3:8b-q4_K_M", 5.2)]

def choose_quant(candidates, memory_gb, headroom=1.2):
    for tag, gb in candidates:
        if gb * headroom <= memory_gb:
            return tag
    return None

print([choose_quant(QWEN3_8B, m) for m in [24, 19.2, 12, 8, 6]])
```

- **Candidates are ordered best quality first.** The first that fits wins.
- **24 GB and exactly 19.2 GB fit FP16; 12 GB fits `q8_0`; 8 GB fits `q4_K_M`; 6 GB fits nothing.** At 6 GB, choose a smaller model, `qwen3:4b`, rather than a lower quantization of 8B.
- **The headroom is a rule of thumb.** Long contexts need more, Module 10.10.

Finally, a cleanup plan.

```python
def cleanup(rows, keep, need_gb):
    removals, freed = [], 0.0
    for r in sorted(rows, key=lambda r: -r["age_days"]):
        if freed >= need_gb:
            break
        if r["name"] in keep:
            continue
        removals.append(f"ollama rm {r['name']}")
        freed += r["gb"]
    return removals, round(freed, 3)

print(cleanup(rows, {"qwen3:8b", "shop-assistant:latest"}, 10))
```

- **Oldest first, skipping what must be kept.** Llama 3.2, five months unused, goes first; then Qwen3 14B: 11.3 GB freed, enough for the 10 GB needed.
- **Freed space is an estimate.** It uses listed sizes, so removing a model that shares blobs with a kept model frees less than listed; check free space afterwards.
- **The output is commands, not actions.** A person reviews them before running anything.

**Complexity.** Linear for tags, listings, and disk usage; $O(n \log n)$ for the cleanup sort.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Pulling before reading the tags page.** Sizes surprise people. Check size and quantization first.

**Assuming `latest` is the biggest or best.** It is the publisher's default. Pin explicit tags.

**Downloading FP16 "for quality".** For most local uses, `q8_0` or `q4_K_M` is nearly as good. Compare on your own tasks.

**Going below 4 bits to squeeze a bigger model in.** Quality drops quickly. A smaller model at 4 bits is often better.

**Adding up `ollama ls`.** Shared blobs make the total misleading. Check actual folder size.

**Removing a custom model to save space.** Its weights belong to the base. Remove the base too, if unused.

**System drive filling.** Set `OLLAMA_MODELS` first, Module 10.3.

**Interrupted downloads.** Re-run the pull; completed layers are not downloaded again.

**Re-pulling to update.** Updating `latest` can change behaviour. Re-run your evaluation, Module 10.15.

**Ignoring context length.** `ollama show` reports the model's maximum. The effective one is set separately, Module 10.2.

**Mixture-of-experts sizes.** `30b-a3b` uses about 3B parameters per token but needs memory for all 30B. Budget memory by the total.

**Licences.** Model licences differ. Check `ollama show` and the model page before commercial use, Modules 10.5 to 10.9.

# ---------------------------------------------------------------- Step 1
def parse_tag(ref):
    """Size, active parameters, variant, and quantization from a tag."""
    model, _, tag = ref.partition(":")
    tag = tag or "latest"
    out = {"model": model, "tag": tag, "size": None, "active": None, "variant": None, "quant": None}
    rest = []
    for part in tag.split("-"):
        if out["size"] is None and re.fullmatch(r"\d+(\.\d+)?[bm]", part):
            out["size"] = part
        elif re.fullmatch(r"a\d+(\.\d+)?b", part):
            out["active"] = part
        elif re.fullmatch(r"q\d\w*|fp16|bf16", part):
            out["quant"] = part
        elif part != "latest":
            rest.append(part)
    out["variant"] = "-".join(rest) or None
    return out


# ---------------------------------------------------------------- Step 2
def parse_ls(text):
    """Installed models with sizes in GB and ages in days."""
    rows = []
    for line in text.strip().splitlines()[1:]:
        cols = re.split(r"\s{2,}", line.strip())
        num, unit = cols[2].split()
        gb = float(num) / 1000 if unit == "MB" else float(num)
        m = re.match(r"(\d+|an?) (\w+?)s? ago", cols[3])
        n = int(m.group(1)) if m.group(1).isdigit() else 1
        rows.append({"name": cols[0], "id": cols[1], "gb": round(gb, 3), "age_days": n * UNIT_DAYS[m.group(2)]})
    return rows


# ---------------------------------------------------------------- Step 3
def disk_usage(manifests):
    """Blobs are stored once per digest, however many models refer to them."""
    naive = sum(size for layers in manifests.values() for _, size in layers)
    unique = {}
    for layers in manifests.values():
        for digest, size in layers:
            unique[digest] = size
    actual = sum(unique.values())
    return round(naive, 3), round(actual, 3), round(naive - actual, 3)


# ---------------------------------------------------------------- Step 4
def choose_quant(candidates, memory_gb, headroom=1.2):
    """Best quality that fits, with headroom for the KV cache and overhead."""
    for tag, gb in candidates:
        if gb * headroom <= memory_gb:
            return tag
    return None


# ---------------------------------------------------------------- Step 5
def cleanup(rows, keep, need_gb):
    """Reviewable removal commands, oldest unneeded models first."""
    removals, freed = [], 0.0
    for r in sorted(rows, key=lambda r: -r["age_days"]):
        if freed >= need_gb:
            break
        if r["name"] in keep:
            continue
        removals.append(f"ollama rm {r['name']}")
        freed += r["gb"]
    return removals, round(freed, 3)
