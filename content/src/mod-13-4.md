# AI Learning Roadmap

The 30-day roadmap in Unit 12 is one route through this course for one month. This module gives the bigger map: a **skill tree** from beginner to builder, showing which skills depend on which, the **resources** in this course for each, and **milestones and self-assessment** so you always know where you are and what to learn next. Unlike a fixed syllabus, a skill tree lets different learners take different paths while respecting the dependencies that matter: you cannot build reliable agents before you can get structured output from a model and measure quality.

Stages and scores are illustrative; adjust the tree to your goals, as Module 12.3 suggests.

## 1. First-Principles Mental Model & Intuition

### The apprentice's progression

A joinery apprenticeship has a natural order: sharpening and measuring before sawing to a line; sawing before cutting joints; simple joints before carcasses; carcasses before fitted furniture. Some skills can be learned in any order, such as finishing and sharpening, but others strictly depend on earlier ones. A good master keeps a record of what each apprentice can do and gives them the next piece that their current skills make possible, a little beyond what they have done before.

```text
 BEGINNER                 PRACTITIONER               BUILDER                        PROFESSIONAL
 how models work ----------------------------------> retrieval        local models
 (also: structured output -> retrieval; how models work -> local models)
 prompting basics -> structured output -> evaluation ---------> agents
       |                    |      \---------------> tool calling --/
       |                    \--> automation workflows -----------------------------> business offers
       +--> chat assistants ----/
       \--> coding with AI -------------------------> deployment

 skill tree = directed acyclic graph: arrows are prerequisites
 available now = not done, all prerequisites done      stage = last stage whose skills are all done
```

### Why a graph, not a list

A list forces one order on everyone. A graph shows the real constraints and leaves the rest free: a learner focused on business can reach automation workflows and business offers without touching retrieval, while a technical learner can go deep into agents. As long as prerequisites are respected, both are valid routes.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### The skill tree

The course's main skills and their prerequisites:

| Skill | Prerequisites | Course resources |
|---|---|---|
| How models work | none | Unit 1 |
| Prompting basics | none | Unit 5 |
| Chat assistants | prompting basics | Units 2 and 3 |
| Structured output | prompting basics | Module 8.5 |
| Evaluation | structured output | Module 8.12 |
| Automation workflows | chat assistants, structured output | Unit 7 |
| Retrieval | how models work, structured output | Modules 8.7 and 8.8 |
| Tool calling | structured output | Module 8.3 |
| Agents | tool calling, evaluation | Unit 8 |
| Coding with AI | prompting basics | Unit 9 |
| Deployment | coding with AI | Module 9.11 |
| Local models | how models work | Unit 10 |
| Business offers | automation workflows | Unit 11 |

Content creation, Unit 6, and the tools directory, Unit 4, sit alongside chat assistants and can be added as further branches.

### Graph terms

The tree is a **directed acyclic graph**: arrows point from prerequisite to dependent skill, and there are no cycles, because no skill can be its own prerequisite. A skill is **available** when it is not done and all its prerequisites are done. A **topological order** lists every skill after all its prerequisites; one exists exactly when the graph has no cycles. Kahn's method builds one by repeatedly taking an available skill and marking it done; if at some point no skill is available but some remain, the graph has a cycle. When several skills are available, choosing those in the earliest stage first, then alphabetically, gives a sensible and reproducible order.

### Stages and milestones

The skills group into four stages:

| Stage | Skills | Milestone |
|---|---|---|
| Beginner | how models work, prompting basics, chat assistants | Uses AI confidently for daily tasks |
| Practitioner | structured output, automation workflows, evaluation | Builds and measures a working automation |
| Builder | retrieval, tool calling, agents, coding with AI, deployment | Ships an evaluated agent or app |
| Professional | business offers, local models | Sells and supports AI work |

A learner's **current stage** is the last stage, in order, whose skills are all done. Stages are milestones, not gates: you may start builder skills before finishing every practitioner one, but you only claim a stage when it is complete.

### Self-assessment

Score each skill from 0, never done, to 5, could teach it, as in Module 12.1. Treat a score of 3 or more, can do it unaided on a real task, as done. The **next focus** is the available skills, earliest stage first. Self-assessment works best with evidence: a skill counts as done when you have a project that demonstrates it, not when you have watched a video. Bloom's taxonomy, which distinguishes remembering and understanding from applying, analysing, and creating, is a reminder that the roadmap's goal is application.

### Using resources

Each skill maps to course units and modules. The lab in each module is a natural test: if you can complete it unaided and quickly, score the skill at 3 or more; if not, study the module. External resources, such as official documentation, add depth once the basics are in place.

### Example routes through the tree

Three common routes show how the same tree serves different goals.

**The business route** suits someone who wants to sell automation to local firms: prompting basics, chat assistants, structured output, automation workflows, evaluation, then business offers. It reaches a sellable service quickly and leaves retrieval and agents for later, when client work demands them.

**The technical route** suits someone aiming at agent engineering: prompting basics, structured output, evaluation, tool calling, agents, then coding with AI and deployment, with retrieval added as soon as a project needs documents. It reaches the builder stage fastest but delays earning.

**The privacy route** suits someone serving clients with sensitive data, such as clinics or law firms: how models work, prompting basics, structured output, local models, retrieval, evaluation, then business offers, so that everything can run on the client's own hardware, Module 10.13.

All three respect the prerequisites; they differ in which branches come first. The roadmap in Unit 12 follows a balanced version that touches each branch within thirty days.

### Collecting evidence

A score is only as good as its evidence. For each skill, keep one artefact that proves it: a prompt library with test results for prompting, a validated JSON output for structured output, an evaluation set with a pass rate for evaluation, a running workflow for automation, a deployed or local app for deployment, a signed proposal for business offers. These artefacts double as portfolio material, Module 11.5, so the learning record and the sales material grow together. When a score is challenged, by a client or by yourself at a quarterly review, the artefact settles the question in a way a feeling of confidence cannot.

### Complexity

Finding available skills is $O(s \times p)$ for $s$ skills with up to $p$ prerequisites each, plus sorting; building a topological order this way is $O(s^2 p)$, fine for a few dozen skills; the stage check is linear in stages and skills.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, the tree and the skills available now.

```python
TREE = {
    "prompting basics": [], "how models work": [], "chat assistants": ["prompting basics"],
    "structured output": ["prompting basics"], "evaluation": ["structured output"],
    "automation workflows": ["chat assistants", "structured output"], "retrieval": ["how models work", "structured output"],
    "tool calling": ["structured output"], "agents": ["tool calling", "evaluation"], "coding with AI": ["prompting basics"],
    "deployment": ["coding with AI"], "local models": ["how models work"], "business offers": ["automation workflows"],
}
STAGES = [("beginner", ["prompting basics", "how models work", "chat assistants"]),
          ("practitioner", ["structured output", "automation workflows", "evaluation"]),
          ("builder", ["retrieval", "tool calling", "agents", "coding with AI", "deployment"]),
          ("professional", ["business offers", "local models"])]
RANK = {s: i for i, (_, skills) in enumerate(STAGES) for s in skills}

def available(tree, done):
    return sorted((s for s, pre in tree.items() if s not in done and all(p in done for p in pre)),
                  key=lambda s: (RANK.get(s, 9), s))

print(available(TREE, set()))
print(available(TREE, {"prompting basics"}))
```

- **A newcomer can start two skills:** how models work and prompting basics.
- **After prompting basics, four are open,** ordered earliest stage first: chat assistants, how models work, structured output, then coding with AI.

Next, a learning order.

```python
def learning_order(tree):
    done, order = set(), []
    while len(order) < len(tree):
        nxt = available(tree, done)
        if not nxt:
            raise ValueError("cycle")
        order.append(nxt[0])
        done.add(nxt[0])
    return order

print(learning_order(TREE))
```

- **Thirteen skills in an order that respects every prerequisite,** finishing the beginner stage first.
- **A cycle raises an error,** catching mistakes in the tree.

Then, the current stage.

```python
def stage(done):
    reached = "starting"
    for name, skills in STAGES:
        if all(s in done for s in skills):
            reached = name
        else:
            break
    return reached

print(stage(set()), stage({"prompting basics", "how models work", "chat assistants"}), stage(set(TREE)))
```

- **Nothing done: starting. The three beginner skills: beginner. Everything: professional.**
- **Stages are claimed in order,** so builder skills without the practitioner stage do not count yet.

Then, mapping resources.

```python
RESOURCES = {"prompting basics": ["Unit 5"], "how models work": ["Unit 1"], "chat assistants": ["Units 2-3"],
             "structured output": ["Module 8.5"], "evaluation": ["Module 8.12"], "automation workflows": ["Unit 7"],
             "retrieval": ["Module 8.7", "Module 8.8"], "tool calling": ["Module 8.3"], "agents": ["Unit 8"],
             "coding with AI": ["Unit 9"], "deployment": ["Module 9.11"], "local models": ["Unit 10"],
             "business offers": ["Unit 11"]}

def plan(tree, done, k=3):
    return [(s, RESOURCES.get(s, [])) for s in available(tree, done)[:k]]

print(plan(TREE, {"prompting basics", "how models work"}))
```

- **Next three skills with where to learn them:** chat assistants in Units 2 and 3, structured output in Module 8.5, coding with AI in Unit 9.

Finally, the next focus from self-assessment.

```python
def next_focus(scores, tree, threshold=3):
    done = {s for s, v in scores.items() if v >= threshold}
    return available(tree, done)[:2], stage(done)

SAM = {"prompting basics": 4, "how models work": 3, "chat assistants": 4, "structured output": 3, "evaluation": 1,
       "automation workflows": 3, "tool calling": 2, "coding with AI": 3, "retrieval": 0}
print(next_focus(SAM, TREE))
```

- **Sam's next focus is evaluation, then deployment.** Evaluation completes the practitioner stage and unlocks agents.
- **Sam is still at the beginner stage on paper,** because evaluation, scored 1, is a practitioner skill. Completing it moves Sam to practitioner.

**Complexity.** Small and polynomial for a course-sized tree.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Skipping evaluation.** Agents without measurement fail quietly. Do it before agents.

**Jumping to agents.** Structured output and tool calling come first.

**Scoring from videos watched.** Score from things built.

**One order for everyone.** Follow the graph, not a list.

**Cycles in a home-made tree.** Check with a topological order.

**Claiming stages early.** A stage is complete only when all its skills are.

**Ignoring the business branch.** Skills earn when offered, Unit 11.

**Too many skills at once.** Two at a time.

**Never re-scoring.** Skills fade and grow; review quarterly.

**Copying someone else's tree.** Adapt it to your goals.

**Treating stages as gates.** Explore ahead; claim in order.

**Forgetting the basics.** Revisit prompting and evaluation as you advance.

**Question 2.** Using `learning_order`, explain what a topological order is and what happens if someone adds a prerequisite that creates a cycle.

<details>
<summary>View Answer</summary>

A topological order lists every skill after all of its prerequisites. `learning_order` builds one by repeatedly taking the first available skill, earliest stage first and then alphabetically, and marking it done; for the course tree it produces thirteen skills starting with how models work, prompting basics, and chat assistants, and ending with business offers and local models, and every skill appears after its prerequisites. If someone added a prerequisite making, for example, structured output depend on evaluation, which already depends on structured output, neither could ever become available: at some point no skill would be available while some remained, and `learning_order` raises a cycle error. That is the property of directed acyclic graphs: a topological order exists exactly when there is no cycle, so the function doubles as a check on the tree.

</details>

**Question 3.** Using `next_focus`, explain why Sam is still at the beginner stage on paper and what to do next.

<details>
<summary>View Answer</summary>

`next_focus` treats skills scored 3 or more as done. Sam has the beginner skills, plus structured output, automation workflows, and coding with AI, but evaluation is scored 1. Stages are claimed in order only when complete, so with evaluation missing, Sam cannot claim practitioner and `stage` reports beginner, even though Sam has done some builder work. The next focus is evaluation, from the practitioner stage, then deployment; both are available. Completing evaluation, for instance by building an evaluation set for the quote assistant as in Module 8.12, moves Sam to practitioner and unlocks agents together with tool calling, which Sam scores 2. The result is a short, concrete plan grounded in the dependency structure rather than in what seems most exciting.
