# Project 1: Personal Portfolio Website

The first Unit 9 project is a personal **portfolio website**: a small, fast, static site that presents who you are, shows evidence of what you can do, and makes it easy to contact you. It brings together Module 9.7's website skills, Module 9.10's Git workflow, and Module 9.11's deployment, and it is a good first project because the stakes are personal and the scope is clear.

AI makes the building part fast: a decent-looking site takes minutes. What AI cannot do is decide what you should say, find your evidence, or keep the design coherent across dozens of small edits. This project is mostly about those decisions, with code checks to keep them honest.

## 1. First-Principles Mental Model & Intuition

### A shop window for your work

A portfolio is a shop window: a passer-by gives it a few seconds, and in those seconds it must answer three questions: **who is this, what can they do for me, and how do I get in touch?** A good window shows a few excellent pieces with price tags, not everything in the stockroom. A cluttered window with a dozen half-finished items and no door handle loses customers.

```text
   PLAN      audience -> pages (home, projects, about, contact) -> each page: purpose + call to action
   CONTENT   3 to 6 project cards: problem, your role, a measurable outcome, a link
   BUILD     brief (Module 9.7) -> AI generates -> iterate ONE change at a time -> commit each (Module 9.10)
             keep a design system: small palette, small type scale
   POLISH    titles and descriptions per page, social preview image, links all working, accessibility audit
   SHIP      static host -> custom domain (A records + www CNAME) -> HTTPS enforced (Module 9.11)
```

### Evidence beats adjectives

Nielsen Norman Group's guidance on design portfolios stresses showing your process and the outcomes of your work, not just finished visuals. The same applies to developers: "passionate full-stack developer" says nothing; "built a lead tracker that cut response time from two days to four hours" says a great deal. AI writes fluent adjectives on demand, which makes concrete evidence the scarce, differentiating ingredient.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Planning content and structure

Start with the **audience**: for Priya, owners of trade businesses who need simple tools. Then the **pages**, typically home, projects, about, and contact, and for each page a **purpose**, what it must achieve, and a **call to action**, the one next step you want visitors to take. Keep the navigation short, a handful of items: every extra item dilutes attention. Check the plan for **orphan pages**, pages that nothing links to, which visitors cannot find and which are usually leftovers.

### Project cards

The projects page carries the weight. A strong project card has four parts:

| Part | Example |
|---|---|
| Problem | "Trade leads were lost in a shared inbox" |
| Your role | "Designed and built with Claude Code" |
| Measurable outcome | "Response time fell from 2 days to 4 hours" |
| Link | A live demo or repository over HTTPS |

Being honest about AI's role in your work is part of the role line; clients increasingly ask, and an accurate answer builds trust. Three to six strong cards beat fifteen weak ones.

### Building with AI and iterating on design

Use a complete brief as in Module 9.7, with your real content and the instruction not to invent anything, then iterate in small steps: one change per prompt, reviewed and committed, so any step can be undone. AI edits drift: ask for "a nicer button" five times and you get five slightly different shades of orange and four font sizes. A **design system** prevents this: a small **palette**, perhaps five colours including text and background, and a **type scale**, perhaps five or six sizes, stated in the brief and checked in the CSS. A simple consistency measure counts the distinct colour values and font sizes; more than the system allows means drift.

### Metadata and sharing

Each page needs a **title**, shown in browser tabs and often in search results, and a **meta description**, a summary that search engines may use as the snippet. Google's documentation notes there is no limit on description length, but snippets are truncated to fit the screen, so practical guidance keeps titles to roughly 60 characters and descriptions to roughly 160, and every page's title should be **unique** and descriptive. The **Open Graph** protocol adds tags such as `og:title` and `og:image` that control how a link looks when shared on social platforms and messaging apps; a portfolio shared without an image looks unfinished.

### Links

Before launch, every link should work: internal links pointing to pages that exist, external links using HTTPS, and no empty links. Broken links are a common result of AI edits that rename or remove pages without updating navigation elsewhere.

### Deploying and a custom domain

A portfolio is a static site, Module 9.11, so a static host such as GitHub Pages fits. GitHub's documentation for custom domains describes the setup: for the apex domain, A records pointing to GitHub's published IP addresses, at the time of writing four addresses from 185.199.108.153 to 185.199.111.153; for `www`, a CNAME to your `username.github.io` domain; then **Enforce HTTPS** in the repository settings once the certificate is issued. Your own domain looks professional and survives a change of host.

### Accessibility and performance

Apply Module 9.7's checks: alt text on every project image, contrast for text over brand colours, a viewport tag, and a page-weight budget. Portfolio images are the usual performance problem: screenshots exported at full resolution.

### Complexity

Plan and link checks are linear in pages and links. Card scoring is constant per card. Style consistency is linear in the stylesheet. Metadata checks are linear in pages.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, checking the site plan.

```python
import re

def site_plan(pages, nav, max_nav=6):
    issues = []
    if len(nav) > max_nav:
        issues.append(f"{len(nav)} navigation items; keep it to {max_nav}")
    linked = set(nav) | {t for p in pages.values() for t in p["links"]}
    for name in sorted(pages):
        page = pages[name]
        if not page.get("purpose"):
            issues.append(f"{name}: no stated purpose")
        if not page.get("cta"):
            issues.append(f"{name}: no call to action")
        if name not in linked and name != "home":
            issues.append(f"{name}: orphan page")
    issues += [f"navigation links to missing page {n}" for n in nav if n not in pages]
    return issues

PAGES = {"home": {"purpose": "who I am and what I do", "cta": "see projects", "links": ["projects", "contact"]},
         "projects": {"purpose": "evidence of skills", "cta": "contact me", "links": ["contact"]},
         "about": {"purpose": "background", "cta": "", "links": []},
         "contact": {"purpose": "get in touch", "cta": "send email", "links": []},
         "old-blog": {"purpose": "", "cta": "", "links": []}}
print(site_plan(PAGES, ["home", "projects", "about", "contact"]))
```

- **The about page has no call to action.** A visitor who reads it is left with nowhere to go; "see my projects" fixes it.
- **The old blog has no purpose and nothing links to it.** An AI leftover: delete it.
- **Navigation is checked for length and for links to pages that do not exist.**

Next, scoring project cards.

```python
def card_score(project):
    missing = []
    if len(project.get("problem", "")) < 20:
        missing.append("problem")
    if not project.get("role"):
        missing.append("role")
    if not re.search(r"\d", project.get("outcome", "")):
        missing.append("measurable outcome")
    if not str(project.get("link", "")).startswith("https://"):
        missing.append("https link")
    return round(1 - len(missing) / 4, 2), missing

STRONG = {"title": "Lead tracker", "problem": "Trade leads were lost in a shared inbox", "role": "Designed and built with Claude Code",
          "outcome": "Response time fell from 2 days to 4 hours", "link": "https://github.com/example/lead-tracker"}
WEAK = {"title": "Website", "problem": "A website", "role": "", "outcome": "Improved the brand", "link": "http://example.com"}
print(card_score(STRONG), card_score(WEAK))
```

- **A problem needs at least a sentence.** "A website" describes the output, not the problem.
- **An outcome needs a number.** "Improved the brand" cannot be checked; "2 days to 4 hours" can.
- **The strong card scores 1.0; the weak one 0.0.** Fix the cards before polishing the design.

Then, checking style consistency.

```python
COLOUR = re.compile(r"#(?:[0-9a-fA-F]{3}){1,2}\b")
SIZE = re.compile(r"font-size:\s*([\d.]+(?:px|rem|em))")

def style_consistency(css, max_colours=5, max_sizes=6):
    colours = sorted({c.lower() for c in COLOUR.findall(css)})
    sizes = sorted(set(SIZE.findall(css)))
    issues = []
    if len(colours) > max_colours:
        issues.append(f"{len(colours)} colours; use a palette of at most {max_colours}")
    if len(sizes) > max_sizes:
        issues.append(f"{len(sizes)} font sizes; use a type scale of at most {max_sizes}")
    return colours, sizes, issues

CSS = ("h1{color:#1b4d3e;font-size:2.5rem}h2{color:#1B4D3E;font-size:2rem}p{color:#333;font-size:1rem}"
       ".card{color:#334;border:#ddd}.btn{background:#e8590c;color:#fff;font-size:15px}"
       ".note{color:#2a2a2a;font-size:0.95rem}small{font-size:13px}.tag{font-size:0.8rem;color:#777}")
print(style_consistency(CSS))
```

- **Colours are compared in lower case, so `#1B4D3E` and `#1b4d3e` count once.**
- **Eight colours, including three near-identical dark greys, `#333`, `#334`, and `#2a2a2a`.** Classic drift from repeated AI edits.
- **Seven font sizes mixing pixels and rems.** Pick a scale and use it everywhere.

Then, page metadata.

```python
def meta_check(pages):
    issues, titles = [], {}
    for name, meta in pages.items():
        title, description = meta.get("title", ""), meta.get("description", "")
        if not 10 <= len(title) <= 60:
            issues.append(f"{name}: title is {len(title)} characters")
        if not 50 <= len(description) <= 160:
            issues.append(f"{name}: description is {len(description)} characters")
        if not meta.get("og_image"):
            issues.append(f"{name}: no og:image")
        titles.setdefault(title, []).append(name)
    issues += [f"duplicate title on {', '.join(sorted(names))}" for names in titles.values() if len(names) > 1]
    return issues

META = {"home": {"title": "Priya Shah | Developer building tools for trades",
                 "description": "I build practical web tools for trade businesses: lead trackers, booking systems, and quoting apps.",
                 "og_image": "/og/home.png"},
        "projects": {"title": "Priya Shah | Developer building tools for trades", "description": "Projects", "og_image": ""}}
print(meta_check(META))
```

- **Titles and descriptions are checked against practical length ranges.** Too short says nothing; too long is truncated.
- **The projects page has an 8-character description and no sharing image.**
- **Both pages share one title.** Search results and browser tabs cannot tell them apart.

Finally, link checks.

```python
LINK = re.compile(r'href="([^"]*)"')

def broken_links(pages):
    issues = []
    for name in sorted(pages):
        for href in LINK.findall(pages[name]):
            if not href:
                issues.append(f"{name}: empty link")
            elif href.startswith("http://"):
                issues.append(f"{name}: insecure link {href}")
            elif href.startswith("/"):
                target = href.strip("/").split("#")[0] or "home"
                if target not in pages:
                    issues.append(f"{name}: broken link {href}")
    return issues

HTML = {"home": '<a href="/projects">Projects</a><a href="/contact">Contact</a><a href="/cv">CV</a>',
        "projects": '<a href="https://github.com/example">GitHub</a><a href="http://oldsite.example">Old site</a><a href="">More</a><a href="/#top">Top</a>',
        "contact": '<a href="mailto:priya@example.com">Email</a>'}
print(broken_links(HTML))
```

- **The CV link points to a page that does not exist.** The AI removed the page but not the link.
- **The old site link uses HTTP.** Switch to HTTPS or remove it.
- **An empty link leads nowhere.**
- **`/#top` resolves to the home page and `mailto:` links are fine.**

**Complexity.** `site_plan` and `broken_links` are linear in pages and links. `card_score` is constant per card. `style_consistency` is linear in the CSS. `meta_check` is linear in pages.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Adjectives instead of evidence.** "Passionate, innovative developer" is noise. Show problems and outcomes.

**Too many projects.** Twelve tutorial clones hide the two good projects. Curate.

**No call to action.** Visitors who are convinced need an obvious next step. Every page ends with one.

**AI-invented content.** Generated bios and testimonials can be false. Use only your own facts.

**Design drift.** Each AI edit adds a colour or size. Keep a palette and a type scale, and check.

**Big-bang redesigns.** "Make it more modern" rewrites everything. One change at a time, committed.

**Identical titles.** Every page called "Portfolio". Write unique titles and descriptions.

**No sharing image.** Links shared in messages look broken. Add Open Graph tags.

**Broken links after edits.** Pages renamed or removed without updating links. Check links before every launch.

**Heavy screenshots.** Full-resolution images slow the site. Compress and size them.

**A free subdomain forever.** Your own domain looks professional and survives a change of host. Attach one.

**Hiding how you used AI.** Clients ask. Be accurate about your role.

# ---------------------------------------------------------------- Step 1
def site_plan(pages, nav, max_nav=6):
    """Every page earns its place: a purpose, a next step, and a way in."""
    issues = []
    if len(nav) > max_nav:
        issues.append(f"{len(nav)} navigation items; keep it to {max_nav}")
    linked = set(nav) | {t for p in pages.values() for t in p["links"]}
    for name in sorted(pages):
        page = pages[name]
        if not page.get("purpose"):
            issues.append(f"{name}: no stated purpose")
        if not page.get("cta"):
            issues.append(f"{name}: no call to action")
        if name not in linked and name != "home":
            issues.append(f"{name}: orphan page")
    issues += [f"navigation links to missing page {n}" for n in nav if n not in pages]
    return issues


# ---------------------------------------------------------------- Step 2
def card_score(project):
    """Evidence beats adjectives."""
    missing = []
    if len(project.get("problem", "")) < 20:
        missing.append("problem")
    if not project.get("role"):
        missing.append("role")
    if not re.search(r"\d", project.get("outcome", "")):
        missing.append("measurable outcome")
    if not str(project.get("link", "")).startswith("https://"):
        missing.append("https link")
    return round(1 - len(missing) / 4, 2), missing


# ---------------------------------------------------------------- Step 3
def style_consistency(css, max_colours=5, max_sizes=6):
    """Count the drift that repeated AI edits leave behind."""
    colours = sorted({c.lower() for c in COLOUR.findall(css)})
    sizes = sorted(set(SIZE.findall(css)))
    issues = []
    if len(colours) > max_colours:
        issues.append(f"{len(colours)} colours; use a palette of at most {max_colours}")
    if len(sizes) > max_sizes:
        issues.append(f"{len(sizes)} font sizes; use a type scale of at most {max_sizes}")
    return colours, sizes, issues


# ---------------------------------------------------------------- Step 4
def meta_check(pages):
    """Unique, useful titles and descriptions, and a sharing image."""
    issues, titles = [], {}
    for name, meta in pages.items():
        title, description = meta.get("title", ""), meta.get("description", "")
        if not 10 <= len(title) <= 60:
            issues.append(f"{name}: title is {len(title)} characters")
        if not 50 <= len(description) <= 160:
            issues.append(f"{name}: description is {len(description)} characters")
        if not meta.get("og_image"):
            issues.append(f"{name}: no og:image")
        titles.setdefault(title, []).append(name)
    issues += [f"duplicate title on {', '.join(sorted(names))}" for names in titles.values() if len(names) > 1]
    return issues

def broken_links(pages):
    """Every link goes somewhere real, over HTTPS."""
    issues = []
    for name in sorted(pages):
        for href in LINK.findall(pages[name]):
            if not href:
                issues.append(f"{name}: empty link")
            elif href.startswith("http://"):
                issues.append(f"{name}: insecure link {href}")
            elif href.startswith("/"):
                target = href.strip("/").split("#")[0] or "home"
                if target not in pages:
                    issues.append(f"{name}: broken link {href}")
    return issues
