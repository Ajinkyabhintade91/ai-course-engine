# 20 AI Agent Project Ideas

Choosing what to build is often harder than building it. This module offers twenty agent project ideas, grouped by difficulty, each tied to a real business or personal problem, and then gives you the tools to choose: how to cut an idea down to a **minimum viable version** that fits the time you have, how to score ideas against your level and goals, and which **safeguards** each idea needs before it touches real people or real systems. The ideas reuse skills from Units 5 to 11; the point is not to build all twenty, but to pick one or two that fit your direction, Module 12.3.

The ideas are starting points. Adapt them to your niche: "a quote assistant for joinery workshops" is a better project than "a quote assistant".

## 1. First-Principles Mental Model & Intuition

### A pattern book for furniture

Joiners have long used pattern books: collections of designs, from simple stools to complex cabinets, each with the joints and skills it requires. An apprentice picks a design that stretches them a little, builds a simpler version first to test the joints, and adds the carving later. Nobody builds the grandest design in the book as their first piece. This module is a pattern book for agents.

```text
 BEGINNER (7)                    INTERMEDIATE (7)                    ADVANCED (6)
 email triage assistant          quote assistant                     repository coding agent
 meeting notes summariser        support agent with order lookup     multi-agent research report
 FAQ bot over your documents     lead qualifier                      data analysis agent
 invoice data extractor          CV screening assistant              private local document agent
 social post drafter             stock reorder agent                 voice receptionist
 research brief assistant        content repurposing pipeline        procurement negotiation assistant
 study tutor with quizzes        scheduling agent

 choose:   fit = level match + 2 x focus areas covered + income bonus (client-facing)
 scope:    must-haves first, then the cheapest extras, within days x hours
 protect:  actions -> approval | personal data -> DPIA | external messages -> human review | hiring -> bias tests
```

### Agents only where they earn it

Many of these ideas work best as **workflows**, fixed sequences with one or two model steps, rather than open-ended agents. Anthropic's guidance on building agents recommends starting with the simplest solution and adding autonomy only when the task needs it, Module 8.10. Several ideas below say where a workflow is enough.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Beginner ideas

| Idea | Problem it solves | Core skills |
|---|---|---|
| Email triage assistant | Inbox overload | Classification, drafting replies for review, Unit 5 |
| Meeting notes summariser | Lost decisions and actions | Summarisation with structured output |
| FAQ bot over your documents | Repeated questions | Retrieval, Module 8.7, citations |
| Invoice data extractor | Manual data entry | Structured output, validation, Unit 7 |
| Social post drafter | Content consistency | Style prompts, a content workflow, Unit 6 |
| Research brief assistant | Slow background research | Search tools, citation checking, Module 8.15 |
| Study tutor with quizzes | Retention when learning | Question generation, recall practice, Module 12.1 |

Most beginner ideas are workflows: input, one or two model calls, structured output, and a person reviewing the result. They are ideal first portfolio pieces because they are easy to measure: minutes saved, fields extracted correctly, questions answered accurately.

### Intermediate ideas

| Idea | Problem it solves | Core skills |
|---|---|---|

| Lead qualifier | Time wasted on poor-fit leads | CRM lookups, scoring, Module 8.16 |

| Content repurposing pipeline | One piece of content, many formats | Multi-step workflow, Unit 6 |
| Scheduling agent | Back-and-forth over meeting times | Calendar tools, confirmation, Module 8.19 |

Intermediate ideas add **tools**: the agent reads or changes other systems. That brings evaluation, Module 8.12, and safeguards to the fore.

### Advanced ideas

| Idea | Problem it solves | Core skills |
|---|---|---|
| Repository coding agent | Routine code changes | Tool use, tests, sandboxing, Unit 9 |
| Multi-agent research report | Long, multi-source reports | Orchestration, Module 8.9 |
| Data analysis agent | Slow answers to data questions | Code execution in a sandbox, verification |

| Voice receptionist | Missed calls | Speech in and out, tools, handoff |
| Procurement negotiation assistant | Time-consuming supplier negotiation | Drafting, approval gates, strategy |

Advanced ideas combine several capabilities and carry more risk, through code execution, real-time conversation, or external communication.

### Scoping a minimum viable version

A **minimum viable product** is the smallest version that tests whether the idea works for a real user. For an agent project, list its features with estimated hours and mark the must-haves. With a budget of $D$ days at $h$ hours a day, keep the must-haves first, cheapest first, then add optional features in order of cost while they fit:

$$\sum_{\text{kept}} \text{hours} \le D \times h$$

If the must-haves alone do not fit, the scope is too large: extend the time or redefine what "must" means. Everything deferred is a list for version two, and often for an upsell, Module 11.12.

### Scoring fit

A project fits a learner when it matches their level, uses their focus areas, Module 12.1, and serves their goal. A simple score:

$$\text{fit} = L + 2A + G$$

where $L$ is 2 for the learner's level, 1 for one level above, 0 for below, and minus 2 for two levels above; $A$ is the number of the learner's focus areas the project uses; and $G$ is 1 when the goal is income and the project is client-facing, because client-facing work becomes a sellable case study. Ties are broken alphabetically for a stable list.

### Safeguards

Every idea that acts, handles personal data, talks to outsiders, or makes decisions about people needs safeguards before it is used for real:

- **Actions with side effects**, such as sending orders, booking meetings, or running code: human approval before execution, Module 8.11.
- **Personal data**: a data protection review, and for high-risk processing a data protection impact assessment, Module 10.13.
- **External messages**: human review of what is sent to customers or suppliers.
- **Decisions about people**, such as CV screening: testing for bias and fairness, because models can reproduce or amplify unfair patterns in their training data, known as algorithmic bias, and because automated decisions in employment are treated as high-risk in many jurisdictions.

Prompt injection, OWASP's top risk for LLM applications, applies to every agent that reads untrusted text, Module 8.14.

### Complexity

Grouping and safeguards are linear in ideas; scoping sorts features, $O(f \log f)$; recommending sorts ideas by fit, $O(n \log n)$.

Next, scoping a minimum viable version.

```python
def mvp(features, days, hours_per_day=1.5):
    budget, kept, deferred, used = days * hours_per_day, [], [], 0.0
    for name, hours, must in sorted(features, key=lambda f: (not f[2], f[1])):
        if used + hours <= budget:
            kept.append(name)
            used += hours
        else:
            deferred.append(name)
    musts_fit = all(f[0] in kept for f in features if f[2])
    return kept, deferred, round(used, 1), musts_fit

FEATURES = [("price lookup from supplier list", 4, True), ("draft quote document", 3, True),
            ("email the quote", 2, False), ("supplier sync", 6, False), ("follow-up reminders", 3, False)]
print(mvp(FEATURES, 7))
print(mvp(FEATURES, 3))
```

- **Seven days at 1.5 hours: both must-haves plus emailing the quote, 9 hours;** reminders and supplier sync wait for version two.
- **Three days: the must-haves do not both fit,** so the scope is too large for the time; extend it or redefine the must-haves.

Then, scoring fit.

```python
def fit(idea, profile):
    li, lp = LEVELS.index(idea["level"]), LEVELS.index(profile["level"])
    level = 2 if li == lp else (1 if li == lp + 1 else (0 if li < lp else -2))
    areas = len(idea["areas"] & set(profile["focus"]))
    goal = 1 if profile.get("goal") == "income" and idea["client_facing"] else 0
    return level + 2 * areas + goal

SAM = {"level": "intermediate", "focus": ["agents", "business"], "goal": "income"}
print(fit(BY_NAME["Quote assistant"], SAM), fit(BY_NAME["Voice receptionist"], SAM), fit(BY_NAME["Study tutor with quizzes"], SAM))
```

- **The quote assistant scores 7 for Sam:** right level, both focus areas, client-facing.
- **The voice receptionist scores 4:** a stretch level, one focus area, client-facing.
- **The study tutor scores 0:** below Sam's level and outside the focus.

Then, recommending projects.

```python
def recommend(cat, profile, k=3):
    scored = sorted(cat, key=lambda i: (-fit(i, profile), i["name"]))
    return [(i["name"], fit(i, profile)) for i in scored[:k]]

print(recommend(CAT, SAM))
print(recommend(CAT, {"level": "beginner", "focus": ["prompting"], "goal": "learning"}))
```

- **For Sam: the quote assistant, then the lead qualifier and the procurement assistant at 6.**
- **For a beginner focused on prompting: email triage, invoice extraction, and meeting notes,** all workflows that are easy to measure.

Finally, safeguards.

```python
def safeguards(idea):
    out = []
    if idea["side_effects"]:
        out.append("human approval before actions")
    if idea["personal_data"]:
        out.append("data protection review")
    if idea["client_facing"]:
        out.append("human review of external messages")
    if idea["name"] == "CV screening assistant":
        out.append("bias and fairness testing")
    return out

for name in ["Scheduling agent", "CV screening assistant", "Study tutor with quizzes"]:
    print(name, safeguards(BY_NAME[name]))
```

- **The scheduling agent needs all three general safeguards.**
- **The CV screener adds bias and fairness testing,** because it makes decisions about people.
- **The study tutor needs none of these,** which is part of why it is a good beginner project.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Starting with the most impressive idea.** Pick one level above you at most.

**Agents where workflows suffice.** Start simple, Module 8.10.

**No must-have list.** Everything feels essential. Decide before building.

**Ignoring time.** Scope to days times hours.

**Generic projects.** Adapt to a niche.

**No measurement.** Every project needs a number.

**Actions without approval.** Gate anything that changes the world.

**Personal data without review.** Check data protection first.

**Hiring tools without fairness tests.** High risk; test for bias, or avoid.

**Unreviewed external messages.** Review before sending.

**Prompt injection ignored.** Any agent reading untrusted text is exposed.

**Building all twenty.** One or two, done well.

<details>
<summary>View Answer</summary>
