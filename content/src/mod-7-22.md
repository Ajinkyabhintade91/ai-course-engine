# Bonus: 10+ Ready-to-Use Automation Templates

Most automations are variations on a few patterns. A new lead goes to a CRM and someone is told. An invoice email is filed and logged. A weekly report is built and sent. Once a pattern has been built well, rebuilding it from scratch for every client or team is wasted effort, and every rebuild is a new chance to make the old mistakes. **Templates** capture a working automation so it can be reused: in the public libraries of n8n, Make, and Zapier, and in a team's own collection.

This bonus module does two things. It gives a catalogue of twelve templates drawn from this unit, each with its trigger, steps, parameters, and the pitfall it most often hits. And it explains how to make templates safe to reuse: how to import someone else's template without importing their problems, how to parameterise your own so they adapt cleanly, and how to document them so the next person can run them.

## 1. First-Principles Mental Model & Intuition

### A recipe card, not a takeaway

A template is like a recipe card from a friend. It tells you the ingredients and the steps, and it saves you inventing the dish. But it was written for their kitchen: their oven runs hot, they used a different flour, and they left a note in the margin you cannot read. Before cooking, you check the ingredients against your own cupboard, adjust the quantities for your table, and throw away anything that looks off.

Importing an automation template is the same. The steps are the value. Everything tied to the author's environment, their accounts, their data, their assumptions, has to be checked and replaced.

```text
   TEMPLATE FILE (JSON)
      |
      v
   LINT METADATA        name, version, description, trigger, apps, credentials, parameters, owner
      |
      v
   SCAN ON IMPORT       credentials to reconnect, destructive steps, pinned data, active flag, secrets
      |
      v
   FILL PARAMETERS      client-specific values: channel names, thresholds, paths; defaults where sensible
      |
      v
   REMAP CREDENTIALS    the author's credential IDs replaced with this instance's; inactive until tested
      |
      v
   TEST WITH TEST DATA  dry run; check every output
      |
      v
   ACTIVATE AND DOCUMENT
```

### Where templates come from

| Source | What you get | Watch for |
|---|---|---|
| n8n template library | Workflow JSON with nodes and connections | Community templates vary in quality |
| Make templates and blueprints | Scenarios to copy into your account | Connections must be created again |
| Zapier templates | Pre-configured Zaps to turn on | Apps and plan features you may not have |
| Your team's own collection | Workflows built and tested in-house | Undocumented assumptions |

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### What a workflow file contains

An n8n workflow is a JSON document, as Module 7.7 described: nodes with types and parameters, connections between them, settings, and optionally pinned data. n8n's documentation on exporting and importing states two facts that matter for templates. Exported workflow JSON files **include credential names and IDs**, but not the secrets themselves; the IDs are not sensitive, though the names could be, depending on how they were named. And **HTTP Request nodes may contain authentication headers when imported from cURL**, so the documentation advises removing or anonymising such information before sharing.

So a template file carries references to credentials that exist in the author's instance, not yours. After import, every node that needs a credential must be pointed at one that exists in your instance. Make blueprints and Zapier templates behave similarly: the structure travels, the connections do not.

### Import checks

Before an imported template runs, check:

| Check | Why |
|---|---|
| Credentials referenced | Each must be reconnected to one of yours |
| Destructive operations | Delete, clear, or remove steps can destroy your data on the first test |
| Pinned data | The author's sample records, possibly real personal data, travel with the file |
| Active flag | A template should arrive inactive; activate only after testing |
| Hard-coded secrets | Keys typed into node parameters, the scan from Module 7.7's lab |
| Unknown node types | Community nodes you have not installed, or nodes from a newer version |

The lab builds an import report for the first four. A destructive step deserves special care: a "delete rows" step that cleared the author's test sheet will clear yours, and the first test of an imported template is exactly when nobody is expecting it.

### Parameters

A good template separates **what is the same everywhere**, the steps, from **what differs per use**, the parameters: a Slack channel, a score threshold, a webhook path, a spreadsheet ID. Parameters are written as placeholders in the template and filled at install time.

The placeholder syntax must not collide with the workflow tool's own expressions. n8n expressions already use double braces, `{{ $json.score }}`, so the lab's template placeholders use a distinct prefix, `{{param.min_score}}`, which an installer can find and replace without touching n8n's own expressions, even when one sits inside the other:

```text
   template:   ={{ $json.score >= {{param.min_score}} }}
   installed:  ={{ $json.score >= 70 }}
```

Every parameter is documented with a description and, where sensible, a default. Two rules: a parameter without a value and without a default stops the installation with a clear message, and a **secret must never have a default**, since a default secret is a shared secret.

### Credentials remapping

Remapping replaces each credential reference by type: the template's `slackApi` credential with ID 7, named for the author, becomes your `slackApi` credential with your ID. References for which no local credential is mapped are listed, so the installer knows exactly what still needs connecting. The remapped copy should also be made inactive and have its pinned data removed, whatever the original said.

### Versioning

Templates change: a bug is fixed, a step is added, a parameter is renamed. **Semantic versioning**, as defined at semver.org, gives version numbers a meaning: MAJOR.MINOR.PATCH, where a patch fixes bugs without changing behaviour, a minor version adds features compatibly, and a major version makes incompatible changes, such as a renamed parameter. An installation records which version it came from, so when version 2.0.0 renames `min_score`, everyone on 1.x knows an upgrade needs care.

### Documentation

A template that only its author understands is not reusable. Each template carries metadata from which a README can be generated:

| Field | Purpose |
|---|---|
| Name and version | Identify it |
| Description | What it does, in one or two sentences |
| Trigger | What starts it |
| Apps | What it connects |
| Credentials needed | What to connect before running |
| Parameters | Each with a description and default |
| Owner | Who to ask, who maintains it |

Generating the README from the metadata, rather than writing it separately, means documentation cannot drift from the template.

### Complexity

Linting metadata is linear in the number of fields and parameters. Filling parameters walks the whole template once. An import scan and credential remapping are linear in the number of nodes. README generation is linear in the metadata.

First, linting template metadata.

```python
import copy
import re

REQUIRED = ["name", "version", "description", "trigger", "apps", "credentials", "parameters", "owner"]
SEMVER = re.compile(r"^\d+\.\d+\.\d+$")

def lint_template(meta):
    issues = [f"missing:{field}" for field in REQUIRED if not meta.get(field)]
    if meta.get("version") and not SEMVER.match(meta["version"]):
        issues.append("bad_version")
    for parameter in meta.get("parameters", []):
        if "name" not in parameter or "description" not in parameter:
            issues.append("parameter_undocumented")
        elif parameter.get("secret") and "default" in parameter:
            issues.append("secret_default:" + parameter["name"])
    return issues

META = {"name": "New lead to CRM and Slack", "version": "1.2.0",
        "description": "Adds form leads to the CRM and notifies sales about high-scoring ones.",
        "trigger": "webhook", "apps": ["HubSpot", "Slack"], "credentials": ["hubSpotApi", "slackApi"],
        "owner": "ops@agency.example",
        "parameters": [{"name": "slack_channel", "description": "Channel for alerts", "default": "#sales"},
                       {"name": "min_score", "description": "Minimum lead score to alert", "default": 70},
                       {"name": "webhook_path", "description": "URL path for the form webhook"}]}
print(lint_template(META))
print(lint_template({"name": "x", "version": "v2", "parameters": [
    {"name": "api_key", "description": "Service key", "secret": True, "default": "sk-123"}, {"name": "y"}]}))
```

- **Every required field must be present and non-empty.** A template without an owner has nobody to fix it.
- **Versions must be MAJOR.MINOR.PATCH.** "v2" is not a semantic version.
- **Every parameter needs a name and a description.** An undocumented parameter is a guess for the installer.
- **A secret parameter with a default is flagged.** "sk-123" as a default would be shared by every installation.
- **The lead template passes.** Its `webhook_path` has no default on purpose: each client needs its own.

Next, filling parameters.

```python
PLACEHOLDER = re.compile(r"\{\{\s*param\.([a-z_][a-z0-9_]*)\s*\}\}")

def fill(value, params, defaults, missing):
    if isinstance(value, str):
        def replace(match):
            name = match.group(1)
            if name in params:
                return str(params[name])
            if name in defaults:
                return str(defaults[name])
            missing.add(name)
            return match.group(0)
        return PLACEHOLDER.sub(replace, value)
    if isinstance(value, dict):
        return {key: fill(inner, params, defaults, missing) for key, inner in value.items()}
    if isinstance(value, list):
        return [fill(inner, params, defaults, missing) for inner in value]
    return value

def parameterize(template, params, meta):
    defaults = {p["name"]: p["default"] for p in meta.get("parameters", []) if "default" in p}
    missing = set()
    filled = fill(copy.deepcopy(template), params, defaults, missing)
    if missing:
        raise ValueError("missing parameters: " + ", ".join(sorted(missing)))
    return filled

WORKFLOW = {"name": "New lead to CRM and Slack", "active": True, "nodes": [
    {"name": "Lead form", "type": "n8n-nodes-base.webhook", "parameters": {"path": "{{param.webhook_path}}"}},
    {"name": "Create contact", "type": "n8n-nodes-base.hubspot", "parameters": {"operation": "upsert"},
     "credentials": {"hubSpotApi": {"id": "12", "name": "HubSpot (template author)"}}},
    {"name": "Score filter", "type": "n8n-nodes-base.if", "parameters": {"conditions": "={{ $json.score >= {{param.min_score}} }}"}},
    {"name": "Notify", "type": "n8n-nodes-base.slack", "parameters": {"channel": "{{param.slack_channel}}", "text": "New lead"},
     "credentials": {"slackApi": {"id": "7", "name": "Slack (template author)"}}},
    {"name": "Clean old", "type": "n8n-nodes-base.googleSheets", "parameters": {"operation": "delete"}}],
    "pinData": {"Lead form": [{"json": {"email": "real.person@example.com"}}]}}

filled = parameterize(WORKFLOW, {"webhook_path": "client-a-leads"}, META)
print(filled["nodes"][0]["parameters"], filled["nodes"][2]["parameters"], filled["nodes"][3]["parameters"]["channel"])
try:
    parameterize(WORKFLOW, {}, META)
except ValueError as error:
    print(error)
```

- **Placeholders use the `param.` prefix.** They are found and replaced without touching n8n's own `{{ $json.score }}` expression around them.
- **Given values win, then defaults.** The webhook path is the client's; the channel and threshold use the defaults "#sales" and 70.
- **The template is copied first.** Filling never changes the original, which will be installed again for the next client.
- **A placeholder with no value and no default stops the install.** Without a webhook path, the error names exactly what is missing.
- **Non-string values pass through unchanged.** Numbers and booleans in the template are not touched.

Then, scanning the import and remapping credentials.

```python
DESTRUCTIVE = {"delete", "remove", "clear", "deleteAll", "truncate"}

def import_report(workflow, local_credentials):
    report = {"credentials_to_connect": [], "destructive_nodes": [],
              "pinned_data": sorted(name for name, rows in (workflow.get("pinData") or {}).items() if rows),
              "active": bool(workflow.get("active"))}
    for node in workflow.get("nodes", []):
        for credential_type, reference in (node.get("credentials") or {}).items():
            if reference.get("id") not in local_credentials.get(credential_type, {}):
                report["credentials_to_connect"].append((node["name"], credential_type))
        if node.get("parameters", {}).get("operation") in DESTRUCTIVE:
            report["destructive_nodes"].append(node["name"])
    return report

def remap_credentials(workflow, mapping):
    copy_of = copy.deepcopy(workflow)
    unmapped = []
    for node in copy_of.get("nodes", []):
        for credential_type in (node.get("credentials") or {}):
            if credential_type in mapping:
                node["credentials"][credential_type] = {"id": mapping[credential_type][0], "name": mapping[credential_type][1]}
            else:
                unmapped.append((node["name"], credential_type))
    copy_of["active"] = False
    copy_of["pinData"] = {}
    return copy_of, unmapped

LOCAL = {"slackApi": {"31": "Slack (agency)"}, "hubSpotApi": {"44": "HubSpot (client A)"}}
print(import_report(WORKFLOW, LOCAL))
remapped, unmapped = remap_credentials(WORKFLOW, {"slackApi": ("31", "Slack (agency)")})
print(remapped["nodes"][3]["credentials"], unmapped, remapped["active"], remapped["pinData"])
```

- **Both credentials need connecting.** The template refers to IDs 12 and 7 in the author's instance; this instance has HubSpot 44 and Slack 31.
- **"Clean old" is flagged as destructive.** A delete operation in an unfamiliar template is the first thing to inspect.
- **Pinned data on "Lead form" is reported.** It holds what looks like a real person's email address.
- **The template arrived active.** The report says so, and the remapped copy is switched off.
- **Remapping replaces Slack and lists HubSpot as still unmapped.** The installer knows exactly one connection remains.
- **The original is unchanged.** Remapping works on a copy, so the template stays reusable.

Finally, generating the README.

```python
def render_readme(meta):
    lines = [f"{meta['name']} (version {meta['version']})", "", meta["description"], "",
             f"Trigger: {meta['trigger']}", f"Apps: {', '.join(meta['apps'])}",
             f"Credentials needed: {', '.join(meta['credentials'])}", "", "Parameters:"]
    for parameter in meta["parameters"]:
        default = f" (default: {parameter['default']})" if "default" in parameter else " (required)"
        lines.append(f"- {parameter['name']}: {parameter['description']}{default}")
    lines += ["", f"Owner: {meta['owner']}"]
    return "\n".join(lines)

print(render_readme(META))
```

- **The README is built from the metadata.** When a parameter is added to the metadata, the documentation updates with it.
- **Parameters show their default, or say they are required.** `webhook_path` is marked required, telling the installer what they must provide.
- **The owner is listed last.** The person to ask is always part of the document.

**Complexity.** `lint_template` and `render_readme` are linear in the metadata. `parameterize` is linear in the template's size. `import_report` and `remap_credentials` are linear in the nodes.

### Installing a template: the checklist

```text
1  READ        metadata and README; does it do what you need?
2  SCAN        import report: credentials, destructive steps, pinned data, active flag; then secrets and node types by eye
3  FILL        parameters for this client; nothing missing
4  REMAP       credentials to this instance; unmapped list empty
5  CLEAN       pinned data removed; workflow inactive
6  TEST        dry run with test data, destructive steps pointed at a copy
7  ACTIVATE    then watch the first real runs
8  RECORD      template name and version installed, date, client, installer
```

### Writing your own templates

| Practice | Why |
|---|---|
| One template, one job | Small templates combine; giant ones break |
| Parameters for everything client-specific | No hand edits after install |
| No secrets, no pinned data, inactive | Safe to share by construction |
| Semantic versions and a change log | Upgrades are predictable |
| README generated from metadata | Documentation never drifts |
| A test fixture with fake data | Every install can be tested the same way |

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Importing and running immediately.** A template that deletes rows deleted the author's test rows; it will delete yours. Scan first.

**Credentials that look connected.** A dropdown showing a credential name from the author's instance is not your credential. Reconnect each one.

**Pinned personal data.** Sample records pinned by the author travel with the file. Remove them on import.

**Templates that arrive active.** A webhook template that starts receiving traffic before it is configured makes a mess. Import inactive.

**Secrets in HTTP nodes.** Templates built from cURL can contain the author's tokens in headers. Remove them and rotate if you are the author.

**Placeholder collisions.** Using `{{ }}` for your own parameters in n8n confuses them with expressions. Use a distinct prefix.

**Unknown community nodes.** A template built with a community node fails to import cleanly without it. Check node types before installing.

**Version drift.** Templates built for an older tool version may use nodes or options that changed. Note the version they were built on.

**Template quality varies.** Public libraries include excellent and broken templates side by side. Read before trusting.

**No owner.** An unowned template is never updated when an API changes. Every template needs one.

**Copy-paste forks.** Ten slightly different copies of one template become ten maintenance problems. Parameterise instead of forking.

**Undocumented assumptions.** "Assumes the sheet has these columns" belongs in the README. Write it down.

**Question 2.** A team's template uses `{{ $json.channel }}` in one place and its own placeholder `{{ channel }}` in another, filled by a simple text replacement of `{{ channel }}`. Explain what can go wrong, and how the lab's placeholder design avoids it. Then fill `={{ $json.total > {{param.limit}} }}` with a default `limit` of 500.

<details>
<summary>View Answer</summary>

Using the same double-brace syntax for two different things makes the template ambiguous. A replacement aimed at the team's `{{ channel }}` might also match spacing variations or nearby expressions, and a more general replacement, for example any `{{ name }}`, could rewrite n8n's own expressions, breaking the workflow in ways that only show up at run time. Conversely, a reader cannot tell which double braces are n8n expressions evaluated per item and which are install-time parameters. The lab's design gives install-time parameters a distinct prefix, `{{param.name}}`, and a pattern that matches only that form, so n8n's expressions such as `{{ $json.channel }}` are never touched, and a parameter can even sit inside an expression. Filling `={{ $json.total > {{param.limit}} }}` with the default 500 gives `={{ $json.total > 500 }}`: the inner placeholder is replaced, and the outer n8n expression is left intact to be evaluated for each item when the workflow runs.

Standard library only. No network calls. Complete the TODO in each step, then press "Run & Verify Step".

import copy

REQUIRED = ["name", "version", "description", "trigger", "apps", "credentials", "parameters", "owner"]
SEMVER = re.compile(r"^\d+\.\d+\.\d+$")

# ---------------------------------------------------------------- Step 1
def lint_template(meta):
    """A template nobody can install or maintain is not reusable."""
    issues = [f"missing:{field}" for field in REQUIRED if not meta.get(field)]
    if meta.get("version") and not SEMVER.match(meta["version"]):
        issues.append("bad_version")
    for parameter in meta.get("parameters", []):
        if "name" not in parameter or "description" not in parameter:
            issues.append("parameter_undocumented")
        elif parameter.get("secret") and "default" in parameter:
            issues.append("secret_default:" + parameter["name"])
    return issues


# ---------------------------------------------------------------- Step 2
def fill(value, params, defaults, missing):
    """Walk strings, dicts, and lists, replacing only param. placeholders."""
    if isinstance(value, str):
        def replace(match):
            name = match.group(1)
            if name in params:
                return str(params[name])
            if name in defaults:
                return str(defaults[name])
            missing.add(name)
            return match.group(0)
        return PLACEHOLDER.sub(replace, value)
    if isinstance(value, dict):
        return {key: fill(inner, params, defaults, missing) for key, inner in value.items()}
    if isinstance(value, list):
        return [fill(inner, params, defaults, missing) for inner in value]
    return value


def parameterize(template, params, meta):
    """Given values win, then defaults; anything still missing stops the install."""
    defaults = {p["name"]: p["default"] for p in meta.get("parameters", []) if "default" in p}
    missing = set()
    filled = fill(copy.deepcopy(template), params, defaults, missing)
    if missing:
        raise ValueError("missing parameters: " + ", ".join(sorted(missing)))
    return filled


# ---------------------------------------------------------------- Step 3
def import_report(workflow, local_credentials):
    """What must be checked before an imported template runs."""
    report = {"credentials_to_connect": [], "destructive_nodes": [],
              "pinned_data": sorted(name for name, rows in (workflow.get("pinData") or {}).items() if rows),
              "active": bool(workflow.get("active"))}
    for node in workflow.get("nodes", []):
        for credential_type, reference in (node.get("credentials") or {}).items():
            if reference.get("id") not in local_credentials.get(credential_type, {}):
                report["credentials_to_connect"].append((node["name"], credential_type))
        if node.get("parameters", {}).get("operation") in DESTRUCTIVE:
            report["destructive_nodes"].append(node["name"])
    return report


# ---------------------------------------------------------------- Step 4
def remap_credentials(workflow, mapping):
    """The author's credential references replaced with this instance's; inactive and unpinned."""
    copy_of = copy.deepcopy(workflow)
    unmapped = []
    for node in copy_of.get("nodes", []):
        for credential_type in (node.get("credentials") or {}):
            if credential_type in mapping:
                node["credentials"][credential_type] = {"id": mapping[credential_type][0], "name": mapping[credential_type][1]}
            else:
                unmapped.append((node["name"], credential_type))
    copy_of["active"] = False
    copy_of["pinData"] = {}
    return copy_of, unmapped


# ---------------------------------------------------------------- Step 5
def render_readme(meta):
    """Documentation generated from metadata cannot drift from the template."""
    lines = [f"{meta['name']} (version {meta['version']})", "", meta["description"], "",
             f"Trigger: {meta['trigger']}", f"Apps: {', '.join(meta['apps'])}",
             f"Credentials needed: {', '.join(meta['credentials'])}", "", "Parameters:"]
    for parameter in meta["parameters"]:
        default = f" (default: {parameter['default']})" if "default" in parameter else " (required)"
        lines.append(f"- {parameter['name']}: {parameter['description']}{default}")
    lines += ["", f"Owner: {meta['owner']}"]
    return "\n".join(lines)
