# Project 5: Content to Content Automation

Creating a substantial piece of content, an hour-long podcast, a webinar, a long article, takes a great deal of effort. Most of its value is then left unused, because it exists in one format on one platform. **Repurposing** turns one long piece into many smaller ones: a blog post, a newsletter section, a dozen social posts, short video clips, captions, and quotes. Unit 6 covered creating each of these formats; Module 6.12 built a content pipeline. This project automates the specific path from one long recording to many derived assets, with a rule that runs through the whole design: **the derived content must be faithful to the original.** A repurposing pipeline that misquotes a guest, or attributes to the host something they never said, does real damage, and language models are very good at producing plausible words nobody said.

## 1. First-Principles Mental Model & Intuition

### A newspaper subeditor with the tape

Imagine a newspaper subeditor given the recording of a long interview. They transcribe it, mark the best passages, write a summary, pick quotes for the headline and the pull-out boxes, and draft short pieces for different sections. A good subeditor checks every quote against the tape, word for word, and notes where in the recording it came from. A bad one paraphrases from memory and puts quotation marks around it.

The pipeline is the good subeditor, with the tape always to hand.

```text
   LONG-FORM SOURCE        podcast audio, webinar video, long article
        |
        v
   TRANSCRIBE              speech-to-text -> segments with start and end times (SRT or VTT)
        |
        v
   CHUNK                   group segments into passages, with overlap, keeping timestamps
        |
        v
   SUMMARISE               per chunk, then combine (map, then reduce)
        |
        v
   DERIVE                  blog post, newsletter, social posts, pull quotes, clip suggestions
        |
        v
   VERIFY                  every quote found word for word in the transcript, with its timestamp
        |
        v
   REVIEW QUEUE            an editor approves, edits, or rejects each asset
        |
        v
   PUBLISH / SCHEDULE      plus captions (WebVTT) uploaded with the video
```

### What each asset needs

| Asset | Built from | Constraint |
|---|---|---|
| Show notes and blog post | The combined summary | Faithful, structured, links to timestamps |
| Social posts | Key points from chunks | Platform length limits, Module 7.21 |
| Pull quotes | Exact transcript text | Verbatim, attributed, with a timestamp |
| Clip suggestions | Segments with strong single ideas | Start and end times from the transcript |
| Captions | The transcript itself | Correct format and timing |

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Transcription

Modern speech-to-text models, such as OpenAI's Whisper, described in the 2022 paper "Robust Speech Recognition via Large-Scale Weak Supervision", turn audio into text with timestamps. They are trained on very large amounts of audio and handle accents and background noise well, but they make characteristic errors: misheard names and technical terms, and occasionally fluent text during silence or music that nobody said. Two practices help: give the transcription step a vocabulary prompt or glossary of names and terms where the service allows it, and have a person check names in anything published.

Transcription services usually charge per minute of audio. At an illustrative rate of USD 0.006 per minute, an hour costs 60 times 0.006, USD 0.36. Rates differ between services and change, so the lab treats the rate as an input.

### Transcript formats

Transcripts arrive as subtitle files, a sequence of **cues**, each with a start time, an end time, and text.

```text
   SRT (SubRip)                                   WebVTT
   1                                              WEBVTT
   00:00:00,000 --> 00:00:04,200
   Welcome back to the Workshop Hour, I'm Dana.  00:00:00.000 --> 00:00:04.200
                                                  Welcome back to the Workshop Hour, I'm Dana.
   2
   00:00:04,200 --> 00:00:09,800                  00:00:04.200 --> 00:00:09.800
   Today we're talking about sharpening chisels   Today we're talking about sharpening chisels
   properly.                                      properly.
```

| Feature | SRT | WebVTT |
|---|---|---|
| Header | None | A first line reading `WEBVTT` |
| Cue number | Required | Optional |
| Millisecond separator | Comma | Full stop |
| Hours | Always written | Optional, required when non-zero, per the W3C specification |
| Used by | Many editors and players | HTML5 video on the web |

Converting between them is mechanical, but the separator difference is a classic cause of captions that silently fail to load.

### Chunking with overlap

A one-hour transcript is roughly 9,000 words, longer than is comfortable to summarise in one pass and long enough that details in the middle get less attention. The standard approach is **map-reduce summarisation**: split the transcript into chunks, summarise each chunk (map), then summarise the summaries (reduce).

Chunks are built from whole segments, so every chunk keeps a start and end time and can be traced back to the recording. Adjacent chunks **overlap** by a segment, so an idea spanning a boundary appears complete in at least one chunk. The rule in the lab: add segments until the next would exceed the word limit; start the next chunk with the last segment of the previous one if it fits alongside the new segment, otherwise start fresh. No chunk then exceeds the limit unless a single segment does.

With $W$ words, a limit of $L$ words per chunk, and overlap, the number of chunks is a little more than $W / L$. For 9,000 words and chunks of 800, about 12 chunks, each a separate model call in the map step, plus one reduce call.

### Faithful derivation

Prompts for each derived asset follow the grounding pattern of Module 7.18: the model receives the relevant chunks and must use only what they say. For quotes, the requirement is stricter: a **pull quote must appear word for word in the transcript**. The model may choose which sentences to quote, but not reword them.

Verification is mechanical. Normalise both the quote and the transcript the same way: lower case, punctuation removed, apostrophes kept so that "I'm" is not confused with "Im", spaces collapsed. Then search for the quote within a single segment, then within windows of two and three consecutive segments, since a sentence often spans two cues. A quote that is found is published with its timestamp, which doubles as a link to that moment in the recording. A quote that is not found is rejected, however good it sounds. "A sharp chisel is twice as safe" is not what the host said, even if it is what they meant.

### Cost per episode

The whole pipeline's cost per episode is the sum of its stages:

$$\text{cost} = m \cdot r + c \cdot \frac{t^{\text{in}}_{c} p_{\text{in}} + t^{\text{out}}_{c} p_{\text{out}}}{10^6} + a \cdot \frac{t^{\text{in}}_{a} p_{\text{in}} + t^{\text{out}}_{a} p_{\text{out}}}{10^6}$$

for $m$ minutes of audio at rate $r$ per minute, $c$ chunk summaries, and $a$ derived assets, each with their own input and output token counts, at per-million prices $p_{\text{in}}$ and $p_{\text{out}}$. For an hour-long episode with 12 chunk summaries of 1,500 tokens in and 300 out, and 10 assets of 3,000 in and 400 out, at the mid-sized model rates used in Module 7.10, the total is about USD 0.53: USD 0.36 for transcription, about 0.07 for summaries, and 0.10 for assets, plus about a cent for the single combining call. The money is trivial; the editor's time reviewing the output is the real cost, which is why verification that removes misquotes before review is worth building.

### Review and publishing

Every derived asset goes to a review queue, the pattern from Modules 6.12 and 7.16, where an editor approves, edits, or rejects it. Assets carry their provenance: which chunks they were built from and, for quotes, the timestamps. Publishing and scheduling, and the platform rules that apply, are the subject of Module 7.21.

### Complexity

Parsing a transcript is linear in its length. Chunking is linear in the number of segments. Quote search is linear in the number of segments times the window size, plus the cost of substring matching. Cost estimation is constant. Converting to WebVTT is linear in the segments.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, parsing an SRT transcript.

```python
import re

SRT = """1
00:00:00,000 --> 00:00:04,200
Welcome back to the Workshop Hour, I'm Dana.

2
00:00:04,200 --> 00:00:09,800
Today we're talking about sharpening chisels properly.

3
00:00:09,800 --> 00:00:15,500
The biggest mistake people make is rushing the coarse stone.

4
00:00:15,500 --> 00:00:21,000
Spend most of your time there and the fine stones take seconds.

5
00:01:02,250 --> 00:01:07,900
A sharp chisel is safer than a blunt one, because you push less.
"""

STAMP = re.compile(r"(\d\d):(\d\d):(\d\d)[,.](\d\d\d)")

def seconds(stamp):
    match = STAMP.fullmatch(stamp.strip())
    if not match:
        raise ValueError("bad timestamp: " + stamp)
    hours, minutes, secs, millis = map(int, match.groups())
    return hours * 3600 + minutes * 60 + secs + millis / 1000

def parse_srt(text):
    segments = []
    for block in re.split(r"\n\s*\n", text.strip()):
        lines = block.strip().splitlines()
        if len(lines) < 3:
            continue
        start, end = [part.strip() for part in lines[1].split("-->")]
        segments.append({"index": int(lines[0]), "start": seconds(start), "end": seconds(end),
                         "text": " ".join(line.strip() for line in lines[2:])})
    return segments

SEGMENTS = parse_srt(SRT)
print(SEGMENTS[0])
print([segment["start"] for segment in SEGMENTS])
```

- **Cues are separated by blank lines.** Each block has a number, a timing line, and one or more text lines.
- **Timestamps become seconds.** `00:01:02,250` is 62.25 seconds. The pattern accepts a comma or a full stop, so the same function reads WebVTT times.
- **Multi-line cue text is joined with spaces.** A cue split over two lines is one sentence.
- **Malformed timestamps raise an error.** A transcript with broken timings should stop the pipeline, not produce clips at the wrong moments.
- **Blocks with fewer than three lines are skipped.** Stray blank cues are common in exported files.

Next, chunking with overlap.

```python
def chunk_segments(segments, max_words=20, overlap=1):
    chunks, current = [], []
    words = lambda group: sum(len(segment["text"].split()) for segment in group)
    for segment in segments:
        size = len(segment["text"].split())
        if current and words(current) + size > max_words:
            chunks.append(current)
            carry = current[-overlap:] if overlap else []
            current = carry if words(carry) + size <= max_words else []
        current.append(segment)
    if current:
        chunks.append(current)
    return [{"start": group[0]["start"], "end": group[-1]["end"], "indices": [s["index"] for s in group],
             "text": " ".join(s["text"] for s in group)} for group in chunks]

for piece in chunk_segments(SEGMENTS):
    print(piece["indices"], piece["start"], piece["end"], len(piece["text"].split()))
print([piece["indices"] for piece in chunk_segments(SEGMENTS, max_words=30)])
```

- **Segments are added until the next would exceed the limit.** The five segments have 8, 7, 10, 12, and 13 words.
- **With a 20-word limit, the chunks are segments 1 and 2, then 2 and 3, then 4, then 5.** Segment 2 is carried over as overlap. Segment 3 cannot be carried into the next chunk, because 10 plus 12 words would exceed 20, so that chunk starts fresh.
- **Every chunk keeps its start time, end time, and segment numbers.** A summary built from chunk 2 can link to 4.2 seconds into the episode.
- **With a 30-word limit, the chunks are 1 to 3, then 3 and 4, then 4 and 5.** Larger chunks, each overlapping its neighbour by one segment.
- **The demonstration limits are tiny so the behaviour is visible.** A real hour-long transcript would use limits of several hundred words.

Then, verifying quotes.

```python
def normalise(text):
    text = text.lower().replace("\u2019", "'")
    return re.sub(r"\s+", " ", re.sub(r"[^\w\s']", " ", text)).strip()

def find_quote(quote, segments, max_span=3):
    target = normalise(quote)
    if not target:
        return None
    for size in range(1, max_span + 1):
        for first in range(len(segments) - size + 1):
            window = " ".join(normalise(s["text"]) for s in segments[first:first + size])
            if target in window:
                return {"start": segments[first]["start"], "end": segments[first + size - 1]["end"],
                        "indices": [s["index"] for s in segments[first:first + size]]}
    return None

print(find_quote("A sharp chisel is safer than a blunt one", SEGMENTS))
print(find_quote("The biggest mistake people make is rushing the coarse stone. Spend most of your time there", SEGMENTS))
print(find_quote("A sharp chisel is twice as safe", SEGMENTS))
print(find_quote("IM DANA", SEGMENTS))
```

- **Normalisation ignores case, punctuation, and spacing, but keeps apostrophes.** Curly apostrophes become straight ones first, since transcripts and models disagree about them.
- **The smallest window is searched first.** A quote inside one segment is found there, so the timestamp is as precise as possible.
- **The chisel quote is found in segment 5, at 62.25 seconds.** It can be published with a link to that moment.
- **The two-sentence quote spans segments 3 and 4, 9.8 to 21.0 seconds.** Sentences crossing cue boundaries are handled by the wider windows.
- **The paraphrase "twice as safe" is not found and is rejected.** The host never said it.
- **"IM DANA" is not found.** Without its apostrophe, "Im" is a different word from "I'm"; the check is strict by design.

Finally, cost and captions.

```python
def episode_cost(minutes, rate_per_minute, chunks, chunk_in, chunk_out, assets, asset_in, asset_out, price_in, price_out):
    transcription = minutes * rate_per_minute
    summaries = chunks * (chunk_in * price_in + chunk_out * price_out) / 1_000_000
    writing = assets * (asset_in * price_in + asset_out * price_out) / 1_000_000
    return round(transcription, 4), round(summaries, 4), round(writing, 4), round(transcription + summaries + writing, 4)

print(episode_cost(60, 0.006, 12, 1500, 300, 10, 3000, 400, 2.0, 10.0))

def vtt_time(total):
    millis = round(total * 1000)
    hours, millis = divmod(millis, 3_600_000)
    minutes, millis = divmod(millis, 60_000)
    secs, millis = divmod(millis, 1000)
    return f"{hours:02d}:{minutes:02d}:{secs:02d}.{millis:03d}"

def to_vtt(segments):
    lines = ["WEBVTT", ""]
    for segment in segments:
        lines += [f"{vtt_time(segment['start'])} --> {vtt_time(segment['end'])}", segment["text"], ""]
    return "\n".join(lines)

print(to_vtt(SEGMENTS[:2]))
print(vtt_time(3725.5))
```

- **Transcription costs USD 0.36 for 60 minutes at the illustrative rate.**
- **Twelve chunk summaries cost USD 0.072, and ten assets USD 0.10.** At USD 2 and 10 per million input and output tokens.
- **The episode costs about USD 0.53, before the single combining call, which adds about a cent.** Model costs are small next to the editor's time.
- **`vtt_time` converts seconds to `HH:MM:SS.mmm`, with a full stop.** 3,725.5 seconds is `01:02:05.500`. Hours are always written, which the specification permits.
- **`to_vtt` writes the header, a blank line, then each cue's timing, text, and a blank line.** Cue numbers are omitted, since WebVTT does not require them.
- **Milliseconds are computed by rounding once.** Converting floating-point seconds piece by piece can produce times like `00:00:04.199`.

**Complexity.** `parse_srt` is linear in the text. `chunk_segments` recounts words in the current chunk, which is small, so it is effectively linear. `find_quote` is linear in the segments times the window size. `episode_cost` is constant. `to_vtt` is linear in the segments.

### Common errors and the stage that catches them

| Error | Caught by |
|---|---|
| Misheard name or term | Glossary at transcription; editor review |
| Text invented during silence | Transcript review; quotes must be verbatim |
| Paraphrase presented as a quote | Quote verification |
| Summary missing a middle section | Chunked map-reduce instead of one long prompt |
| Captions failing to load | Correct WebVTT header and full-stop milliseconds |
| Clip cut mid-sentence | Clip times taken from segment boundaries |

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Quotes the guest never said.** A model "tidying" a quote changes its meaning. Verify every quote verbatim.

**Misheard names.** Transcription models struggle with names and jargon. Use a glossary and check names before publishing.

**Silence turned into text.** Speech-to-text can produce words over music or silence. Skim the transcript near intros and outros.

**One giant prompt for the whole episode.** Details in the middle are lost. Chunk, summarise, combine.

**Chunks cut mid-sentence.** Fixed character chunks split ideas. Chunk on segment boundaries with overlap.

**Losing timestamps.** Assets without timestamps cannot be checked or linked. Carry start and end times through every stage.

**Comma versus full stop.** SRT uses commas in times, WebVTT full stops. A wrong separator makes captions fail silently.

**Repurposing without adapting.** The same paragraph pasted on every platform performs badly everywhere. Each format needs its own shape, as Unit 6 showed.

**Auto-publishing derived content.** Faithfulness needs a person's check. Keep a review queue.

**Over-producing.** Thirty posts from one episode dilute attention. Choose the best few ideas.

**Ignoring rights.** Guests may have agreed to a podcast, not to clips in adverts. Check permissions for each use.

**No record of sources.** When a guest disputes a quote, the timestamp settles it in seconds.

    {"index": 5, "start": 62.25, "end": 67.9, "text": "A sharp chisel is safer than a blunt one, because you push less."}]


def normalise(text):
    """Given: lower case, curly apostrophes straightened, punctuation except apostrophes removed, spaces collapsed."""
    text = text.lower().replace("\u2019", "'")
    return re.sub(r"\s+", " ", re.sub(r"[^\w\s']", " ", text)).strip()


# ---------------------------------------------------------------- Step 1
def seconds(stamp):
    """A comma or a full stop before the milliseconds, so SRT and WebVTT both parse."""
    match = STAMP.fullmatch(stamp.strip())
    if not match:
        raise ValueError("bad timestamp: " + stamp)
    hours, minutes, secs, millis = map(int, match.groups())
    return hours * 3600 + minutes * 60 + secs + millis / 1000


def parse_srt(text):
    """Cues: number, timing line, text lines; blank lines between."""
    segments = []
    for block in re.split(r"\n\s*\n", text.strip()):
        lines = block.strip().splitlines()
        if len(lines) < 3:
            continue
        start, end = [part.strip() for part in lines[1].split("-->")]
        segments.append({"index": int(lines[0]), "start": seconds(start), "end": seconds(end),
                         "text": " ".join(line.strip() for line in lines[2:])})
    return segments


# ---------------------------------------------------------------- Step 2
def chunk_segments(segments, max_words=20, overlap=1):
    """Whole segments, overlap where it fits, timestamps kept for every chunk."""
    chunks, current = [], []
    words = lambda group: sum(len(segment["text"].split()) for segment in group)
    for segment in segments:
        size = len(segment["text"].split())
        if current and words(current) + size > max_words:
            chunks.append(current)
            carry = current[-overlap:] if overlap else []
            current = carry if words(carry) + size <= max_words else []
        current.append(segment)
    if current:
        chunks.append(current)
    return [{"start": group[0]["start"], "end": group[-1]["end"], "indices": [s["index"] for s in group],
             "text": " ".join(s["text"] for s in group)} for group in chunks]


# ---------------------------------------------------------------- Step 3
def find_quote(quote, segments, max_span=3):
    """A pull quote must be verbatim; the smallest window gives the most precise timestamp."""
    target = normalise(quote)
    if not target:
        return None
    for size in range(1, max_span + 1):
        for first in range(len(segments) - size + 1):
            window = " ".join(normalise(s["text"]) for s in segments[first:first + size])
            if target in window:
                return {"start": segments[first]["start"], "end": segments[first + size - 1]["end"],
                        "indices": [s["index"] for s in segments[first:first + size]]}
    return None


# ---------------------------------------------------------------- Step 4
def episode_cost(minutes, rate_per_minute, chunks, chunk_in, chunk_out, assets, asset_in, asset_out, price_in, price_out):
    """Transcription plus map-reduce summaries plus asset writing."""
    transcription = minutes * rate_per_minute
    summaries = chunks * (chunk_in * price_in + chunk_out * price_out) / 1_000_000
    writing = assets * (asset_in * price_in + asset_out * price_out) / 1_000_000
    return round(transcription, 4), round(summaries, 4), round(writing, 4), round(transcription + summaries + writing, 4)


# ---------------------------------------------------------------- Step 5
def vtt_time(total):
    """WebVTT uses a full stop before the milliseconds, never a comma."""
    millis = round(total * 1000)
    hours, millis = divmod(millis, 3_600_000)
    minutes, millis = divmod(millis, 60_000)
    secs, millis = divmod(millis, 1000)
    return f"{hours:02d}:{minutes:02d}:{secs:02d}.{millis:03d}"


def to_vtt(segments):
    """Header, blank line, then timing, text, and a blank line per cue."""
    lines = ["WEBVTT", ""]
    for segment in segments:
        lines += [f"{vtt_time(segment['start'])} --> {vtt_time(segment['end'])}", segment["text"], ""]
    return "\n".join(lines)
