# Gemini: Overview and Setup

Gemini is Google's family of AI models and the assistant built on them. If you have worked through the ChatGPT and Claude units, the foundations are already familiar: a model that predicts text, wrapped in a product that supplies context and tools. This chapter covers what is distinctive about Gemini. Three things stand out. Its models were built from the start to take images, audio, and video as well as text. Its context window has long been among the largest available. And it is tied into Google's search engine and Google's office applications.

Product details here are from Google's documentation in November 2026. Google revises its lineup more often than any other major provider, and model names in particular will have changed by the time you read this. The chapter is organised around the things that last: tiers, surfaces, and how to reason about tokens of different kinds.

## 1. First-Principles Mental Model & Intuition

### A kitchen with three stations

Think of a restaurant kitchen. The head chef handles the difficult dishes: slow, expensive, and the best in the building. The line cooks turn out most of the orders quickly and well. The prep cook does simple, repetitive work in bulk at the lowest cost.

Every major model family is arranged this way, and Gemini has traditionally named its stations plainly.

| Station | Traditional Gemini name | What it is for |
|---|---|---|
| Head chef | **Pro** | The hardest reasoning, complex code, long analytical work |
| Line cook | **Flash** | Everyday work where speed matters. The default for most tasks |
| Prep cook | **Flash-Lite** | High-volume, simple jobs at the lowest price |

This is the same triage you met for OpenAI's models in Module 2.2 and Claude's in Module 3.1. The names change with each generation. The newest Gemini generation at the time of writing uses a different naming scheme, described in Section 2. The three stations remain.

### One family, several front doors

The same models are reached through different entrances, built for different people.

```text
                          THE GEMINI MODELS
              frontier          fast            lightweight
                  |               |                  |
   ---------------+---------------+------------------+---------------
   |               |                  |                    |
+--------+   +-----------+   +----------------+   +----------------+
| Gemini |   | Google AI |   | Vertex AI and  |   | Gemini inside  |
| app    |   | Studio    |   | Gemini         |   | Gmail, Docs,   |
|        |   |           |   | Enterprise     |   | Sheets, Meet   |
+--------+   +-----------+   +----------------+   +----------------+
 everyone     developers      organisations        people already
 chatting     trying things   building with        working in
              and getting     contracts and        Google's apps
              an API key      controls
```

As with Claude in Module 3.1, two questions come up for every task: which model, and through which door. A further question matters more for Gemini than for the others: **what kind of input?** Because Gemini accepts audio and video directly, a meeting recording can be given to it as it is, without a transcript.

### Three strengths to remember

**It takes in more than text.** A photograph, a PDF with charts, an hour of audio, a screen recording: all can be given to the model directly. Module 1.5 called this multimodality.

**The desk is very large.** A context window of about a million tokens holds several books at once. Google's documentation gives the examples of roughly eight average novels or the transcripts of more than two hundred podcast episodes.

**It can look things up.** With **grounding**, the model runs Google searches while answering and cites what it found. This addresses the knowledge cut-off described in Module 1.10.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### The model family

At the time of writing, Google's model page lists a new generation, Gemini 4, alongside the Gemini 3 line.

| Model | Station | Described as |
|---|---|---|
| Gemini 4 Carbon | Frontier | The strongest reasoning: complex software engineering, scientific and multimodal knowledge work |
| Gemini 4 Argon | Frontier, more efficient | Frontier-level reasoning that is faster and uses fewer tokens per turn |
| Gemini 4 Hydrogen | Fast | Fast and efficient, for everyday coding and agent work |
| Gemini 3.8 Flash and 3.6 Flash | Fast, previous generation | Balanced speed and multimodal ability for general tasks |
| Gemini 3.5 Flash-Lite | Lightweight | The fastest and cheapest of its line |

With Gemini 4 the names changed from Pro, Flash, and Flash-Lite to chemical elements, and the older names continue on the Gemini 3 models. You may therefore meet both schemes in the same menu. When a name is unfamiliar, ask which station it is.

Beside these general models, Google lists specialised ones for image generation, video generation, speech, music, and embeddings.

Three facts about the lineup are worth more than the names.

1. **Models are retired on a schedule.** The same page lists older models as shut down, and gives dates on which requests for some current ones will be redirected to newer models. Anything you build should expect this.
2. **"Preview" means temporary.** Models labelled as previews can change or disappear at short notice.
3. **The tiers differ in price by a large factor**, as the next section shows.

### Prices and the cost of a request

The cost formula is the one from Module 2.2 and Module 3.1:

$$
\text{cost} = \frac{T_{\text{in}}}{10^{6}} \times P_{\text{in}} + \frac{T_{\text{out}}}{10^{6}} \times P_{\text{out}}
$$

A snapshot of Google's standard API prices in November 2026, per million tokens:

| Model | Input | Output | Cached input |
|---|---|---|---|
| Gemini 4 Carbon | USD 2.00 | USD 10.00 | USD 0.10 |
| Gemini 4 Hydrogen | USD 1.50 | USD 7.50 | USD 0.075 |
| Gemini 3.8 Flash | USD 0.75 | USD 3.75 | USD 0.075 |
| Gemini 3.5 Flash-Lite | USD 0.30 | USD 2.50 | USD 0.03 |

For a request with 100,000 input tokens and 2,000 output tokens:

| Model | Calculation | Cost |
|---|---|---|
| Carbon | $0.1 \times 2.00 + 0.002 \times 10.00$ | USD 0.22 |
| Hydrogen | $0.1 \times 1.50 + 0.002 \times 7.50$ | USD 0.165 |
| 3.8 Flash | $0.1 \times 0.75 + 0.002 \times 3.75$ | USD 0.0825 |
| 3.5 Flash-Lite | $0.1 \times 0.30 + 0.002 \times 2.50$ | USD 0.035 |

Several details on the pricing page matter in practice.

- **Thinking is billed as output.** These models reason before answering, and the reasoning tokens are charged at the output rate, as Module 2.2 explained.
- **Cached input is far cheaper.** Repeated context read from a cache costs a small fraction of the normal input price, about a twentieth for Carbon in the table. Module 3.2 worked through the arithmetic of caching.
- **Batch processing is about half price**, for work that can wait.
- **Prices move.** The same page announces increases for some of these models on stated dates in the following weeks. Treat any price table, including this one, as a dated snapshot.
- **The free tier has a different bargain.** Google AI Studio offers free use of some models within limits. The pricing page states that content sent through the free tier is used to improve Google's products, and paid use is not.

### Tokens for things that are not text

Text is measured as in Module 1.9, at about four characters per token. Other kinds of input have their own rates in Google's documentation.

| Input | Rate | Example |
|---|---|---|
| Text | About 4 characters per token | A 200,000-character report is about 50,000 tokens |
| Image | 258 tokens if both sides are 384 pixels or less. Larger images are divided into tiles of 768 by 768, at 258 tokens each | A 1920 by 1080 slide is $3 \times 2 = 6$ tiles, 1,548 tokens |
| Audio | 32 tokens per second | One hour is $3{,}600 \times 32 = 115{,}200$ tokens |
| Video | Sampled at about one frame per second, with the audio track. A long-standing figure is 263 tokens per second. Newer models at their default resolution use fewer, roughly 100 | One hour is 946,800 tokens at the older figure, or about 360,000 at the newer |

The tile rule can be written as a formula. For an image of width $w$ and height $h$ larger than 384 pixels on a side:

$$
T_{\text{image}} \approx \left\lceil \frac{w}{768} \right\rceil \times \left\lceil \frac{h}{768} \right\rceil \times 258
$$

This is a simplification of the documented procedure and gives a good estimate.

The total for a mixed request is the sum:

$$
T_{\text{in}} = \left\lceil \frac{\text{characters}}{4} \right\rceil + \sum T_{\text{image}} + 32 \cdot t_{\text{audio}} + v \cdot t_{\text{video}}
$$

where the times are in seconds and $v$ is the video rate.

Two practical conclusions follow. An hour of audio is surprisingly cheap, a little over a tenth of the window. An hour of video at full detail nearly fills the window by itself. If you only need what was said in a recording, send the audio.

### The context window

Current Gemini models have a context window of 1,048,576 tokens. For the Gemini 4 models, Google's documentation describes this as shared between the input, the model's thinking, and its output. If $W$ is the window, $T_{\text{in}}$ the input, and $M$ the output you asked for, the room actually available for output is

$$
\text{room} = \min\bigl(M,\ \max(0,\ W - T_{\text{in}})\bigr)
$$

A request that fills almost the whole window leaves the model little space to think or answer. Earlier generations had a separate output limit of about 64,000 tokens.

How much is a million tokens? At three quarters of a word per token it is about 750,000 words, or roughly 1,500 pages at 500 words a page. That is this chapter's estimate. Google's own examples are the eight novels and two hundred podcast transcripts mentioned above, and about 50,000 lines of code.

As Module 1.9 warned, fitting in the window is not the same as being read well. Very long inputs are handled less reliably than short ones, and they cost in proportion to their length on every request. The methods of Module 3.9 apply: put the question last, label each document, and ask for supporting quotes.

### Grounding with Google Search

A model's knowledge stops at its training cut-off. **Grounding** connects it to current information.

```text
   your question
        |
        v
   MODEL decides whether a search would help
        |
        +--> writes search queries --> GOOGLE SEARCH --> result pages
        |                                                    |
        v                                                    v
   MODEL writes an answer using the results, with citations to the pages
```

Three properties are worth knowing.

**The model decides whether to search.** Grounding makes search available. For a question the model believes it can answer, it may not search at all.

**The answer comes with sources.** Citations link statements to pages. As with every citation in this course, they show where to look and do not prove the statement.

**It is billed separately through the API.** At the time of writing the pricing page gives a monthly allowance of 5,000 grounded requests at no charge for current models and USD 14 per thousand after that. For $n$ requests in a month:

$$
\text{cost}_{\text{grounding}} = \frac{\max(0,\ n - 5{,}000)}{1{,}000} \times 14
$$

Twenty thousand grounded requests cost $15 \times 14$, or USD 210, on top of the tokens. In the Gemini app, searching is included in your plan.

### Plans

For individuals, Google sells access to Gemini as part of wider subscriptions that also include cloud storage and features in other Google products. At the time of writing the plans page lists, above the free tier, plans named Google AI Plus, Google AI Pro, and Google AI Ultra, each giving access to more capable models and higher limits, with storage rising from hundreds of gigabytes to tens of terabytes. Prices vary by country and change, so they are not repeated here. Students are offered discounts in some regions.

### Privacy settings

Google's privacy pages for the Gemini app describe the following, as of the time of writing.

- A setting called **Keep Activity** controls whether your chats are saved to your account. When it is on, saved activity is used to improve Google's services, including training its models.
- **Human reviewers read a sample of conversations.** Reviewed chats are disconnected from your account and can be kept for up to three years, and deleting your activity does not delete them.
- **Saved activity is deleted automatically after 18 months by default.** You can choose 3 or 36 months instead.
- **Temporary chats** are not used for training and are kept for 72 hours.
- **Work and school accounts are governed by different terms**, covered in Module 3.13.

The practical rule is the one from Module 3.1: find the setting on the first day, decide deliberately, and do not put anything confidential into a consumer account whose data may be reviewed.

## 3. Production-Grade Implementation & Annotated Walkthrough

The quantities in this chapter make a planning tool for multimodal work. First, counting tokens for mixed input.

```python
import math

def image_tokens(width, height):
    if width <= 384 and height <= 384:
        return 258
    return math.ceil(width / 768) * math.ceil(height / 768) * 258

def input_tokens(characters=0, image_sizes=(), audio_seconds=0, video_seconds=0, video_rate=263):
    text = math.ceil(characters / 4)
    images = sum(image_tokens(width, height) for width, height in image_sizes)
    return text + images + 32 * audio_seconds + video_rate * video_seconds

print(image_tokens(300, 300), image_tokens(1024, 1024), image_tokens(1920, 1080))
pack = input_tokens(characters=200_000, image_sizes=[(1920, 1080)] * 10, audio_seconds=3_600)
print(f"report + 10 slides + 1 hour of audio: {pack:,} tokens")
print(f"report + 1 hour of video            : {input_tokens(characters=200_000, video_seconds=3_600):,} tokens")
print(f"the same at the newer video rate    : {input_tokens(characters=200_000, video_seconds=3_600, video_rate=100):,} tokens")
```

- **Small images have a flat cost.** Anything up to 384 pixels on each side is 258 tokens. A thumbnail and a small icon cost the same.
- **Larger images are counted in tiles.** `math.ceil` rounds up in each direction, because a partial tile is still processed. A 1920 by 1080 slide needs three tiles across and two down.
- **`video_rate` is a parameter.** The documentation has given different figures for different models and resolutions. A parameter with the older, higher figure as the default produces a cautious estimate, and the last line shows how much the answer changes with the newer one.
- **A report, ten slides, and an hour of audio come to 180,680 tokens.** That is under a fifth of the window. The report with an hour of video comes to 996,800, almost all of it.

Next, the window, and the cost of a request.

```python
WINDOW = 1_048_576

PRICES = {            # USD per 1M tokens: (input, output, cached input). A dated snapshot.
    "carbon": (2.00, 10.00, 0.10),
    "hydrogen": (1.50, 7.50, 0.075),
    "flash": (0.75, 3.75, 0.075),
    "flash-lite": (0.30, 2.50, 0.03),
}

def output_room(used_input, max_output, window=WINDOW):
    return min(max_output, max(0, window - used_input))

def request_cost(model, used_input, output, cached=0, prices=PRICES):
    price_in, price_out, price_cached = prices[model]
    fresh = used_input - cached
    return fresh / 1e6 * price_in + cached / 1e6 * price_cached + output / 1e6 * price_out

print(output_room(180_680, 64_000), output_room(996_800, 64_000), output_room(1_200_000, 64_000))
for model in PRICES:
    print(f"{model:>10}: USD {request_cost(model, 100_000, 2_000):.4f}   meeting pack USD {request_cost(model, pack, 2_000):.4f}")
print(f"carbon with 90,000 of 100,000 input tokens cached: USD {request_cost('carbon', 100_000, 2_000, cached=90_000):.4f}")
```

- **`output_room` applies the shared-window rule.** With the meeting pack there is space for the full 64,000 tokens of output. With the hour of video only 51,776 remain. With an input larger than the window there is none, and `max(0, ...)` stops the result going negative.
- **Prices are data with a label.** The comment says the table is a snapshot. When Google changes a price, one line changes.
- **Cached tokens are priced separately.** The input is split into the part read fresh and the part read from the cache. For the Carbon request, caching 90,000 of the 100,000 input tokens brings the cost from USD 0.22 to about USD 0.05.
- **The loop shows the spread.** The same request costs about six times as much on the frontier model as on the lightweight one.

Finally, grounding.

```python
def grounding_cost(requests, free=5_000, per_thousand=14.0):
    return max(0, requests - free) / 1_000 * per_thousand

for requests in (4_000, 5_000, 20_000):
    print(f"{requests:>6,} grounded requests in a month: USD {grounding_cost(requests):.2f}")
```

- **The allowance is subtracted first.** Below it the cost is zero. Above it only the excess is charged.
- **The numbers are parameters.** Allowances and rates are exactly the kind of figure that changes.

**Complexity.** Every function here is constant time except `input_tokens`, which is linear in the number of images.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**The names are confusing, and it is not you.** Version numbers, element names, "Pro", "Flash", "Lite", "preview", and dated identifiers all coexist. Users regularly choose the wrong model because of it. Ask of any name: which station, and is it stable or a preview?

**Models disappear.** Developers on Google's forums complain that preview models change or are withdrawn, and the documentation lists retirement dates for stable ones too. If you depend on a model, note its end date, keep the name in configuration, and re-test when it changes.

**The app and AI Studio give different answers.** People test a prompt in one and are surprised by the other. They share a model and little else: instructions, tools, limits, and settings differ. Test where you will use it.

**Free in AI Studio has a price.** Content sent through the free tier may be used to improve Google's products. Do not paste confidential material into a free API key's requests or a free prototype.

**Video fills the window.** Uploading an hour of video where the audio would do uses several times the tokens and can leave little room for an answer. Send audio for speech, a few screenshots for visuals, and video only when the motion matters.

**A huge window invites lazy prompts.** Being able to paste five books does not mean five books is a good prompt. Relevant, labelled material with the question at the end outperforms everything-you-have.

**Grounding does not always trigger.** The model decides whether to search. If you need current information, say so: "search for the latest figures and cite your sources". Check the citations for whether a search happened at all.

**Grounding has its own limits.** Developers report hitting rate limits on grounded requests that are separate from the model's own limits. If grounded calls fail under load, look at the search quota.

**Rate limits arrive sooner than expected on the free tier.** A prototype that works in testing can stop under real use. Read the limits for your tier before you promise anything to anyone.

**Thinking tokens inflate output bills.** A short visible answer may have been preceded by a long reasoning phase billed at the output rate. Check the usage figures returned with a response and do not estimate from what you can see.

**The consumer app is not the place for client data.** With activity saved, conversations may be reviewed by people and retained for years. Use a work account with the appropriate terms, or the temporary chat mode, for anything sensitive.

**Check what you already pay for.** Many people subscribe to an assistant elsewhere while already holding a Google storage plan that includes a capable Gemini tier.

## 5. Active Recall Check & Synthesis Summary

**Summary.** Gemini is Google's family of models, arranged like every such family into a frontier tier, a fast everyday tier, and a lightweight tier for volume, with names that have changed between generations and prices that differ several-fold between the ends. Its distinguishing strengths are direct handling of images, audio, and video, a context window of about a million tokens, and grounding in Google Search. In the newest models the window is shared between input, thinking, and output. Consumer chats may be saved, reviewed by people, and used to improve models unless you change the settings, and the free API tier trades cost for data use.

"""
Lab solution: Multimodal Tokens, the Context Window, and Costs
Standard library only.

Rates and prices are a dated snapshot for practice. Always check the provider's current pages.
"""
import math

WINDOW = 1_048_576

PRICES = {            # USD per 1M tokens: (input, output, cached input)
    "carbon": (2.00, 10.00, 0.10),
    "hydrogen": (1.50, 7.50, 0.075),
    "flash": (0.75, 3.75, 0.075),
    "flash-lite": (0.30, 2.50, 0.03),
}


# ---------------------------------------------------------------- Step 1
def image_tokens(width, height):
    """Small images cost a flat 258 tokens. Larger ones are counted in 768-pixel tiles,
    rounding up in each direction because a partial tile is still processed."""
    if width <= 384 and height <= 384:
        return 258
    return math.ceil(width / 768) * math.ceil(height / 768) * 258


# ---------------------------------------------------------------- Step 2
def input_tokens(characters=0, image_sizes=(), audio_seconds=0, video_seconds=0, video_rate=263):
    """Each kind of input has its own rate. The video rate is a parameter because the
    documented figure differs between models and resolutions; the default is the cautious one."""
    text = math.ceil(characters / 4)
    images = sum(image_tokens(width, height) for width, height in image_sizes)
    return text + images + 32 * audio_seconds + video_rate * video_seconds


# ---------------------------------------------------------------- Step 3
def output_room(used_input, max_output, window=WINDOW):
    """A request that nearly fills the window leaves little room to think or answer."""
    return min(max_output, max(0, window - used_input))


# ---------------------------------------------------------------- Step 4
def request_cost(model, used_input, output, cached=0, prices=PRICES):
    """Prices are per MILLION tokens. Cached input is charged at its own, much lower rate."""
    price_in, price_out, price_cached = prices[model]
    fresh = used_input - cached
    return fresh / 1e6 * price_in + cached / 1e6 * price_cached + output / 1e6 * price_out


# ---------------------------------------------------------------- Step 5
def grounding_cost(requests, free=5_000, per_thousand=14.0):
    """Only the requests beyond the free allowance are charged."""
    return max(0, requests - free) / 1_000 * per_thousand
