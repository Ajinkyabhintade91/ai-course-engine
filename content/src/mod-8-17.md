# Agent Project 3: AI Customer Support Agent

Module 7.18 built a support assistant that answered from help articles with citations and handed difficult conversations to people. This project upgrades it into an agent that also acts on the customer's **account**: looking up orders, starting returns, and, with approval, issuing refunds. Combining retrieval over help content with account tools is what makes a support agent genuinely useful, since most real questions are about "my order", not "the policy", and it is also what makes it risky: the agent can now leak one customer's data to another, misstate a policy in a way the company must honour, and report success on conversations that were never resolved.

## 1. First-Principles Mental Model & Intuition

### A front-desk clerk with a terminal

A good front-desk clerk does three different things. They answer **policy** questions from the manual, quoting it rather than improvising. They answer **account** questions from the terminal, but only after checking who they are talking to, and only about that person's own records. And they **decide** on requests by applying the policy to the record, "your order arrived 15 days ago, so it is within the 30-day window", without bending the rules because the customer is persuasive. When they cannot help, they pass the customer to a supervisor with a note, so the customer does not have to start again.

```text
   customer message
        |
   [identify customer]  logged-in session -> customer_id (never trust an id typed in chat)
        |
   [plan]  policy question? -> search_help (RAG, Modules 7.18 and 8.7)
           account question? -> get_order (authorised: this customer's order only)
           action? -> eligibility computed in CODE from policy + order -> start_return / refund (approval)
        |
   [answer]  cite help articles; state account facts from tools; never invent policy
        |
   [escalate?]  Module 8.11 triggers -> handoff packet (summary, facts, what was tried, masked data)
        |
   [measure]  containment vs TRUE resolution (no reopen within 7 days); CSAT with confidence interval
```

### Policy statements are commitments

In 2024 a Canadian tribunal ordered Air Canada to pay a passenger CAD 812 after its website chatbot described a bereavement-fare refund policy incorrectly. As CBC News reported, the airline argued that the chatbot was a separate legal entity responsible for its own actions; the tribunal did not accept that. Whatever the jurisdiction, the practical lesson is that a support agent's statements about policy are the company's statements. Policy must come from authoritative content or code, never from the model's general knowledge or improvisation.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Two knowledge sources, two kinds of trust

| Source | Example | Retrieved by | Trust rule |
|---|---|---|---|
| Help content | Returns policy, delivery times | Retrieval, Modules 7.18 and 8.7 | Answer only from retrieved passages, with citations |
| Account data | Order A-1 delivered 15 days ago | Tools, Module 8.4 | Only the authenticated customer's records |

Claude's customer support use-case guide recommends the same split: ground answers in your knowledge base and connect tools for account actions, with clear instructions for when to escalate.

### Account tools and object-level authorisation

The most dangerous bug in a support agent is answering about **someone else's** order. OWASP ranks **broken object level authorization**, BOLA, as the top API security risk: an endpoint checks that the user is logged in but not that the specific object, here an order, belongs to them. In an agent, BOLA appears when the model passes an order number the customer typed, "what's the status of B-7?", and the tool returns it without checking ownership. Prompt injection, Module 8.14, makes this worse: a crafted message can ask the agent to look up arbitrary orders.

The rule is enforced in the tool layer, never by the prompt:

1. The customer's identity comes from the **authenticated session**, never from the conversation text.
2. Every tool that touches account data requires a verified customer.
3. Every object argument, an order, an address, a payment method, is checked against the session's customer.
4. Not-found and not-yours return the **same** message, so the agent cannot be used to discover which order numbers exist.
5. Actions above a risk tier require approval, Module 8.11.

### Policy decisions in code

"Can I return this?" combines policy, a 30-day window, 14 days if opened, some items excluded, with account data, delivery date, opened or not, items. A model asked to reason this out may get the arithmetic or the exceptions wrong, and its answer is a commitment. The decision belongs in a **deterministic function** the agent calls, which returns the decision and a reason the agent then explains:

$$\text{eligible} \iff \text{delivered} \;\land\; \text{no excluded items} \;\land\; (\text{today} - \text{delivered}) \le w(\text{opened})$$

with $w = 30$ days for unopened items and 14 for opened ones in the lab's policy. The model's job is to explain the result kindly and accurately; it never overrides it. When policy changes, one function changes, and the eval set of Module 8.12 confirms it.

### Escalation and handoff design

Module 8.11 defined when to escalate. The handoff itself deserves design, because a bad handoff, "please hold for an agent", followed by the customer repeating everything, undoes the goodwill the agent earned. A **handoff packet** gives the person:

| Field | Purpose |
|---|---|
| Customer identifier | Open the account immediately |
| Escalation reasons | Why the agent stopped, Module 8.11's reasons |
| Facts established | Order, eligibility, what tools returned |
| What was tried | Steps already taken, so they are not repeated |
| Last customer message | The current state of the conversation |
| Transcript, with sensitive data masked | Context without spreading card numbers into the ticketing system |

Customers sometimes type full card numbers into chat. The packet masks them, keeping only the last four digits, before they reach the human queue, where they would otherwise be stored and copied.

### Measuring resolution

**Containment**, the share of conversations the agent finished without handing over, is the easiest metric and the most misleading. A customer who gives up, or who gets a wrong answer and comes back three days later, counts as contained. Vendors draw the distinction themselves: Intercom's documentation for its Fin agent separates **confirmed** resolutions, where the customer says the answer was satisfactory, from **assumed** resolutions, where the customer leaves without asking for more help, and advises handing off proactively when frustration is detected. A stricter measure is **true resolution**:

$$\text{resolution rate} = \frac{|\{c : \text{no handoff},\ \text{confirmed},\ \text{no reopen within } d \text{ days}\}|}{N}$$

and the gap, containment minus resolution, is **false containment**: conversations the dashboard counts as wins that were not.

### Measuring satisfaction honestly

Customer satisfaction, CSAT, is usually the share of survey responses scoring 4 or 5 out of 5. Two cautions. First, **response rates are low** and responders are not typical: very happy and very angry customers answer more. Second, **small samples are noisy**: 8 satisfied of 10 responses is "80 percent" with a wide uncertainty. The **Wilson score interval** gives a confidence interval for a proportion $\hat p$ from $n$ responses that behaves well for small $n$ and extreme values:

$$\frac{\hat p + \frac{z^2}{2n} \pm z\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}$$

with $z = 1.96$ for 95 percent. Eight of 10 gives an interval of about 0.49 to 0.94; 70 of 100 gives about 0.60 to 0.78. Report CSAT with its interval and response rate, or a week of noise will be mistaken for a trend.

### Complexity

Authorisation is constant per call. Eligibility is linear in the order's items. The handoff packet is linear in the transcript. Resolution metrics are linear in conversations. The Wilson interval is constant once counts are known.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, authorising tool calls.

```python
import math
import re

ORDERS = {"A-1": {"customer": "c-42", "delivered_day": 100, "status": "delivered", "total": 89.0, "items": ["SAW-3"], "opened": False},
          "A-2": {"customer": "c-42", "delivered_day": 60, "status": "delivered", "total": 129.0, "items": ["DRILL-2"], "opened": True},
          "B-7": {"customer": "c-99", "delivered_day": 110, "status": "delivered", "total": 19.0, "items": ["BLADE-10"], "opened": False},
          "A-3": {"customer": "c-42", "delivered_day": None, "status": "in transit", "total": 45.0, "items": ["LAMP-9"], "opened": False}}
TOOLS = {"search_help": {"auth": False, "approval": False}, "get_order": {"auth": True, "approval": False},
         "start_return": {"auth": True, "approval": False}, "issue_refund": {"auth": True, "approval": True}}

def authorise(session, tool, args, orders):
    rule = TOOLS.get(tool)
    if rule is None:
        return "deny", "unknown tool"
    if rule["auth"] and not session.get("customer_id"):
        return "deny", "customer not verified"
    order_id = args.get("order_id")
    if order_id is not None:
        order = orders.get(order_id)
        if order is None or order["customer"] != session.get("customer_id"):
            return "deny", f"order {order_id} not found for this customer"
    if rule["approval"]:
        return "approve", "needs human approval"
    return "allow", "ok"

SESSION = {"customer_id": "c-42"}
print(authorise(SESSION, "get_order", {"order_id": "A-1"}, ORDERS))
print(authorise(SESSION, "get_order", {"order_id": "B-7"}, ORDERS))
print(authorise({}, "get_order", {"order_id": "A-1"}, ORDERS))
print(authorise(SESSION, "issue_refund", {"order_id": "A-1"}, ORDERS))
```

- **The customer id comes from the session object.** The conversation never supplies it.
- **Searching help needs no login; account tools do.**
- **B-7 exists but belongs to c-99.** The denial reads exactly like the one for a non-existent order, so the agent cannot be used to probe order numbers.
- **Refunds pass authorisation but need a person's approval.**

Next, eligibility in code.

```python
POLICY = {"window_days": 30, "opened_window_days": 14, "excluded": {"BLADE-10"}}

def return_eligibility(order, policy, today):
    if order["status"] != "delivered":
        return False, "not delivered yet", None
    excluded = [item for item in order["items"] if item in policy["excluded"]]
    if excluded:
        return False, f"{', '.join(excluded)} cannot be returned", None
    window = policy["opened_window_days"] if order["opened"] else policy["window_days"]
    age = today - order["delivered_day"]
    if age > window:
        return False, f"{age} days since delivery, window {window}", None
    return True, f"{window - age} days left", order["total"]

for order_id, order in ORDERS.items():
    print(order_id, return_eligibility(order, POLICY, today=115))
```

- **Checks run in a fixed order: delivered, excluded items, then the window.** The first failure is the reason given.
- **A-1, unopened, delivered 15 days ago: eligible with 15 days left, refund 89.**
- **A-2 was opened, so its window is 14 days, and it is 55 days old.**
- **B-7's blade is excluded; A-3 has not arrived.**
- **The agent explains these results; it never recomputes or overrides them.**

Then, the handoff packet.

```python
CARD = re.compile(r"\b(?:\d[ -]?){12}(\d{4})\b")

def mask(text):
    return CARD.sub(lambda m: "card ending " + m.group(1), text)

def handoff_packet(customer_id, transcript, facts, reasons, tried):
    clean = [(who, mask(text)) for who, text in transcript]
    return {"customer": customer_id, "reasons": reasons, "facts": facts, "tried": tried,
            "last_customer_message": next((text for who, text in reversed(clean) if who == "customer"), ""),
            "turns": len(transcript), "transcript": clean}

TRANSCRIPT = [("customer", "My refund for A-2 never arrived"),
              ("agent", "A-2 was delivered 55 days ago and was opened, so it is outside the 14 day window."),
              ("customer", "I paid with 4111 1111 1111 1234, let me talk to a person")]
packet = handoff_packet("c-42", TRANSCRIPT, {"order": "A-2", "eligible": False}, ["asked for a person"],
                        ["checked order A-2", "checked return window"])
print(packet["last_customer_message"])
print(packet["reasons"], packet["tried"], packet["turns"])
```

- **Card numbers become "card ending 1234" throughout the transcript.** The human queue never stores the full number.
- **The last customer message is found from the end, skipping agent turns.**
- **Facts and attempted steps travel with the conversation.** The person starts where the agent stopped.

Then, true resolution.

```python
def resolution(conversations, reopen_days=7):
    n = len(conversations)
    contained = [c for c in conversations if not c["handoff"]]
    resolved = [c for c in contained
                if c["confirmed"] and not (c["reopened_after"] is not None and c["reopened_after"] <= reopen_days)]
    return {"containment": round(len(contained) / n, 3), "resolution": round(len(resolved) / n, 3),
            "false_containment": round((len(contained) - len(resolved)) / n, 3)}

CONVERSATIONS = [{"handoff": False, "confirmed": True, "reopened_after": None}, {"handoff": False, "confirmed": True, "reopened_after": 3},
                 {"handoff": False, "confirmed": False, "reopened_after": None}, {"handoff": True, "confirmed": False, "reopened_after": None},
                 {"handoff": False, "confirmed": True, "reopened_after": 12}, {"handoff": False, "confirmed": True, "reopened_after": None},
                 {"handoff": True, "confirmed": True, "reopened_after": None}, {"handoff": False, "confirmed": False, "reopened_after": 1}]
print(resolution(CONVERSATIONS))
```

- **Six of eight conversations were contained: 75 percent.** The number a vendor dashboard might show.
- **Only three were confirmed and not reopened within 7 days: 37.5 percent.**
- **A reopen after 12 days counts as a new issue.** The window is a policy choice.
- **False containment is 37.5 percent.** Half of the "contained" conversations were not resolved.

Finally, satisfaction with an interval.

```python
def csat(scores, surveys_sent, z=1.96):
    n = len(scores)
    if n == 0:
        return {"responses": 0}
    p = sum(1 for s in scores if s >= 4) / n
    centre = (p + z * z / (2 * n)) / (1 + z * z / n)
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / (1 + z * z / n)
    return {"responses": n, "response_rate": round(n / surveys_sent, 3), "csat": round(p, 3),
            "low": round(centre - half, 3), "high": round(centre + half, 3)}

print(csat([5, 4, 5, 3, 4, 5, 2, 5, 4, 4], surveys_sent=80))
print(csat([5] * 45 + [4] * 25 + [3] * 10 + [2] * 12 + [1] * 8, surveys_sent=400))
```

- **Scores of 4 and 5 count as satisfied.**
- **Ten responses at 80 percent give an interval of 0.49 to 0.94.** Almost anything is consistent with that.
- **A hundred responses at 70 percent give 0.60 to 0.78.** Narrower, but the 25 percent response rate still limits what it says about all customers.

**Complexity.** `authorise` is constant. `return_eligibility` is linear in items. `handoff_packet` is linear in the transcript. `resolution` is linear in conversations. `csat` is linear in responses.

### A support agent launch checklist

```text
IDENTITY     customer_id from the authenticated session only; chat text never sets identity
TOOLS        search_help (public); get_order, start_return (verified, own orders only); issue_refund (approval)
DENIALS      not-found and not-yours return the same message; denials logged and alerted on spikes
POLICY       eligibility, fees, and windows computed in code; the agent explains, never decides
ANSWERS      policy only from retrieved help passages with citations (Module 7.18)
HANDOFF      packet: reasons, facts, steps tried, last message, masked transcript
METRICS      containment, true resolution (no reopen in 7 days), false containment; CSAT with 95% interval
EVALS        regression tasks for every policy rule and every BOLA attempt (Module 8.12)
```

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**Trusting identity from chat.** "I'm customer c-99" must change nothing. Take identity from the session.

**Checking login, not ownership.** Logged-in customers can still ask about other orders. Check every object.

**Different errors for not-found and not-yours.** The difference reveals which orders exist. Use one message.

**Letting the model apply policy.** Its arithmetic and exceptions are a liability, as the Air Canada case shows for policy statements. Compute decisions in code.

**Improvised policy.** When retrieval finds nothing, the model fills the gap from general knowledge. Say "I don't know" and hand over.

**Handoffs without context.** Customers repeating themselves are angrier than before. Send a packet.

**Card numbers in tickets.** Chat transcripts copied into ticketing systems spread payment data. Mask before handoff.

**Celebrating containment.** Customers who give up look contained. Measure confirmed resolution without reopens.

**CSAT from ten surveys.** A week's swing from 80 to 60 percent may be noise. Report the interval.

**Ignoring who answers surveys.** Responders are not typical customers. Track response rate and look at transcripts too.

**Refunds on persuasion.** A persistent customer can talk a model into exceptions. Exceptions belong to people.

**No eval for policy changes.** A new return window silently breaks old answers. Add regression tasks per rule.

def mask(text):
    """Given: replace card numbers with "card ending NNNN"."""
    return CARD.sub(lambda m: "card ending " + m.group(1), text)


# ---------------------------------------------------------------- Step 1
def authorise(session, tool, args, orders):
    """Identity from the session; ownership checked per object; one message for not-found and not-yours."""
    rule = TOOLS.get(tool)
    if rule is None:
        return "deny", "unknown tool"
    if rule["auth"] and not session.get("customer_id"):
        return "deny", "customer not verified"
    order_id = args.get("order_id")
    if order_id is not None:
        order = orders.get(order_id)
        if order is None or order["customer"] != session.get("customer_id"):
            return "deny", f"order {order_id} not found for this customer"
    if rule["approval"]:
        return "approve", "needs human approval"
    return "allow", "ok"


# ---------------------------------------------------------------- Step 2
def return_eligibility(order, policy, today):
    """Policy applied in code; the agent explains, never decides."""
    if order["status"] != "delivered":
        return False, "not delivered yet", None
    excluded = [item for item in order["items"] if item in policy["excluded"]]
    if excluded:
        return False, f"{', '.join(excluded)} cannot be returned", None
    window = policy["opened_window_days"] if order["opened"] else policy["window_days"]
    age = today - order["delivered_day"]
    if age > window:
        return False, f"{age} days since delivery, window {window}", None
    return True, f"{window - age} days left", order["total"]


# ---------------------------------------------------------------- Step 3
def handoff_packet(customer_id, transcript, facts, reasons, tried):
    """Everything the person needs, nothing they should not store."""
    clean = [(who, mask(text)) for who, text in transcript]
    return {"customer": customer_id, "reasons": reasons, "facts": facts, "tried": tried,
            "last_customer_message": next((text for who, text in reversed(clean) if who == "customer"), ""),
            "turns": len(transcript), "transcript": clean}


# ---------------------------------------------------------------- Step 4
def resolution(conversations, reopen_days=7):
    """Containment counts silence as success; resolution does not."""
    n = len(conversations)
    contained = [c for c in conversations if not c["handoff"]]
    resolved = [c for c in contained
                if c["confirmed"] and not (c["reopened_after"] is not None and c["reopened_after"] <= reopen_days)]
    return {"containment": round(len(contained) / n, 3), "resolution": round(len(resolved) / n, 3),
            "false_containment": round((len(contained) - len(resolved)) / n, 3)}


# ---------------------------------------------------------------- Step 5
def csat(scores, surveys_sent, z=1.96):
    """Satisfaction with its uncertainty and response rate."""
    n = len(scores)
    if n == 0:
        return {"responses": 0}
    p = sum(1 for s in scores if s >= 4) / n
    centre = (p + z * z / (2 * n)) / (1 + z * z / n)
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / (1 + z * z / n)
    return {"responses": n, "response_rate": round(n / surveys_sent, 3), "csat": round(p, 3),
            "low": round(centre - half, 3), "high": round(centre + half, 3)}
