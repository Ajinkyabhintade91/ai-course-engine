# Installing Ollama

Module 10.2 explained what Ollama is. This module installs it on Windows, macOS, and Linux, checks that it uses your GPU, and configures it: where models are stored, which address the server listens on, and how environment variables are set on each operating system. Installation is usually one download or one command, but most of the problems people post about, slow models, full system drives, and servers that other machines cannot reach or that everyone can reach, come from the few decisions made at this stage.

Facts are from Ollama's documentation at the time of writing (November 2026). Requirements change between releases, so check the installation pages for your platform before relying on any version number here.

## 1. First-Principles Mental Model & Intuition

### Installing a workshop machine

Installing Ollama is like installing a new machine in a workshop. Before delivery you check that the floor can take the weight and the doorway is wide enough: the **preflight** of operating-system version, memory, and disk. On delivery you connect it to the right power supply, because a lathe on the wrong supply runs, but slowly and badly: the **accelerator**, CUDA, ROCm, Metal, or Vulkan rather than plain CPU. Then you decide where its materials are stored, so they do not fill the corridor, and who may use it, only people inside the workshop or anyone walking past the open door: the **model directory** and the **host address**. Finally, you write the settings in the place the machine actually reads them, because a note stuck to the wrong panel is ignored: the **environment variables**, set differently on each operating system.

```text
 PREFLIGHT              INSTALL                 VERIFY                 CONFIGURE
 OS version             Windows: OllamaSetup    ollama -v              OLLAMA_MODELS  (where models live)
 RAM, disk              macOS:   Ollama.dmg     ollama run small-model OLLAMA_HOST    (who can connect)
 GPU, driver            Linux:   install.sh     ollama ps -> 100% GPU  OLLAMA_KEEP_ALIVE, OLLAMA_CONTEXT_LENGTH
                        Docker:  ollama/ollama  server log             set via: setx / launchctl / systemctl edit
                                                                       then restart the server
```

### The single most important habit

After every install or configuration change, **verify**: check the version, run a small model, and look at `ollama ps`. A setting that was not picked up, or a GPU that was not detected, produces a system that works but slowly or in the wrong place, and nothing will warn you unless you look.

## 2. Core Theory, Mathematical Foundations & Architecture Internals

### Requirements by platform

| Platform | Requirement (as documented) | Notes |
|---|---|---|
| Windows | Windows 10 22H2 or newer, Home or Pro | Installs in your home folder without administrator rights; at least 4 GB for the install, plus space for models |
| macOS | macOS 14 Sonoma or newer | Apple silicon runs on CPU and GPU; Intel Macs run on CPU only |
| Linux | Most current distributions, x86-64 and ARM64 | Install script or manual packages; systemd service recommended |

Memory sets the size of model you can run. Ollama's README has long advised roughly 8 GB of RAM for 7B models, 16 GB for 13B, and 32 GB for 33B, at the default quantization; Module 10.10 does this properly. Disk matters too: models are gigabytes each, and the documentation warns that they can take tens to hundreds of gigabytes in total.

### Installing

**Windows.** Download and run `OllamaSetup.exe`. Ollama runs in the background with a tray icon, and the `ollama` command works in Command Prompt and PowerShell. The installer accepts `/DIR="d:\some\location"` to install elsewhere.

**macOS.** Open `Ollama.dmg` and drag the app to Applications. On first start, it offers to link the `ollama` command into `/usr/local/bin`.

**Linux.** Run the install script:

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

It installs the binary and sets up a systemd service running as an `ollama` user. A manual install extracts a package into `/usr` and adds the service file yourself, with an extra ROCm package for AMD GPUs and a separate ARM64 package. Setting `OLLAMA_VERSION` when running the script installs a specific version. Piping a script into a shell runs code you have not read; on a machine you care about, download the script, read it, then run it.

**Docker.** The `ollama/ollama` image runs the server in a container, with a volume for models and the port published, and GPU access passed through with the container runtime's GPU options. Useful for servers; on a desktop, the native install is simpler.

### Verifying

```bash
ollama -v                      # the CLI works and can see the server version
ollama run llama3.2 "Say hi"   # downloads a small model and generates
ollama ps                      # PROCESSOR column: 100% GPU, 100% CPU, or a CPU/GPU split
```

The `ollama ps` check is the one that matters for performance. The FAQ describes the column: `100% GPU` means the model is entirely in GPU memory, `100% CPU` entirely in system memory, and a split such as `48%/52% CPU/GPU` means it is partly in each.

### Choosing the accelerator

Ollama picks a backend automatically from the hardware it finds:

| Hardware | Backend | Conditions (as documented) |
|---|---|---|
| NVIDIA GPU | CUDA | Compute capability 5.0 or newer; on Windows, driver 551.61 or newer |
| AMD Radeon GPU | ROCm, or Vulkan | ROCm v7-capable driver stack for ROCm; otherwise Vulkan, which the Windows page describes as enabled by default and the recommended fallback |
| Apple silicon Mac | Metal | Built in; no driver to install |
| Intel Mac | CPU | No GPU acceleration |
| Other GPUs | Vulkan where supported | Check the hardware support page |
| None detected | CPU | Works, but much slower for anything but small models |

On Linux, check the driver first: `nvidia-smi` should list your NVIDIA GPU; if it does not, Ollama cannot use it either. On a laptop with both an integrated and a discrete GPU, the Windows documentation describes a variable for steering Vulkan to the discrete one.

### Configuration: what you can change

The server reads environment variables when it starts. The most useful:

| Variable | Default | Purpose |
|---|---|---|
| `OLLAMA_HOST` | `127.0.0.1:11434` | Address and port the server listens on, and the CLI talks to |
| `OLLAMA_MODELS` | macOS `~/.ollama/models`; Linux service `/usr/share/ollama/.ollama/models`; Windows `C:\Users\%username%\.ollama\models` | Where models are stored |
| `OLLAMA_KEEP_ALIVE` | `5m` | How long models stay loaded after a request |
| `OLLAMA_CONTEXT_LENGTH` | Version and memory dependent, Module 10.2 | Default context window |
| `OLLAMA_ORIGINS` | Local origins | Which browser origins may call the API |
| `OLLAMA_NUM_PARALLEL`, `OLLAMA_MAX_LOADED_MODELS` | Small numbers | Concurrency, Module 10.10 |
| `OLLAMA_DEBUG` | Off | Verbose logs for troubleshooting |

`ollama serve --help` lists the variables your version supports. A misspelled variable, `OLLAMA_MODEL` instead of `OLLAMA_MODELS`, is silently ignored.

### Parsing the host

`OLLAMA_HOST` can be a bare address, `0.0.0.0`; an address and port, `0.0.0.0:8080`; a port only, `:11500`; or a URL with a scheme, `http://localhost:11500`. Missing parts take defaults: address `127.0.0.1`, port `11434`. An address is **exposed** if it is anything other than the loopback addresses, `127.0.0.1`, `localhost`, or `::1`. `0.0.0.0` means every network interface: your laptop on café Wi-Fi would accept requests from anyone on that network. Ollama's API has no built-in authentication, so an exposed server needs a firewall or an authenticating proxy, Module 10.13.

### Where variables must be set

The documentation is specific, and this is the commonest source of "I set it, but nothing changed":

| OS | How | Then |
|---|---|---|
| Windows | Edit environment variables for your account (Settings or Control Panel), or `setx NAME "value"` | Quit Ollama from the tray and start it again; open a new terminal |
| macOS (app) | `launchctl setenv NAME "value"` for each variable | Restart the Ollama app |
| Linux (systemd) | `sudo systemctl edit ollama.service`, then `Environment="NAME=value"` lines under `[Service]` | `sudo systemctl daemon-reload` and `sudo systemctl restart ollama` |

On Linux, `export OLLAMA_HOST=` in your shell affects only the CLI in that shell, not the service, which runs as a different user under systemd. On Windows and macOS, the running app keeps its old environment until restarted.

### Logs

When something is wrong, read the server log: on macOS `~/.ollama/logs/server.log`; on Linux `journalctl -u ollama`; on Windows the `server.log` in `%LOCALAPPDATA%\Ollama`. Setting `OLLAMA_DEBUG=1` adds detail. Module 10.14 covers diagnosis.

### Complexity

Every check in this module is linear in its input: the machine description, the host string, the environment variables, or the list of commands generated.

## 3. Production-Grade Implementation & Annotated Walkthrough

First, a preflight check of each machine.

```python
def preflight(m):
    issues = []
    os_name, ver = m["os"], m.get("version")
    if os_name == "macos":
        if ver[0] < 14:
            issues.append("macOS 14 Sonoma or newer required")
        if m.get("arch") == "x86_64":
            issues.append("Intel Mac: CPU only, expect slow generation")
    elif os_name == "windows":
        if ver < (10, "22H2"):
            issues.append("Windows 10 22H2 or newer required")
        if m.get("disk_free_gb", 0) < 4:
            issues.append("at least 4 GB needed for the install")
    if m.get("ram_gb", 0) < 8:
        issues.append("under 8 GB RAM: only small models")
    if m.get("disk_free_gb", 0) < 20:
        issues.append("under 20 GB free: room for only a few models")
    return issues

MACHINES = {
    "old-windows": {"os": "windows", "version": (10, "21H2"), "ram_gb": 16, "disk_free_gb": 120},
    "macbook": {"os": "macos", "version": (15, 2), "arch": "arm64", "ram_gb": 16, "disk_free_gb": 200},
    "old-imac": {"os": "macos", "version": (13, 6), "arch": "x86_64", "ram_gb": 8, "disk_free_gb": 15},
    "tiny-linux": {"os": "linux", "version": None, "ram_gb": 4, "disk_free_gb": 3},
    "new-windows": {"os": "windows", "version": (11, "24H2"), "ram_gb": 32, "disk_free_gb": 500},
}
for name, m in MACHINES.items():
    print(name, preflight(m))
```

- **Windows versions compare as tuples.** `(10, "21H2") < (10, "22H2")` is true, and any Windows 11 release is newer than any Windows 10.
- **The Intel iMac fails three ways:** old macOS, CPU only, and little disk space.
- **The thresholds for RAM and disk are advisory.** They flag machines where only small models will be practical; Module 10.10 gives exact sizing.

Next, the accelerator.

```python
def accelerator(os_name, gpu):
    if os_name == "macos":
        return "Metal" if gpu and gpu.get("vendor") == "apple" else "CPU"
    if not gpu:
        return "CPU"
    vendor = gpu["vendor"]
    if vendor == "nvidia":
        if gpu.get("compute", 0) < 5.0:
            return "CPU"
        if os_name == "windows" and gpu.get("driver", 0) < 551.61:
            return "update driver"
        return "CUDA"
    if vendor == "amd":
        return "ROCm" if gpu.get("rocm") else "Vulkan"
    return "Vulkan" if gpu.get("vulkan") else "CPU"

print(accelerator("windows", {"vendor": "nvidia", "compute": 8.6, "driver": 560.0}))
print(accelerator("windows", {"vendor": "nvidia", "compute": 8.6, "driver": 537.0}))
print(accelerator("linux", {"vendor": "nvidia", "compute": 3.5}))
print(accelerator("macos", {"vendor": "apple"}), accelerator("windows", {"vendor": "amd", "rocm": False}))
```

- **An old NVIDIA card, compute capability 3.5, falls back to the CPU.** The machine "has a GPU" but Ollama will not use it.
- **An old Windows driver is fixable.** Updating the driver is cheaper than buying hardware.
- **AMD without ROCm uses Vulkan.** Slower in some cases than ROCm, but far faster than CPU.

Then, parsing `OLLAMA_HOST`.

```python
LOCAL = {"127.0.0.1", "localhost", "::1"}

def parse_host(value):
    if not value:
        value = "127.0.0.1:11434"
    scheme = "http"
    if "://" in value:
        scheme, value = value.split("://", 1)
    host, _, port = value.rpartition(":") if ":" in value else (value, "", "")
    host = host or "127.0.0.1"
    port = int(port) if port else 11434
    return {"scheme": scheme, "host": host, "port": port, "exposed": host not in LOCAL}

for v in [None, "0.0.0.0", "0.0.0.0:8080", ":11500", "http://localhost:11500", "192.168.1.20:11434"]:
    print(v, parse_host(v))
```

- **No value means local only on the default port.**
- **`0.0.0.0` and a LAN address are exposed.** Anyone who can reach the port can use the models.
- **A port-only value changes the port but stays local.** Useful when 11434 is taken.

Then, the whole server configuration with warnings.

```python
KNOWN = {"OLLAMA_HOST", "OLLAMA_MODELS", "OLLAMA_KEEP_ALIVE", "OLLAMA_CONTEXT_LENGTH", "OLLAMA_NUM_PARALLEL",
         "OLLAMA_MAX_LOADED_MODELS", "OLLAMA_MAX_QUEUE", "OLLAMA_ORIGINS", "OLLAMA_FLASH_ATTENTION",
         "OLLAMA_KV_CACHE_TYPE", "OLLAMA_DEBUG", "OLLAMA_NO_CLOUD"}
MODEL_DIRS = {"macos": "~/.ollama/models", "linux": "/usr/share/ollama/.ollama/models",
              "windows": r"C:\Users\%username%\.ollama\models"}

def server_config(env, os_name):
    host = parse_host(env.get("OLLAMA_HOST"))
    cfg = {"address": f"{host['host']}:{host['port']}",
           "models": env.get("OLLAMA_MODELS", MODEL_DIRS[os_name]),
           "keep_alive": env.get("OLLAMA_KEEP_ALIVE", "5m"), "warnings": []}
    if host["exposed"]:
        cfg["warnings"].append("server reachable from the network: firewall it")
    if env.get("OLLAMA_ORIGINS") == "*":
        cfg["warnings"].append("any website may call the API")
    for k in sorted(env):
        if k.startswith("OLLAMA_") and k not in KNOWN:
            cfg["warnings"].append(f"unknown variable {k}")
    return cfg

print(server_config({}, "linux"))
print(server_config({"OLLAMA_HOST": "0.0.0.0", "OLLAMA_MODELS": r"D:\ollama\models", "OLLAMA_ORIGINS": "*",
                     "OLLAMA_MODEL": "qwen3:8b", "OLLAMA_KEEP_ALIVE": "30m"}, "windows"))
```

- **Defaults per operating system.** On Linux the service stores models under the `ollama` user's home, not yours.
- **Three warnings for the risky Windows setup:** exposed, any origin, and a misspelled variable.
- **`OLLAMA_ORIGINS="*"` lets any web page you visit call your local API from the browser.** Restrict it to the origins you need.

Finally, generating the commands that set variables correctly on each OS.

```python
def env_commands(os_name, env):
    keys = sorted(env)
    if os_name == "linux":
        return (["sudo systemctl edit ollama.service", "[Service]"]
                + [f'Environment="{k}={env[k]}"' for k in keys]
                + ["sudo systemctl daemon-reload", "sudo systemctl restart ollama"])
    if os_name == "macos":
        return [f'launchctl setenv {k} "{env[k]}"' for k in keys] + ["restart the Ollama app"]
    return [f'setx {k} "{env[k]}"' for k in keys] + ["quit Ollama from the tray and start it again"]

for os_name in ["linux", "macos", "windows"]:
    print(os_name, env_commands(os_name, {"OLLAMA_MODELS": "/data/ollama", "OLLAMA_KEEP_ALIVE": "30m"}))
```

- **Every recipe ends with a restart.** Without it, the running server keeps its old settings.
- **Linux uses a systemd override, not a shell export.**
- **Sorted keys make the output stable,** so it can be reviewed and diffed.

**Complexity.** Each function is linear in its input.

## 4. Practitioner Wisdom & Edge Cases (Reddit / HN / Stack Overflow Synthesis)

**"It is slow" after installing.** Usually CPU-only or split. Check `ollama ps`.

**GPU present, not used.** Driver too old, unsupported card, or missing ROCm package on Linux. Check `nvidia-smi` and the server log.

**Setting variables in the wrong place.** A shell export does not reach the systemd service; the Windows app needs restarting. Use the documented method for each OS.

**Misspelled variable names.** Silently ignored. Check against `ollama serve --help`.

**System drive filling up.** Models are large. Set `OLLAMA_MODELS` before downloading, Module 10.4.

**Permissions on a custom model directory (Linux).** The service runs as the `ollama` user, which must be able to write there.

**Exposing to the network without protection.** No authentication by default. Firewall it or use a proxy.

**`OLLAMA_ORIGINS="*"`.** Any website can reach your API. Restrict origins.

**Port already in use.** Another Ollama or another tool holds 11434. Stop it or change the port.

**Two installs at once.** A Docker container and a native install fighting over the same port. Run one.

**Updates.** macOS and Windows update automatically on restart; on Linux, re-run the script. Re-verify afterwards.

**Old terminal fonts on Windows 10.** Progress bars render as squares. Change the font.

**Question 2.** The shop wants the Linux box to serve models to the other two machines. Someone suggests running `export OLLAMA_HOST=0.0.0.0` and restarting. Use `parse_host`, `server_config`, and `env_commands` to explain why this does not work and what the safe configuration is.

<details>
<summary>View Answer</summary>

**Question 3.** The Windows desktop's system drive has 60 GB free, and the team plans to try several large models. Using `server_config` and `env_commands`, explain what to configure before the first download and how to make sure it took effect.

<details>
<summary>View Answer</summary>

To confirm it took effect, open a new terminal, pull a small model, and check that files appear under the new folder and not the default one. Models already downloaded to the old folder are not moved automatically, so either move them while Ollama is stopped or pull them again.

KNOWN = {"OLLAMA_HOST", "OLLAMA_MODELS", "OLLAMA_KEEP_ALIVE", "OLLAMA_CONTEXT_LENGTH", "OLLAMA_NUM_PARALLEL",

              "windows": r"C:\Users\%username%\.ollama\models"}


# ---------------------------------------------------------------- Step 1
def preflight(m):
    """Documented OS requirements plus advisory memory and disk thresholds."""
    issues = []
    os_name, ver = m["os"], m.get("version")
    if os_name == "macos":
        if ver[0] < 14:
            issues.append("macOS 14 Sonoma or newer required")
        if m.get("arch") == "x86_64":
            issues.append("Intel Mac: CPU only, expect slow generation")
    elif os_name == "windows":
        if ver < (10, "22H2"):
            issues.append("Windows 10 22H2 or newer required")
        if m.get("disk_free_gb", 0) < 4:
            issues.append("at least 4 GB needed for the install")
    if m.get("ram_gb", 0) < 8:
        issues.append("under 8 GB RAM: only small models")
    if m.get("disk_free_gb", 0) < 20:
        issues.append("under 20 GB free: room for only a few models")
    return issues


# ---------------------------------------------------------------- Step 2
def accelerator(os_name, gpu):
    """The backend Ollama can use on this hardware."""
    if os_name == "macos":
        return "Metal" if gpu and gpu.get("vendor") == "apple" else "CPU"
    if not gpu:
        return "CPU"
    vendor = gpu["vendor"]
    if vendor == "nvidia":
        if gpu.get("compute", 0) < 5.0:
            return "CPU"
        if os_name == "windows" and gpu.get("driver", 0) < 551.61:
            return "update driver"
        return "CUDA"
    if vendor == "amd":
        return "ROCm" if gpu.get("rocm") else "Vulkan"
    return "Vulkan" if gpu.get("vulkan") else "CPU"


# ---------------------------------------------------------------- Step 3
def parse_host(value):
    """OLLAMA_HOST with defaults, and whether it is reachable from other machines."""
    if not value:
        value = "127.0.0.1:11434"
    scheme = "http"
    if "://" in value:
        scheme, value = value.split("://", 1)
    host, _, port = value.rpartition(":") if ":" in value else (value, "", "")
    host = host or "127.0.0.1"
    port = int(port) if port else 11434
    return {"scheme": scheme, "host": host, "port": port, "exposed": host not in LOCAL}


# ---------------------------------------------------------------- Step 4
def server_config(env, os_name):
    """What the server will actually do, with safety warnings."""
    host = parse_host(env.get("OLLAMA_HOST"))
    cfg = {"address": f"{host['host']}:{host['port']}",
           "models": env.get("OLLAMA_MODELS", MODEL_DIRS[os_name]),
           "keep_alive": env.get("OLLAMA_KEEP_ALIVE", "5m"), "warnings": []}
    if host["exposed"]:
        cfg["warnings"].append("server reachable from the network: firewall it")
    if env.get("OLLAMA_ORIGINS") == "*":
        cfg["warnings"].append("any website may call the API")
    for k in sorted(env):
        if k.startswith("OLLAMA_") and k not in KNOWN:
            cfg["warnings"].append(f"unknown variable {k}")
    return cfg


# ---------------------------------------------------------------- Step 5
def env_commands(os_name, env):
    """The documented way to set server variables on each OS, ending with a restart."""
    keys = sorted(env)
    if os_name == "linux":
        return (["sudo systemctl edit ollama.service", "[Service]"]
                + [f'Environment="{k}={env[k]}"' for k in keys]

    return [f'setx {k} "{env[k]}"' for k in keys] + ["quit Ollama from the tray and start it again"]
